# 架构概览

> Spectra 系统精简架构，供 AI 快速建立项目认知。

> 后端是单体多模块、单租户、非 SaaS。`spectra-launch` 负责一个 Spring Boot 进程的模块装配；`spectra-core` 永远启用并内置 notification/upload，OA、Workflow 通过显式依赖和 `spectra.modules.<name>.enabled` 作为可选能力启用。不要为该项目引入租户上下文、服务注册发现、远程配置中心或 Nacos。

## 系统架构

```
spectra-ui (Web)  ──┐
                    └──→ spectra-admin (API :4004) ──→ PostgreSQL + Redis
```

## 目录结构

```
spectra/
├── spectra-admin/          ← 后端 API 服务
│   ├── spectra-config/     ← 统一配置文件
│   ├── spectra-common/     ← 公共契约、值对象、安全端口、审计/健康协议
│   ├── spectra-framework/  ← 框架与安全技术层（MVC/JSON/缓存/Redis/MyBatis/Security）
│   ├── spectra-modules/    ← 业务模块聚合层
│   │   ├── spectra-core/   ← 必选核心：用户/权限/系统/调度/监控/统一审计/通知/上传
│   │   ├── spectra-oa/     ← OA 办公
│   │   ├── spectra-workflow/ ← 工作流
│   └── spectra-launch/     ← 启动入口
├── spectra-ui/             ← Web 管理后台
└── logicflow-plugin-flowable/     ← BPMN 流程建模插件
```

依赖方向固定为 `launch → 业务叶子模块 → framework → common`；`spectra-modules` 仅用于 Maven 聚合，不重复承载叶子模块依赖。安全能力不再提供独立 Starter：Common 定义安全端口，Framework 提供 Spring Security 与安全 Redis 技术实现，Core 承载认证、授权和安全审计业务。
