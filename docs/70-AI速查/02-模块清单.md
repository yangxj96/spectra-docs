# 模块清单

> 所有子项目及其模块的一句话职责描述。

## 后端模块 (spectra-admin)

### 基础层

| 模块 | 路径 | 职责 |
|---|---|---|
| spectra-config | `spectra-config/` | 统一配置文件，所有 application-*.yml 集中管理 |
| spectra-common | `spectra-common/` | 公共契约：BaseEntity、DTO、值对象、安全端口、审计/健康协议；保留少量已登记的历史技术桥接 |
| spectra-framework | `spectra-framework/` | 技术基础设施：MVC、JSON、Redis、缓存、MyBatis、加密、Spring Security 和 Actuator 健康适配 |

### 启动与自动配置

| 模块 | 路径 | 职责 |
|---|---|---|
| spectra-launch | `spectra-launch/` | Spring Boot 唯一启动入口和组合根，只负责模块装配与校验 |
| — | — | 安全自动配置随 `spectra-framework` 发布，不再拆分独立 Starter；`spectra-launch` 通过 `FrameworkModule` 入口装配 |

### 业务模块

| 模块 | 路径 | 职责 |
|---|---|---|
| spectra-core | `modules/spectra-core/` | 必选核心：用户/认证/角色/权限/组织/系统配置/统一审计、安全变更 outbox、审计归档编排、健康聚合、单体调度、统一通知和文件上传 |
| spectra-oa | `modules/spectra-oa/` | OA 办公：资产/考勤/日历/通讯录/合同/文档/会议/公告/报表 |
| spectra-workflow | `modules/spectra-workflow/` | 工作流：Flowable 流程引擎，审批/任务/历史 |

## 模块依赖关系

```
spectra-oa ──→ spectra-core + workflow.api + common.port.file
spectra-workflow ──→ common + framework

spectra-launch ──→ core + OA + Workflow
                 └─→ spectra-modules（仅聚合，不提供运行时能力）

Core 内置 notification/upload 子域，不依赖 OA、Workflow 等可选业务模块；未来 `spectra-erp` 由 launch 装配，不修改 Core。

安全能力：`spectra-common` 提供认证主体、Token、Session、验证码和安全上下文端口；`spectra-framework` 提供 Spring Security、过滤器和安全 Redis 适配；`spectra-core` 提供认证、授权、安全审计和安全变更编排。
```
