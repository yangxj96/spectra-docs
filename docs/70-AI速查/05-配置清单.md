# 配置清单

> 后端团队模板是 `spectra-admin/.mise.local.toml.example`；两个前端模板分别是各自的 `.env.example`。复制出的本机文件被 Git 忽略，不得提交真实值。

## 配置文件分级

| 文件 | 仓库状态 | 能否直接使用 |
|---|---|---|
| `spectra-admin/mise.toml` | 已提交 | 可直接使用，只固定 JDK 版本 |
| `spectra-admin/.mise.local.toml.example` | 已提交 | 只能作为模板复制 |
| `spectra-admin/.mise.local.toml` | 不提交 | 每台机器必须创建并填写 |
| `spectra-ui/.env.example` | 已提交 | 复制为 `.env.development` 后使用 |
| `spectra-app/.env.example` | 已提交 | 复制为 `.env.development` 后使用 |
| 根目录 `.mise.local.toml` | 不提交 | 维护者可选上层覆盖，新克隆不需要 |

## 后端

### 基础启动必须真实可用

| 环境变量 | 说明 | 本机示例/默认拓扑 |
|---|---|---|
| `DB_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://127.0.0.1:5432/devops00_spectra_db` |
| `DB_USERNAME` | 数据库用户 | `postgres` |
| `DB_PASSWORD` | 数据库密码 | 必须自行设置，不提供公共默认值 |
| `REDIS_HOST` | Redis 地址 | `127.0.0.1` |
| `REDIS_PORT` | Redis 端口 | `6379` |
| `REDIS_DB` | Redis DB | `0` |
| `REDIS_PASSWORD` | Redis 密码 | 必须与 Redis 服务一致 |

### 服务与本地 TLS

| 环境变量 | 说明 | 模板值 |
|---|---|---|
| `SERVER_PORT` | 后端监听端口 | `4004` |
| `SERVER_SSL_ENABLED` | 是否启用 Spring Boot HTTPS | `false`，首次启动可直接使用 |
| `DEFAULT_PASSWORD` | 新增/重置用户的默认密码 | 本地占位值；共享环境必须更换 |
| `SSL_PASSWORD` | P12 密码 | 仅启用 HTTPS 时必须与证书一致 |
| `SSL_TYPE` | KeyStore 类型 | `PKCS12` |
| `SSL_ALIAS` | KeyStore 别名 | `tomcat` |

证书固定从后端工作目录下的 `files/ssl/keystore.p12` 读取；该路径是仓库相对运行路径，可复用，但证书文件和密码是本机配置，不能提交。

### 启动时需要有值，使用功能前需要真实 Provider

| 分组 | 环境变量 | 模板行为 |
|---|---|---|
| S3 | `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION` | 本机占位值只用于完成配置；上传前接入真实 S3/MinIO |
| AI | `AI_KEY`、`AI_BASE_URL`、`AI_MODEL` | 本机占位端点不提供模型能力；调用聊天前替换 |
| RAG | `RAG_KEY`、`RAG_BASE_URL`、`RAG_MODEL` | 调用向量化前替换，并初始化 pgvector 表 |

这些配置当前会参与 Bean 创建，不能从本机配置文件中随意删除。模板中的 `local-placeholder` 不是可用凭据，也不能用于生产。

### 接口加解密不是环境变量

接口加解密已改为运行时动态配置：开关和四个 RSA 密钥存储在 `spectra_core.sys_config` 的 `crypto.*` 项中，通过系统管理 API 维护，初始数据默认关闭。旧的 `SPECTRA_SYSTEM_SM_ENABLED`、`SPECTRA_SYSTEM_SM_PUBLIC_KEY`、`SPECTRA_SYSTEM_SM_PRIVATE_KEY` 不再被源码读取，不要加入本机模板。

## spectra-ui

## 通知模块

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `NOTIFICATION_ENABLED` | 通知模块总开关 | `true` |
| `NOTIFICATION_ADDRESS_ENCRYPTION_KEY` | 通知外部地址 AES-GCM 密钥，Base64 编码后为 16/24/32 字节 | 空（未配置时外部地址入队失败） |
| `NOTIFICATION_SENSITIVE_PAYLOAD_KEY` | 通知敏感参数和敏感渲染结果 AES-GCM 密钥，Base64 编码后为 16/24/32 字节 | 空（未配置时敏感通知入队失败） |
| `NOTIFICATION_WORKER_PROCESSING_TIMEOUT_SECONDS` | Worker 处理租约超时时间 | `300` |
| `NOTIFICATION_WORKER_RETRY_BASE_DELAY_SECONDS` | Worker 指数退避基准秒数 | `5` |
| `spectra.notification.worker.fixed-delay-ms` | PostgreSQL 外部渠道任务 Worker 轮询间隔 | `5000` |
| `NOTIFICATION_CLEANUP_ENABLED` | 是否定时清理终态/过期记录中的敏感密文 | `true` |
| `NOTIFICATION_CLEANUP_FIXED_DELAY_MS` | 敏感密文清理任务间隔 | `3600000` |
| `NOTIFICATION_CLEANUP_BATCH_SIZE` | 单次清理请求/任务上限 | `100` |
| `NOTIFICATION_CLEANUP_RETENTION_SECONDS` | 终态记录保留敏感密文时间 | `86400` |

`SMS/EMAIL` 当前使用独立 Gateway 和 Placeholder Sender；外部渠道返回 `CHANNEL_NOT_CONFIGURED`，不会报告发送成功。验证码发送前会先检查渠道可用性，渠道不可用时不写 Redis。Provider 测试替身只放在 test scope，示例为 `spectra-notification/src/test/java/.../MockSmsSender.java` 和 `MockEmailSender.java`，不通过生产配置覆盖统一 Gateway。

| 环境变量 | 说明 | 首次启动模板 |
|---|---|---|
| `VITE_API_URL` | 后端基础地址，保留尾部 `/` | `http://127.0.0.1:4004/` |
| `VITE_WEB_TITLE` | 页面标题 | `光谱平台` |
| `VITE_CRYPTO_ENABLED` | 前端加解密开关 | `false` |

## spectra-app

| 环境变量 | 说明 | 首次启动模板 |
|---|---|---|
| `VITE_API_BASE_URL` | 后端基础地址，不带尾部 `/` | `http://127.0.0.1:4004` |
| `VITE_DEV_MODE` | 开发模式开关 | `false` |
| `VITE_APP_TITLE` | 应用标题 | `光谱` |
| `VITE_CRYPTO_ENABLED` | H5 加解密开关 | `false` |

后端换成 HTTPS、非本机主机或其他端口时，两个前端配置必须一起调整。

## 不能提交的内容

- `.mise.local.toml`、`.env.development`、`.env.local` 等本机覆盖。
- 数据库/Redis/S3/AI/RAG 的真实密码、Token、密钥和完整连接配置。
- `keystore.p12`、CA 私钥、PEM/KEY 文件。
- 某个开发者的用户目录、磁盘绝对路径、IDE 临时参数文件。
