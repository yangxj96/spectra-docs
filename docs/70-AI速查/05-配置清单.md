# 配置清单

> 后端团队模板是 `spectra-admin/.mise.local.toml.example`；两个前端模板分别是各自的 `.env.example`。复制出的本机文件被 Git 忽略，不得提交真实值。

## 配置文件分级

| 文件 | 仓库状态 | 能否直接使用 |
|---|---|---|
| `spectra-admin/mise.toml` | 已提交 | 可直接使用，只固定 JDK 版本 |
| `spectra-admin/.mise.local.toml.example` | 已提交 | 只能作为模板复制 |
| `spectra-admin/.mise.local.toml` | 不提交 | 每台机器必须创建并填写 |
| `spectra-ui/.env.example` | 已提交 | 复制为 `.env.development` 后使用 |
| `spectra-app/.env.example` | 已提交 | 复制为 `.env.development` 后使用 |
| 根目录 `.mise.local.toml` | 不提交 | 维护者可选上层覆盖，新克隆不需要 |

## 后端

### 基础启动必须真实可用

| 环境变量 | 说明 | 本机示例/默认拓扑 |
|---|---|---|
| `DB_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://127.0.0.1:5432/devops00_spectra_db` |
| `DB_USERNAME` | 数据库用户 | `postgres` |
| `DB_PASSWORD` | 数据库密码 | 必须自行设置，不提供公共默认值 |
| `SPECTRA_FLYWAY_ENABLED` | 是否启用目标 schema 的 Flyway 迁移；关闭仅用于明确的迁移维护窗口 | `true`；`baseline-on-migrate=false`，新环境必须从 V1 开始 |
| `REDIS_HOST` | Redis 地址 | `127.0.0.1` |
| `REDIS_PORT` | Redis 端口 | `6379` |
| `REDIS_DB` | Redis DB | `0` |
| `REDIS_PASSWORD` | Redis 密码 | 必须与 Redis 服务一致 |
| `SPECTRA_SECURITY_AUTHORIZATION_CHANGE_TOKEN_HMAC_KEY` | Role/RoleAssignment Preview/Apply token 的 HMAC 密钥 | 必须由环境变量或密钥管理系统注入，UTF-8 长度至少 32 字节；未配置时授权写入口 fail-closed |
| `SPECTRA_SECURITY_MFA_ENCRYPTION_KEY` | TOTP 共享密钥 AES-GCM 加密密钥 | 必须由环境变量或密钥管理系统注入，UTF-8 长度必须为 32 字节；未配置时 MFA 登记/校验 fail-closed |
| `SPECTRA_SECURITY_MFA_ENCRYPTION_KEY_VERSION` | TOTP 密钥加密版本 | 默认 `v1`；密钥轮换时先完成迁移再切换版本 |
| `SPECTRA_SECURITY_MFA_PREVIOUS_ENCRYPTION_KEY` / `SPECTRA_SECURITY_MFA_PREVIOUS_ENCRYPTION_KEY_VERSION` | TOTP 轮换窗口内解密上一版本并在成功验证时自动迁移 | 必须同时配置；只用于迁移，不用于新加密；完成迁移后立即移除 |
| `SPECTRA_SECURITY_MFA_TOTP_ISSUER` | TOTP provisioning URI 发行方 | 默认 `Spectra` |
| `SPECTRA_SECURITY_MFA_REQUIRED_FOR_DEV_OPS` | DEV_OPS 是否强制 MFA | 默认 `true`；未完成 MFA 的 Root 不得创建普通 Session |
| `SPECTRA_SECURITY_MFA_CHALLENGE_EXPIRE` | 二阶段登录 MFA challenge 有效期（秒） | 默认 `300`；仅保存短期 challenge 元数据，不保存密码、验证码或 Token |
| `SPECTRA_SECURITY_MFA_CHALLENGE_MAX_ATTEMPTS` | 二阶段登录 MFA challenge 最大失败次数 | 默认 `5`；达到上限后立即失效 |
| `SPECTRA_SECURITY_AUDIT_ARCHIVE_BACKEND` | 安全审计归档后端 | 生产必须为 `S3_OBJECT_LOCK`；开发默认 `PENDING` |
| `S3_SECURITY_AUDIT_ARCHIVE_BUCKET` | 安全审计独立 Object Lock/WORM bucket | 启用 `S3_OBJECT_LOCK` 时必须配置，不能和普通文件 bucket 共用 |
| `S3_SECURITY_AUDIT_ARCHIVE_PREFIX` | 安全审计对象前缀 | 默认 `security-audit/` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SECURE` | Web Refresh Cookie Secure 标记 | 生产必须为 `true`；HTTP 开发环境由 `application-dev.yml` 默认设为 `false` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE` | Web Refresh Cookie SameSite | 默认 `Strict`；仅部署确需跨站时受控使用 `None` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE_NONE_ALLOWED` | 是否批准跨站 Refresh Cookie | 默认 `false`；设为 `true` 前必须完成精确 Origin、CSRF 和代理 HTTPS 评审 |
| `SPECTRA_SECURITY_ALLOW_INSECURE_REFRESH_COOKIE` | 是否显式允许 HTTP 开发环境 Cookie | 仅开发环境可为 `true`；生产必须为 `false` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_NAME` / `SPECTRA_SECURITY_REFRESH_COOKIE_PATH` / `SPECTRA_SECURITY_REFRESH_COOKIE_DOMAIN` | Refresh Cookie 名称、Path、Domain | 生产默认 `__Host-spectra-refresh`、`/`、空 Domain；HTTP 开发环境使用 `spectra-refresh`、`/`、空 Domain |
| `SPECTRA_SECURITY_CSRF_COOKIE_NAME` / `SPECTRA_SECURITY_CSRF_HEADER_NAME` | 双提交 CSRF Cookie/Header 名称 | 默认 `XSRF-TOKEN` / `X-XSRF-TOKEN`；必须非空且互不相同 |

### 可选 Flyway PostgreSQL 集成门禁

`SecurityFlywayPostgresIntegrationTest` 默认禁用，不读取或修改本机业务数据库。需要在隔离、可丢弃的 PostgreSQL 数据库上验证 V1-V16 时，显式设置 `SPECTRA_SECURITY_FLYWAY_POSTGRES_TEST=true`，并提供下表连接变量；V2 会创建 `spectra_runtime`/`spectra_migrator` 数据库角色，因此测试账号需要具备 `CREATEROLE` 权限。非空库用例必须使用另一套专用数据库，测试会创建并清理临时 marker 表，不得指向开发或生产库。

当前 V15 会在 V14 默认 Root 种子的基础上对齐 `sys_log` 的结构化日志字段，V16 将日志说明扩展为 `TEXT` 以容纳异常上下文。V14 创建默认 `ROLE_DEV_OPS`、`devops00.com` 用户、密码身份、BCrypt 凭据和有效 RoleAssignment；它不预置 TOTP 密钥或 Recovery Code。生产首次部署必须完成受控 MFA enrollment、Recovery Code 保管和引导密码轮换。引导密码只通过用户/运维的受控渠道提供，不写入本文档。

| 环境变量 | 说明 |
|---|---|
| `SPECTRA_SECURITY_FLYWAY_POSTGRES_TEST` | 是否启用真实 PostgreSQL/Flyway 集成测试；默认不设置（禁用） |
| `SPECTRA_SECURITY_FLYWAY_DB_URL` / `USERNAME` / `PASSWORD` | 空目标库的连接信息，用于验证 V1、V2 完整迁移 |
| `SPECTRA_SECURITY_FLYWAY_NONEMPTY_DB_URL` / `USERNAME` / `PASSWORD` | 独立非空库的连接信息，用于验证 `baselineOnMigrate=false` 拒绝自动 baseline |

### 服务与本地 TLS

| 环境变量 | 说明 | 模板值 |
|---|---|---|
| `SERVER_PORT` | 后端监听端口 | `4004` |
| `SERVER_SSL_ENABLED` | 是否启用 Spring Boot HTTPS | `true`，首次启动需要本机 P12 证书 |
| `DEFAULT_PASSWORD` | 新增/重置用户的默认密码 | 本地占位值；共享环境必须更换 |
| `SSL_PASSWORD` | P12 密码 | 仅启用 HTTPS 时必须与证书一致 |
| `SSL_TYPE` | KeyStore 类型 | `PKCS12` |
| `SSL_ALIAS` | KeyStore 别名 | `tomcat` |

证书固定从后端工作目录下的 `files/ssl/keystore.p12` 读取；该路径是仓库相对运行路径，可复用，但证书文件和密码是本机配置，不能提交。

### 启动时需要有值，使用功能前需要真实 Provider

| 分组 | 环境变量 | 模板行为 |
|---|---|---|
| S3 | `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION` | 本机占位值只用于完成配置；上传前接入真实 S3/MinIO |
| AI | `AI_KEY`、`AI_BASE_URL`、`AI_MODEL` | 本机占位端点不提供模型能力；调用聊天前替换 |
| RAG | `RAG_KEY`、`RAG_BASE_URL`、`RAG_MODEL` | 调用向量化前替换，并初始化 pgvector 表 |

这些配置当前会参与 Bean 创建，不能从本机配置文件中随意删除。模板中的 `local-placeholder` 不是可用凭据，也不能用于生产。

### 接口加解密不是环境变量

接口加解密已改为运行时动态配置：开关和四个 RSA 密钥存储在 `spectra_core.sys_config` 的 `crypto.*` 项中，通过系统管理 API 维护，初始数据默认关闭。旧的 `SPECTRA_SYSTEM_SM_ENABLED`、`SPECTRA_SYSTEM_SM_PUBLIC_KEY`、`SPECTRA_SYSTEM_SM_PRIVATE_KEY` 不再被源码读取，不要加入本机模板。

### CORS 与跨站安全

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `SPECTRA_CORS_ORIGIN_ALLOWLIST` | 精确允许的 Origin，逗号分隔；禁止 `*`；生产必须显式配置 HTTPS Origin | 开发环境 `https://localhost:5173,https://127.0.0.1:5173`；生产环境未配置时启动失败 |
| `SPECTRA_CORS_REQUIRED` | 是否要求至少一个 CORS Origin | 开发 `false`；生产 `true` |
| `SERVER_FORWARD_HEADERS_STRATEGY` | 反向代理 HTTPS 感知策略 | `framework`；生产必须确认代理只信任受控 Forwarded/X-Forwarded 头 |

后端只接受精确 Origin，不使用通配符 Origin Pattern。启用带凭证的 Web Cookie 前，必须同时配置 HTTPS、精确 Origin allowlist 和 CSRF 防护；不要把 `SameSite=None` 当作默认值。

| `SECURITY_VERIFICATION_CODE_HMAC_KEY` | 验证码 Redis 摘要 HMAC 密钥；不得写入代码、日志或提交 | 空（未配置时验证码发送失败） |
| `SECURITY_VERIFICATION_CODE_MAX_ATTEMPTS` | 单个验证码窗口最大校验次数 | `5` |
| `NOTIFICATION_ENABLED` | 通知模块总开关 | `true` |
| `NOTIFICATION_ADDRESS_ENCRYPTION_KEY` | 通知外部地址 AES-GCM 密钥，Base64 编码后为 16/24/32 字节 | 空（未配置时外部地址入队失败） |
| `NOTIFICATION_SENSITIVE_PAYLOAD_KEY` | 通知敏感参数和敏感渲染结果 AES-GCM 密钥，Base64 编码后为 16/24/32 字节 | 空（未配置时敏感通知入队失败） |
| `NOTIFICATION_ALLOWED_LINK_PREFIXES` | 消息中心允许的前端站内路由前缀，逗号分隔 | `/login,/auth/,/oa/,/workflow/,/notification/,/notification-center/,/system/,/file/,/ai/` |
| `NOTIFICATION_WORKER_PROCESSING_TIMEOUT_SECONDS` | Worker 处理租约超时时间 | `300` |
| `NOTIFICATION_WORKER_RETRY_BASE_DELAY_SECONDS` | Worker 指数退避基准秒数 | `5` |
| `spectra.notification.worker.fixed-delay-ms` | PostgreSQL 外部渠道任务 Worker 轮询间隔 | `5000` |
| `NOTIFICATION_CLEANUP_ENABLED` | 是否定时清理终态/过期记录中的敏感密文 | `true` |
| `NOTIFICATION_CLEANUP_FIXED_DELAY_MS` | 敏感密文清理任务间隔 | `3600000` |
| `NOTIFICATION_CLEANUP_BATCH_SIZE` | 单次清理请求/任务上限 | `100` |
| `NOTIFICATION_CLEANUP_RETENTION_SECONDS` | 终态记录保留敏感密文时间 | `86400` |

`SMS/EMAIL` 当前使用独立 Gateway 和 Placeholder Sender；外部渠道返回 `CHANNEL_NOT_CONFIGURED`，不会报告发送成功。验证码发送前会先检查渠道可用性，渠道不可用时不写 Redis。Provider 测试替身只放在 test scope，示例为 `spectra-notification/src/test/java/.../MockSmsSender.java` 和 `MockEmailSender.java`，不通过生产配置覆盖统一 Gateway。

## 不能提交的内容

- `.mise.local.toml`、`.env.development`、`.env.local` 等本机覆盖。
- 数据库/Redis/S3/AI/RAG 的真实密码、Token、密钥和完整连接配置。
- `keystore.p12`、CA 私钥、PEM/KEY 文件。
- 某个开发者的用户目录、磁盘绝对路径、IDE 临时参数文件。
