## 后端

### 基础启动必须真实可用

| 环境变量 | 说明 | 本机示例/默认拓扑 |
|---|---|---|
| `DB_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://127.0.0.1:5432/devops00_spectra_db` |
| `DB_USERNAME` | 数据库用户 | `postgres` |
| `DB_PASSWORD` | 数据库密码 | 必须自行设置，不提供公共默认值 |
| `SPECTRA_FLYWAY_ENABLED` | 是否启用目标 schema 的 Flyway 迁移；关闭仅用于明确的迁移维护窗口 | `true`；`baseline-on-migrate=false`，新环境必须从 V1 开始 |

| `SPECTRA_REDIS_CONNECT_TIMEOUT` | Redis 建立连接超时 | `5s` |
| `SPECTRA_REDIS_COMMAND_TIMEOUT` | Redis 命令执行超时 | `10s` |
| `SPECTRA_REDIS_POOL_MAX_ACTIVE` / `SPECTRA_REDIS_POOL_MAX_IDLE` / `SPECTRA_REDIS_POOL_MIN_IDLE` | Lettuce 连接池上限、最大空闲和最小空闲连接数 | `20` / `10` / `2` |
| `SPECTRA_REDIS_POOL_MAX_WAIT` | 从 Lettuce 连接池获取连接的最大等待时间 | `5000ms` |
| `SPECTRA_SECURITY_REDIS_WORKER_BATCH_SIZE` | 安全 Redis 相关 worker 的批量边界；当前只作为统一运行时契约参数 | `100`，允许范围 `1..1000` |
| `SPECTRA_SECURITY_AUTHORIZATION_CHANGE_TOKEN_HMAC_KEY` | Role/RoleAssignment Preview/Apply token 的 HMAC 密钥 | 必须由环境变量或密钥管理系统注入，UTF-8 长度至少 32 字节；未配置时授权写入口 fail-closed |
| `SPECTRA_SECURITY_AUDIT_ARCHIVE_BACKEND` | 安全审计归档后端 | 生产必须为 `S3_OBJECT_LOCK`；开发默认 `PENDING` |
| `S3_SECURITY_AUDIT_ARCHIVE_BUCKET` | 安全审计独立 Object Lock/WORM bucket | 启用 `S3_OBJECT_LOCK` 时必须配置，不能和普通文件 bucket 共用 |
| `S3_SECURITY_AUDIT_ARCHIVE_PREFIX` | 安全审计对象前缀 | 默认 `security-audit/` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SECURE` | Web Refresh Cookie Secure 标记 | HTTPS 开发和生产均为 `true`；仅明确的 HTTP 隔离环境才允许单独覆盖 |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE` | Web Refresh Cookie SameSite | 默认 `Strict`；仅部署确需跨站时受控使用 `None` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE_NONE_ALLOWED` | 是否批准跨站 Refresh Cookie | 默认 `false`；设为 `true` 前必须完成精确 Origin、CSRF 和代理 HTTPS 评审 |
| `SPECTRA_SECURITY_ALLOW_INSECURE_REFRESH_COOKIE` | 是否显式允许 HTTP 开发环境 Cookie | HTTPS 开发和生产均为 `false`；仅明确的 HTTP 隔离环境才允许 `true` |
| `SPECTRA_SECURITY_REFRESH_COOKIE_NAME` / `SPECTRA_SECURITY_REFRESH_COOKIE_PATH` / `SPECTRA_SECURITY_REFRESH_COOKIE_DOMAIN` | Refresh Cookie 名称、Path、Domain | HTTPS 开发和生产默认 `__Host-spectra-refresh`、`/`、空 Domain；HTTP 隔离开发环境显式关闭 Secure 时才允许使用非 `__Host-` 名称 |
| `SPECTRA_SECURITY_CSRF_COOKIE_NAME` / `SPECTRA_SECURITY_CSRF_HEADER_NAME` | 双提交 CSRF Cookie/Header 名称 | 默认 `XSRF-TOKEN` / `X-XSRF-TOKEN`；必须非空且互不相同 |

安全 Redis 的 namespace 固定为 `sec:`，由 `spectra-framework` 的安全技术实现统一生成 Token、Session、验证码、防重放和登录失败锁定 key；不能通过环境变量改写。`spectra.security.redis.fail-closed` 固定为 `true`，安全 Redis 连接、命令或状态确认失败时不得放行相关安全操作。普通缓存使用自己的 key 空间，不能复用安全 Redis key。

### 单体模块装配

模块装配是单体组合根的启动期行为，不是运行时服务发现。`spectra-launch/pom.xml` 决定模块是否进入 classpath，`spectra.modules.<name>.enabled` 决定已引入的 OA/Workflow 是否注册自动配置；两者都不会通过 Nacos、远程配置中心或注册中心动态改变。

`spectra.modules.<name>.enabled` 与 `spectra.notification.enabled` 不是同一层配置：前者只用于 OA/Workflow 的 launch/AutoConfiguration 模块装配，后者是 Core 通知子域的业务功能开关，可能由系统设置引导写入 `spectra_core.sys_config`。Core 不提供关闭开关，也不存在租户级模块开关。

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `spectra.modules.workflow.enabled` | 是否装配 Flowable 工作流模块；关闭后不注册流程 Controller 和模块 Bean | `true` |
| `spectra.modules.oa.enabled` | 是否装配 OA 业务模块；关闭后不注册 OA Controller 和业务任务 | `true` |

`spectra-core` 始终由 `spectra-launch` 装配，不能通过配置关闭。模块是否可用首先由 `spectra-launch/pom.xml` 的显式依赖决定，再由上述启动配置决定；这些开关只在应用启动时生效，不支持运行时动态启停。OA 只依赖 Workflow 作为必需 adapter；通知和文件上传已经随 Core 提供。缺少必需 adapter 时应用启动失败并提示缺失模块，不使用隐式组件扫描或空实现降级。

首次系统初始化令牌不再配置为环境变量。应用启动时检查 `spectra_core.sys_system_state`；状态为 `UNINITIALIZED` 且 Redis 中没有引导令牌摘要时，生成一次随机令牌并输出到后端控制台。Redis 只保存 SHA-256 摘要，初始化完成后自动删除；令牌应按密码处理，不得写入共享日志、工单或数据库。

首次初始化还会将 `system.name`、`system.short-name`、`system.logo`、`system.default-locale`、`system.default-timezone` 和 `security.profile` 六项非敏感配置写入 `spectra_core.sys_config`。初始化接口只允许写入这组白名单配置；数据库、Redis、密码、Token、第三方凭据和私钥仍由部署配置或密钥管理系统提供。

后端时间转换解析时区遵循“当前用户时区 → `system.default-timezone` → UTC”的顺序；用户时区为空或无效时使用系统默认时区，系统配置不存在或无效时最终使用 UTC。

Web 前端启动时通过公开接口 `/api/system/bootstrap` 一次获取系统公开信息、加解密配置和初始化状态；该接口不返回 `security.profile`、私钥或其他敏感配置。

### 集成测试分类与外部依赖

默认的 `./mvnw test` 只运行快速单元/契约测试，并排除 `integration` 与
`manual-integration` 标签；不会读取本机数据库/Redis 配置，也不会连接本机服务。

`SecurityFlywayPostgresIntegrationTest`、`OutboxPostgresIntegrationTest`、
`NotificationPostgresIntegrationTest` 和 `SecurityRedisFailureIntegrationTest` 使用
Testcontainers 创建固定版本的可丢弃 PostgreSQL/Redis 实例，完整执行对应 Flyway
迁移并由测试扩展清理容器。需要 Docker Runtime 时才执行：

```bash
cd spectra-admin
./mvnw -Pintegration -Dgroups=integration test
```

也可以使用 `./mvnw -Dgroups=integration test`，Maven 会自动激活同名 profile。
容器启动失败必须让测试失败，不能通过本机服务或凭据静默回退。当前开发机没有 Docker，
因此本机只验证默认测试和编译，不执行上述命令。

尚未迁移为容器夹具的行政区划导入、调度迁移和安全并发治理测试标记为
`manual-integration`，只能使用明确的隔离数据库并通过手工 profile 执行；这些测试的
环境变量不参与默认测试和 `integration` profile。不得把手工测试连接指向开发库或生产库。

当前 Flyway 迁移基线包含目标 schema、公共字段顺序、技术主键、完整注释、运行时数据库角色、Permission Catalog、安全策略和 OA 固定种子；后续结构变更使用递增版本迁移。首个 DEV_OPS 用户、密码身份、BCrypt 凭据和有效 RoleAssignment 由系统初始化 API 创建，不再预置静态账号或密码。

| `SERVER_PORT` | 后端监听端口 | `4004` |

### 服务监控

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `spectra.monitor.collection-interval-ms` | 服务监控数据新鲜度判断窗口，单位为毫秒；实际采集由统一调度 LOOP 控制 | `10000` |
| `spectra.monitor.history-retention-days` | 单体服务监控历史采样保留天数，后台按小时触发过期清理 | `7` |
| `spectra.monitor.diagnostics.enabled` | 是否允许创建诊断任务 | `true` |
| `spectra.monitor.diagnostics.heap-dump-enabled` | 是否允许生成堆转储；高风险功能默认关闭 | `false` |
| `spectra.monitor.diagnostics.directory` | 诊断文件受控目录；不配置时使用系统临时目录下的 `spectra-monitor-diagnostics` | `${java.io.tmpdir}/spectra-monitor-diagnostics` |
| `spectra.monitor.diagnostics.retention-hours` | 诊断文件保留小时数，过期后自动清理 | `24` |
| `spectra.monitor.diagnostics.thread-dump-max-bytes` | 线程转储最大字节数 | `5242880` |
| `spectra.monitor.diagnostics.heap-dump-max-bytes` | 堆转储最大字节数 | `536870912` |
| `spectra.monitor.diagnostics.cleanup-interval-ms` | 诊断文件清理任务间隔，单位为毫秒 | `3600000` |

Actuator 健康端点由 framework 适配器暴露 Core 的统一健康聚合结果。Core 注册表收集 `DependencyHealthContributor`，模块只提供自己的 PostgreSQL/Redis/Flowable/通知/对象存储贡献实现；不会在 Core 复制连接检查。Prometheus registry 由 `spectra-launch` 组合根直接装配；开发和生产只暴露 `health`、`info`、`metrics`、`prometheus`，其中 `metrics` 和 `prometheus` 不在匿名白名单内，必须经过安全认证和受控网络入口。健康详情必须经过授权：

| 配置项 | 开发环境 | 生产环境 |
|---|---|---|
| `management.endpoints.web.exposure.include` | `health, info, metrics, prometheus` | `health, info, metrics, prometheus` |
| `management.endpoint.health.show-details` | `always` | `when-authorized` |
| `management.endpoint.health.status.order` | `down,out-of-service,degraded,unknown,up` | `down,out-of-service,degraded,unknown,up` |

HTTP 请求由 framework 统一生成或清洗 `X-Request-ID`、`X-Correlation-ID`，响应始终返回最终值；链路值进入 MDC、`@Audit` 的 `AuditContext`、安全审计、普通操作日志 outbox 和通知请求的 `trace_id`。请求结束后必须清理 MDC。后台 worker 使用任务级 correlation ID，不把空字符串当作链路标识；指标标签只允许固定业务枚举，不得加入用户 ID、对象 ID、完整 URL、查询参数或凭据。

### 单体调度内核

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `spectra.scheduler.enabled` | 是否启用统一调度内核；启用后仍必须通过 PostgreSQL 启动门禁 | `true` |
| `spectra.scheduler.poll-interval` | 内部调度 tick 间隔；不代表业务任务的执行频率。tick 使用 JDK 25 虚拟线程执行，离散处理器使用独立虚拟线程执行器，调度入口保持单线程串行 | `1s` |
| `spectra.scheduler.due-batch-size` | 单次到期派发、执行领取和循环控制的批量上限 | `50` |

调度 Cron 的时区读取 `spectra_core.sys_config` 中的 `system.default-timezone`，要求有效 IANA 时区；缺失或无效时回退 UTC，不使用 JVM 默认时区。任务定义、租约、幂等键、执行结果和 LOOP 会话全部以 PostgreSQL 为事实源；数据库不可用时调度器保持未就绪并停止新的状态推进。内置任务和管理 API 见 [[../10-后端/35-单体调度内核]]。

上传清理由内置 `file.upload.cleanup` 系统任务统一执行，类型为 `SYSTEM`、范围为 `SINGLETON`、计划方式为 `FIXED_DELAY`，默认每 5 分钟触发。上传会话和资产的保留时长、重试和批次参数仍由 Core 上传子域的 `application-*.yml` 配置提供，不再配置或读取独立的 `cleanup-interval`。

### 启动时需要有值，使用功能前需要真实 Provider

| 分组 | 环境变量 | 模板行为 |
|---|---|---|
| S3 | `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION` | 本机占位值只用于完成配置；上传前接入真实 S3/MinIO |

这些配置当前会参与 Bean 创建，不能从本机配置文件中随意删除。模板中的 `local-placeholder` 不是可用凭据，也不能用于生产。

### 文件上传参数

`spectra.file.upload.chunk-size`、`min-chunk-size` 和 `max-chunk-size` 在后端绑定为 `Long`，单位是字节，配置值必须使用纯数字；当前默认分别为 `8388608`（8 MiB）、`5242880`（5 MiB）和 `67108864`（64 MiB）。带单位的 `8MB`、`5MB`、`64MB` 只适用于 Spring `DataSize` 类型配置，不适用于这三个上传参数。

### 接口加解密不是环境变量

接口加解密已改为运行时动态配置：开关和四个 RSA 密钥存储在 `spectra_core.sys_config` 的 `crypto.*` 项中，通过系统管理 API 维护，初始数据默认关闭。旧的 `SPECTRA_SYSTEM_SM_ENABLED`、`SPECTRA_SYSTEM_SM_PUBLIC_KEY`、`SPECTRA_SYSTEM_SM_PRIVATE_KEY` 不再被源码读取，不要加入本机模板。

### CORS 与跨站安全

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `SPECTRA_CORS_ORIGIN_ALLOWLIST` | 精确允许的 Origin，逗号分隔；禁止 `*`；生产必须显式配置 HTTPS Origin | 开发环境 `https://localhost:5173,https://127.0.0.1:5173`；生产环境未配置时启动失败 |
| `SPECTRA_CORS_REQUIRED` | 是否要求至少一个 CORS Origin | 开发 `false`；生产 `true` |
| `SERVER_FORWARD_HEADERS_STRATEGY` | 反向代理 HTTPS 感知策略 | `framework`；生产必须确认代理只信任受控 Forwarded/X-Forwarded 头 |

后端只接受精确 Origin，不使用通配符 Origin Pattern。启用带凭证的 Web Cookie 前，必须同时配置 HTTPS、精确 Origin allowlist 和 CSRF 防护；不要把 `SameSite=None` 当作默认值。

### 默认验证范围与 1.0.0 发布门禁

默认验证范围包括本地 Flyway V1、安全集成测试、故障 fail-closed 验收和人工业务验收；CI Flyway 实跑、生产 CORS/代理配置、备份恢复、S3 Object Lock、Root break-glass 演练和归档恢复属于 `1.0.0` 发布门禁，执行要求见 [[../60-部署运维/50-生产部署说明]] 和相关 Runbook。

## Core 通知配置

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `SECURITY_VERIFICATION_CODE_HMAC_KEY` | 验证码 Redis 摘要 HMAC 密钥；不得写入代码、日志或提交 | 空（未配置时验证码发送失败） |
| `SECURITY_VERIFICATION_CODE_MAX_ATTEMPTS` | 单个验证码窗口最大校验次数 | `5` |
通知业务开关、AES-GCM 密钥、站内链接白名单和敏感载荷清理开关在 DEV_OPS 首次登录后的系统设置引导中保存为 `sys_config` 的 `notification.*` 项。Worker/清理任务的轮询间隔、租约超时、重试退避、批量大小和保留时长是运行调度参数，使用 `application-*.yml` 默认值，不再要求写入 `.mise.local.toml`。

底部版权开关、版权名称和点击跳转地址在同一系统设置引导中保存为 `sys_config` 的 `copyright.enabled`、`copyright.name` 和 `copyright.url` 项；前端通过 `GET /api/system/bootstrap` 获取并渲染 Footer，不再把版权内容写死在组件中。

`SMS/EMAIL` 的具体供应商投递在健康检查未通过前由安全阻断 Sender 处理，不会报告发送成功。Provider 支持 `ALIYUN_SMS`、`TENCENT_SMS`、`SMTP`、`HTTP_JSON` 和 `MOCK`；非敏感配置由 `/notification/admin/providers` 保存到 `spectra_core.sys_config` 的 `notification.provider.sms/email`，AccessKey Secret、SecretKey、SMTP 密码或 HTTP Token 单独以 Core 通知子域 AES-GCM 密文保存到对应 `.secret` 键。短信配置包含地域、凭据标识、签名、模板编码，腾讯云额外包含 `SmsSdkAppId` 和模板参数顺序；SMTP 配置包含主机、端口、用户名、发件地址、发件人名称和 SSL/STARTTLS。接口只返回配置状态、Secret 是否存在、Key ID、更新时间和脱敏原因。配置完整但未健康检查前返回 `UNHEALTHY`，Secret 缺失或密钥不可用时返回 `BLOCKED`。运维端测试发送通过 `/notification/admin/providers/{channel}/test` 接入，必须提供明确测试地址和 `SEND_TEST` 确认词，目标不落库、不从用户数据推导。Worker 对明确限流结果按任务最大尝试次数退避，超时/UNKNOWN 结果写入 Delivery 后停止无条件重试。验证码发送前会先检查渠道可用性，渠道不可用时不写 Redis。MOCK Provider 位于生产运行时，只在最终发送点输出脱敏日志，其他流程与真实 Provider 相同。

| 环境变量 | 说明 | 首次启动模板 |
|---|---|---|
| `VITE_API_URL` | Web API 基础地址；开发环境直连 HTTPS 后端 4004 并保留尾部 `/`，生产环境填写实际后端完整地址 | 开发：`https://127.0.0.1:4004/`；生产：按部署地址填写 |
前端加解密开关由 `GET /api/system/bootstrap` 返回，首次登录后的系统设置引导保存；不再配置 `VITE_CRYPTO_ENABLED`。

后端换成 HTTPS、非本机主机或其他端口时，Web 前端的 `VITE_API_URL` 必须同步调整。

## 不能提交的内容

- `.mise.local.toml`、`.env.development`、`.env.local` 等本机覆盖。
- 数据库/Redis/S3 的真实密码、Token、密钥和完整连接配置。
- `keystore.p12`、CA 私钥、PEM/KEY 文件。
- 某个开发者的用户目录、磁盘绝对路径、IDE 临时参数文件。
