# 常见问题

## 为什么需要递归克隆

根仓库通过 Git submodule 引入后端、Web 管理后台和流程设计器。只克隆根仓库不会自动得到三个子项目，需要使用：

```bash
git clone --recurse-submodules https://github.com/yangxj96/spectra-docs.git spectra
```

普通克隆后执行 `git submodule update --init --recursive` 即可补齐。

## 为什么根仓库没有一个统一的 `mise.toml`

三个子项目有各自的工具链和 `mise.toml`。后端使用 Java、Maven Wrapper，Web 和流程设计器使用 Node.js、pnpm；进入对应子项目后执行 `mise trust`、`mise install` 和 `mise exec`，避免用一个根级版本覆盖不同项目的构建要求。

## 为什么后端默认使用 HTTPS

开发配置默认启用 HTTPS，以便验证刷新 Cookie、CSRF 和前后端安全通信。Web 的 `VITE_API_URL` 也必须使用 HTTPS 并指向后端实际地址。证书错误应通过信任本机证书或修正证书配置解决，不应在生产环境关闭安全 Cookie。

## 为什么 Redis 不可用时登录失败

安全 Redis 保存 Token、Session、验证码、防重放和登录失败锁定等安全运行态。服务端无法确认这些状态时必须 fail-closed，不能退化为无会话或无验证码模式。先检查 Redis 地址、端口、密码和服务状态。

## 为什么能看到页面但不能操作

页面菜单、按钮和接口权限是不同层次。前端可能已经加载路由，但后端仍会检查 Permission、角色边界、用户状态、Session 和数据范围。检查账号的 RoleAssignment、菜单权限和业务数据范围，并重新登录刷新权限状态。

## 为什么上传需要先分析文件

前端先计算文件大小和 SHA-256，服务端据此执行类型、大小、秒传和断点续传判断。最终文件仍由服务端重新计算摘要和大小；客户端摘要不能替代服务端校验。

## 为什么流程设计器不能直接选择用户或表单

流程插件只提供 Picker 事件和属性面板，不拥有宿主业务的用户、用户组、表单、Java 类和流程选择器。宿主项目需要监听 `property:picker`，打开自己的业务选择器，再通过 `resolve` 回填值。

## 如何判断文档过时

对照当前子模块提交、构建文件、路由、Controller、配置绑定类和 Flyway migration。如果页面名称、路径、命令或字段不一致，应提交文档问题并附上当前事实来源；不要自行复制本机配置或生产数据作为复现材料。
