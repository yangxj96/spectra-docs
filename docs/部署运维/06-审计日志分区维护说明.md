# 审计日志分区维护说明

操作日志与安全审计事件统一写入 `spectra_core.sys_audit_event`。表按 `occurred_at` 使用 PostgreSQL RANGE 分区，并包含 `sys_audit_event_default` 默认分区。应用直接同步写入数据库，不使用审计 outbox、外部投递队列或对象存储归档。

分区创建、边界管理、备份恢复和数据清理由 DBA 负责。本项目不规定保留时长，也不提供应用侧迁移、归档、恢复或清理入口。所有 DBA 操作应通过变更单执行，并遵循组织的数据保留和备份策略。

## 权限与数据约束

- 应用运行账号对分区父表仅有 `SELECT`、`INSERT` 权限；应用不可更新或删除审计记录。
- 父表上的触发器拒绝更新和删除。不要通过应用账号、业务 SQL 或应用迁移清理审计事实。
- 审计详情由 `(event_id, occurred_at)` 定位，维护时必须保留复合主键和 `occurred_at` 分区键。
- 默认分区用于接收尚无专属范围分区的记录。默认分区持续增长表示需要检查未来分区是否按计划创建。

## 创建未来分区

DBA 应按已批准的分区粒度，在目标时间范围开始前创建分区。以下示例创建 UTC 月分区；实际命名与时间边界按数据库维护规范调整：

```sql
CREATE TABLE spectra_core.sys_audit_event_2026_10
    PARTITION OF spectra_core.sys_audit_event
    FOR VALUES FROM ('2026-10-01 00:00:00+00')
             TO ('2026-11-01 00:00:00+00');
```

PostgreSQL 在创建分区时会检查默认分区中是否存在落入新边界的数据。如果存在，创建会失败；不要绕过检查或直接禁用审计保护。DBA 应在维护窗口制定数据整理方案，核对受影响时间范围、锁影响、备份和回退步骤，再创建目标分区。分区创建后确认默认分区不再承载该范围的数据，并抽查目标分区的约束、索引、触发器和运行账号权限。

## 例行检查

在变更记录中核对父表、分区及边界，可使用 PostgreSQL 分区目录视图：

```sql
SELECT
    parent.relid::regclass AS parent_table,
    child.relid::regclass AS partition_table,
    child.isleaf,
    child.level
FROM pg_partition_tree('spectra_core.sys_audit_event'::regclass) AS child
JOIN pg_class parent ON parent.oid = child.parentrelid
ORDER BY child.relid::regclass::text;
```

同时检查默认分区的行数趋势、已创建分区覆盖范围、审计追加失败告警、父表及叶子分区权限，以及备份恢复演练结果。具体采样频率和容量阈值由 DBA 按部署规模制定。

## 数据清理和备份恢复

保留期限和清理时点由 DBA 根据正式的数据治理要求确定，不由应用配置推导。删除历史数据前，DBA 应确认适用的保留规则、法律/调查冻结、备份完整性和审批记录；通过数据库分区维护流程实施，并保留可审计的操作证据。不可使用应用接口或普通运行账号删除数据。

备份和恢复时应验证统一审计表、所有需要保留的分区、分区边界、主键、索引、追加写入约束及运行账号权限。恢复到新实例后，还应插入一条隔离测试审计事件并确认它按 `occurred_at` 路由到预期分区；测试数据须按恢复演练方案处置。
