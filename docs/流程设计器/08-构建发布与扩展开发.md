# 构建发布与扩展开发

> 对应项目：`logicflow-plugin-flowable/`。构建配置为 `tsup.config.ts`，示例位于 `examples/`。

## 项目命令

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装插件和示例依赖 |
| `pnpm run dev` | tsup 监听源码并持续构建 |
| `pnpm run build` | 生成发布产物 |
| `pnpm run format` | 格式化 `src`、脚本和 tsup 配置 |
| `pnpm run format:check` | 检查格式 |
| `cd examples && pnpm dev` | 启动 Vue + Vite 示例 |

当前插件包没有独立的 Vitest/Jest 测试脚本，交付验证以格式检查、TypeScript/tsup 构建、示例运行和 `spectra-ui` 宿主测试为主。新增复杂转换规则时应补充可执行的宿主或独立测试。

## 构建产物

`tsup.config.ts` 的入口是 `src/index.ts`，输出：

```text
dist/
├── index.js       ESM
├── index.cjs      CommonJS
├── index.d.ts     TypeScript 声明
├── index.d.cts    CommonJS 声明
├── index.css      LogicFlow 核心 CSS + 插件 CSS
└── *.map          sourcemap
```

Vue、Element Plus、LogicFlow Core 和 LogicFlow Extension 作为 external，不打入插件 JavaScript。`onSuccess` 执行 `scripts/merge-css.mjs` 合并 CSS；宿主只需引入插件的 `style.css`，如果额外使用 LogicFlow Extension 控件，仍需按扩展包要求引入扩展 CSS。

## 增加新节点类型

以新增一个任务节点为例：

1. 在 `src/elements/nodes/tasks/{node-name}/` 创建 `model.ts`、`view.ts` 和注册入口。文件名遵循 kebab-case，注册文件使用正确的 `index.ts` 文件名。
2. 在 `src/core/constants.ts` 增加 `NODE_TYPES`、中文名称和图标。
3. 在 `src/elements/nodes/tasks/index.ts` 调用注册函数。
4. 在 `src/features/schema/nodes/` 新增属性 Schema。
5. 在 `src/features/schema/index.ts` 导出并加入 `schemaRegistry`。
6. 在 `src/features/behaviors/index.ts` 增加连接规则。
7. 在 `src/panel/dnd/index.ts` 增加 DND 条目和分组。
8. 在 `src/features/import/types.ts` 增加 XML 标签映射，在 `src/features/export/types.ts` 增加反向映射。
9. 检查导入、导出、属性面板、连接规则和 Spectra 宿主显示。
10. 更新 [[03-BPMN元素与节点模型]]、[[04-属性Schema与编辑面板]] 和本页。

## 增加属性字段

新增字段时必须同时确定：

- BPMN inline 属性还是 children 子元素。
- 默认值、控件类型、下拉选项和必填规则。
- 是否使用 Flowable 命名空间。
- 是否需要 CDATA 或特殊 XML 标签处理。
- 是否需要业务 Picker，以及宿主是否能提供对应对话框。
- 导入时如何从 XML 还原，导出时如何生成 XML。

只修改面板 Schema 而不修改导入导出，会导致用户看到的值无法保存或重新打开后丢失。

## 增加 Picker 类型

1. 在 `features/schema/types.ts` 扩展 `PickerType` 联合类型。
2. 在对应 Schema 字段设置 `pickerType` 和 `pickerMultiple`。
3. 在宿主监听 `property:picker`，创建业务选择器并调用 `resolve`。
4. 为 value、label、单选/多选和取消场景补充文档。
5. 确认 label 字段不会被导出为 BPMN 属性。

插件只发布 Picker 协议，不绑定 Spectra API，保证 npm 包可以被其他宿主复用。

## 修改导入导出时的检查

```text
Schema
  ├─ 新建画布默认值
  ├─ 属性面板编辑和 setProperties
  ├─ toBpmnXml 属性/子元素/CDATA
  └─ fromBpmnXml XML → form

元素
  ├─ LogicFlow register
  ├─ DND 条目
  ├─ NodeBehavior
  └─ DI 尺寸和连线锚点
```

至少执行新建、编辑、导出、重新导入和部署前检查；重点检查特殊字符、重复 ID、旧 XML 兼容标签、无 DI XML 和 Flowable 命名空间属性。

## Spectra 联调

插件使用本地 `file:` 依赖接入 `spectra-ui`，开发时 Vite 别名会指向插件源码，样式别名指向 `dist/index.css`。推荐：

```bash
# 终端一：插件目录
pnpm run dev

# 终端二：spectra-ui 目录
pnpm start
```

插件初始化、CSS 或构建入口变化后，使用 `pnpm run build` 生成产物，再在 Web 页面验证宿主集成。

## 发布前检查

```bash
pnpm run format:check
pnpm run build
```

然后在示例项目和 `spectra-ui` 流程编辑页面验证：面板挂载、节点拖拽、属性编辑、Picker 回填、XML 导入、XML 导出、部署按钮和错误状态。
