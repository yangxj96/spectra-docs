# 插件架构与初始化

> 对应源码：`logicflow-plugin-flowable/src/index.ts`、`src/core/index.ts`、`src/elements/`、`src/panel/` 和 `src/features/`。

## 模块分层

```text
src/index.ts
  └─ Flowable 默认导出
       ├─ Plugin → core/FlowablePlugin
       ├─ toBpmnXml → features/export
       └─ fromBpmnXml → features/import

core/
  ├─ constants.ts       类型、名称、图标和插件名
  ├─ domain-types.ts    LogicFlow properties / form 类型
  └─ index.ts            插件初始化编排

elements/               BPMN Model / View / register
panel/                  DND、属性面板
features/
  ├─ schema/             属性定义和类型映射
  ├─ behaviors/          连线创建阶段规则
  ├─ context/            流程上下文
  ├─ context-menu/       节点和连线右键菜单
  ├─ import/             BPMN XML → LogicFlow
  └─ export/             LogicFlow → BPMN XML
```

## FlowablePlugin 初始化顺序

插件构造函数接收 `{ lf, options }`，合并默认选项后执行 `init()`：

```text
new FlowablePlugin({ lf, options })
  │
  ├─ initContext()
  │    └─ WeakMap 记录 process id / name / isExecutable
  ├─ initElements()
  │    └─ 注册事件、任务、顺序流、网关、子流程和调用活动
  ├─ initPlugins()
  │    ├─ registerContextMenu(lf)
  │    └─ DynamicGroup（子流程容器）
  ├─ initDefaultConfig()
  │    ├─ 默认边类型 bpmn:sequenceFlow
  │    └─ graphModel.editConfigModel.allowResize = true
  └─ bindEvents()
       ├─ graph:rendered → 挂载 DND / 属性面板
       └─ connection:not-allowed → 输出拒绝原因
```

初始化不会自动调用 `lf.render()`；宿主仍必须在创建实例后调用渲染。面板在 `graph:rendered` 后挂载，避免容器还未准备完成。

## 流程上下文

`features/context/process.ts` 使用 `WeakMap<LogicFlow, ProcessModel>` 保存每个 LogicFlow 实例独立的流程元数据：

| 字段 | 默认值 | XML 用途 |
|---|---|---|
| `id` | `process-` + UUID | `<process id>` 和 BPMNPlane 的 `bpmnElement` |
| `name` | `新建流程` | `<process name>` |
| `category` | 未设置 | `definitions.targetNamespace` |
| `documentation` | 未设置 | `<documentation>` |
| `isExecutable` | `true` | `<process isExecutable>` |

流程上下文不是 Vue 响应式对象。属性面板编辑流程字段时会写回真实上下文；XML 导入更新上下文后发出 `process:change`，属性面板用该事件刷新快照。

## LogicFlow 模型与属性

插件在 `BpmnProperties` 中扩展 LogicFlow properties：

```typescript
interface BpmnProperties extends LogicFlow.PropertiesType {
  form?: Record<string, unknown>;
  schemas?: Property[];
  rules?: Record<string, unknown>;
  name?: string;
}
```

节点和边的用户编辑值统一放在 `properties.form`；`schemas` 保存该元素使用的属性定义。导出层从 LogicFlow 的真实 model 读取最新数据，而不是依赖面板的临时快照。

## 注册和销毁

注册函数都接收 LogicFlow 实例并调用 `lf.register({ type, model, view })`。DND 和属性面板使用 `WeakMap<HTMLElement, App>` 防止同一个容器重复挂载，并返回卸载函数。

上下文菜单当前使用模块级挂载标记，只向 `document.body` 挂载一次；如果宿主同时创建多个编辑器，需要关注全局菜单的生命周期和事件绑定范围。

## 扩展点

- 在 `core/types.ts` 扩展插件选项时，保持面板容器和宿主回调的边界。
- 在 `features/schema/types.ts` 增加属性控件或 Picker 类型。
- 在 `panel/property/renderer/` 注册自定义渲染器。
- 在 `features/behaviors/` 增加节点连接规则。
- 在 `elements/` 增加 Model、View 和注册函数。
- 在 `features/import/types.ts` 与 `features/export/types.ts` 同步 XML 映射。

新增能力至少要补充对应的 Schema、DND 条目、行为规则、导入导出映射和宿主文档，不能只注册一个视觉节点。
