# 连接规则与交互行为

> 对应源码：`src/features/behaviors/`、各元素 Model 和 `src/features/context-menu/`。

## 校验边界

当前源码实现的是 LogicFlow 连线创建阶段规则：

```text
用户拖动创建连线
    │
    ├─ sourceRules：能否出线、目标类型、最大出线、重复线
    └─ targetRules：能否入线、来源类型、最大入线
```

`NodeBehavior` 中虽然有 `minIn` 和 `minOut` 字段，但它们只为未来的图级完整性校验保留，当前没有独立的 `BehaviorsEngine`，也不会自动在保存或部署前检查整张流程图。

因此，“连线创建成功”不等于“流程可以部署”。宿主应在部署前额外检查开始/结束节点、孤立节点、网关分支条件、默认流和节点连通性。

## NodeBehavior 字段

| 字段 | 当前用途 |
|---|---|
| `allowIn` / `allowOut` | 是否允许作为连线终点/起点，创建阶段执行 |
| `maxIn` / `maxOut` | 最大入线/出线，创建阶段执行 |
| `minIn` / `minOut` | 最小入线/出线，当前只记录规则意图 |
| `allowSourceTypes` | 作为目标时允许的来源类型，当前未配置具体白名单 |
| `allowTargetTypes` | 作为来源时允许的目标类型，当前未配置具体白名单 |
| `type` | 用于拒绝提示中的中文节点名称 |

所有行为定义集中在 `NODE_BEHAVIORS`，各节点 Model 在构造函数中调用 `createConnectRules()`，直接写入 `sourceRules` 和 `targetRules`。这样可以避免 LogicFlow 首次访问规则时缓存到尚未配置的结果。

## 当前连接规则矩阵

| 节点 | 入线 | 出线 | 最小/最大约束 |
|---|---|---|---|
| 开始事件 | 禁止 | 允许 | 出线 1；入线 0 |
| 结束事件 | 允许 | 禁止 | 入线至少 1；出线 0 |
| 中间捕获/抛出事件 | 允许 | 允许 | 入线至少 1，出线至少 1；上限 99 |
| 边界事件 | 禁止 | 允许 | 入线 0；出线至少 1；附着关系由属性字段表达 |
| 用户/服务/脚本任务 | 允许 | 允许 | 入线至少 1；出线最多 1 |
| 接收任务 | 允许 | 允许 | 入线至少 1；出线最多 1，允许暂时无出线 |
| 嵌入式子流程 | 允许 | 允许 | 入线至少 1；出线至少 1；上限 99 |
| 调用活动 | 允许 | 允许 | 入线至少 1；出线最多 1 |
| 排他/包容/并行网关 | 允许 | 允许 | 入线至少 1；出线至少 2；上限 99 |

注意：当前网关 Schema 中包含默认路径字段，行为规则只限制拓扑数量，并不会自动验证每一条分支的条件和默认路径语义。

## 已实现的创建阶段规则

`createSourceRules()` 和 `createTargetRules()` 会按顺序执行：

- 节点不允许出线/入线时直接拒绝。
- 如果配置类型白名单，校验目标或来源类型。
- 已达到最大出线/入线数量时拒绝。
- 同一来源节点到同一目标节点已有连线时拒绝重复连接。

连线被拒绝时，插件监听 `connection:not-allowed` 并向控制台输出节点名称和 LogicFlow 提供的原因，便于开发调试；页面是否显示友好提示由宿主决定。

## 右键菜单

节点和连线通过 `node:contextmenu`、`edge:contextmenu` 打开全局上下文菜单：

- 节点：删除节点。
- 连线：删除顺序流、默认流入口。
- 点击外部：关闭菜单。
- DynamicGroup 存在时，删除子流程节点会暂时移除其删除监听，直接调用 `graphModel.deleteNode()`，再恢复监听，避免级联删除递归。

当前“设置为默认流”条目仍然是日志占位，不会修改网关或顺序流属性。不要在业务文档中将它描述为已完成能力。

## 宿主部署前校验建议

在调用 `Flowable.toBpmnXml()` 和部署 API 前，宿主至少应检查：

1. 流程 ID、流程名称非空且 ID 符合 XML NCName。
2. 至少有一个开始事件和结束事件。
3. 没有孤立节点，每条连线引用的节点存在。
4. 开始/结束、任务、网关的最小入线/出线满足规则。
5. 排他网关和包容网关的分支条件、默认路径符合业务要求。
6. 并行网关没有条件或默认流配置。
7. 用户任务的人员/组、服务任务的实现方式、调用活动的流程 Key 已正确配置。
8. 脚本、表达式和 Flowable 扩展属性符合后端部署能力。

这些是宿主层建议，不代表插件当前已经提供完整校验器。
