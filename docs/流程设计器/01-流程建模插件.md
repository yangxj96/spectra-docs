# 流程建模插件使用指南

> 对应仓库：`logicflow-plugin-flowable/`。npm 包：`@yangxj96/logicflow-plugin-flowable`。当前 `package.json` 版本为 `0.1.2`。

## 安装和对等依赖

```bash
pnpm add @yangxj96/logicflow-plugin-flowable
```

宿主项目需要自行安装以下对等依赖：

| 依赖 | 当前约束 |
|---|---|
| `@logicflow/core` | `^2.1.11` |
| `@logicflow/extension` | `^2.1.11` |
| `element-plus` | `>=2.13.2 <3` |
| `vue` | `>=3.5.28 <4` |
| `preact` | `^10.17.1`，可选 |

版本约束以插件 `package.json` 为准。

## 最小集成

插件不会创建外层布局，宿主必须提供画布、DND 面板和属性面板容器，并保证容器及父级有明确高度：

```html
<div class="flowable-editor">
  <aside id="dnd-panel"></aside>
  <main id="graph"></main>
  <aside id="property-panel"></aside>
</div>
```

```css
.flowable-editor {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr) 320px;
  width: 100%;
  height: 720px;
  min-height: 0;
}

.flowable-editor > * {
  min-width: 0;
  min-height: 0;
  overflow: hidden;
}
```

创建 LogicFlow 并注册插件：

```typescript
import LogicFlow from "@logicflow/core";
import Flowable, {
  type FlowablePluginOptions,
  type PickerRequestPayload
} from "@yangxj96/logicflow-plugin-flowable";
import "@yangxj96/logicflow-plugin-flowable/style.css";

const lf = new LogicFlow({
  container: document.querySelector("#graph") as HTMLElement,
  grid: true,
  plugins: [Flowable.Plugin],
  pluginsOptions: {
    [Flowable.Plugin.pluginName]: {
      panel: {
        dnd: document.querySelector("#dnd-panel") as HTMLElement,
        property: document.querySelector("#property-panel") as HTMLElement
      },
      pickers: ["form", "user", "group", "javaClass", "process"]
    } satisfies FlowablePluginOptions
  }
});

lf.render({});
```

如果不需要内置面板，可以只传入插件：

```typescript
const lf = new LogicFlow({
  container: graphContainer,
  plugins: [Flowable.Plugin],
  pluginsOptions: {
    [Flowable.Plugin.pluginName]: {}
  }
});
```

## 插件配置

```typescript
interface FlowablePluginOptions {
  panel?: {
    dnd?: HTMLElement;
    property?: HTMLElement;
  };
  pickers?: PickerType[];
}
```

| 配置 | 说明 |
|---|---|
| `panel.dnd` | DND 面板挂载容器；不配置则不挂载 |
| `panel.property` | 属性面板挂载容器；不配置则不挂载 |
| `pickers` | 宿主已经实现的选择器类型，未声明的 Picker 降级为普通文本输入 |

面板可以独立配置。宿主必须在 LogicFlow 初始化前准备好容器，并处理好 `min-height: 0`、滚动和销毁生命周期。

## 公共入口

默认导出对象包含三个 API：

| API | 说明 |
|---|---|
| `Flowable.Plugin` | LogicFlow 插件类，负责注册元素和内置能力 |
| `Flowable.toBpmnXml(lf)` | 将当前画布导出为 BPMN 2.0 XML |
| `Flowable.fromBpmnXml(xml, lf)` | 解析 XML 并直接渲染到指定 LogicFlow 实例 |

公共类型从包根入口导出：

```typescript
import type {
  FlowablePluginOptions,
  ImportResult,
  PickerRequestPayload,
  PickerType
} from "@yangxj96/logicflow-plugin-flowable";
```

## 内置面板

### DND 面板

DND 面板根据 `DND_ITEMS` 按事件、任务、网关、子流程分组，拖动条目会调用 `lf.dnd.startDrag({ type, text })`。默认分组和节点详见 [[03-BPMN元素与节点模型]]。

### 属性面板

属性面板根据当前选择切换编辑对象：

- 点击空白区域：流程属性。
- 点击节点：节点属性。
- 点击连线：连线属性。

控件由 Schema 的 `component` 字段决定，包括普通文本、多行文本、数字、布尔开关、下拉框、表达式和 Picker。字段修改会更新 LogicFlow 模型；名称字段还会同步更新画布文本。详见 [[04-属性Schema与编辑面板]]。

### 右键菜单

节点右键菜单目前提供删除节点；连线右键菜单提供删除顺序流和默认流入口。菜单挂载到 `document.body`，点击画布外部会关闭。默认流菜单当前只输出日志，不能当作已经完成的默认流业务设置。

## Picker 接入

插件不访问宿主业务 API，也不创建用户、表单或流程选择弹窗。宿主将支持的类型放到 `pickers` 后，属性面板点击“选择”会发出 `property:picker`：

```typescript
lf.on("property:picker", (payload: PickerRequestPayload) => {
  openBusinessDialog({
    type: payload.pickerType,
    multiple: payload.multiple,
    currentValue: payload.currentValue,
    onConfirm(items) {
      const value = items.map(item => item.value).join(",");
      const label = items.map(item => item.label ?? item.value).join(",");
      payload.resolve(value, label);
    }
  });
});
```

`resolve(value, label)` 中，`value` 写入 BPMN 属性，`label` 写入同名的 `字段名Label` 辅助字段，只用于面板显示。多选值使用逗号分隔。宿主取消弹窗时不要调用 `resolve`。

当前 Picker 类型：

| 类型 | 典型字段 | 选择结果 |
|---|---|---|
| `form` | `flowable:formKey` | 表单编码 |
| `user` | `flowable:assignee`、`flowable:candidateUsers` | 用户 ID |
| `group` | `flowable:candidateGroups` | 用户组/部门 ID |
| `javaClass` | `flowable:class` | Java 全限定类名 |
| `process` | `calledElement` | 流程 Key |

## 导入导出快速使用

```typescript
const xml = Flowable.toBpmnXml(lf);

const result: ImportResult = Flowable.fromBpmnXml(xml, lf);
if (!result.success) {
  console.error(result.message);
}
```

导入依赖浏览器 `DOMParser`，服务端渲染环境不能直接调用。XML 支持、ID 规范化、DI 坐标和当前限制见 [[06-BPMN导入导出]]。

## 与 Flowable 的职责关系

```text
编辑画布 → toBpmnXml() → WorkflowApi.deployProcess()
                                     │
                                     ▼
                           spectra-admin / Flowable 部署
                                     │
             任务、实例、版本、权限和业务数据由后端负责
```

插件生成 XML，但不保存流程定义、不递增版本、不执行流程，也不负责后端 API 权限。Spectra 中的完整接入见 [[07-Spectra宿主集成]]。
