# 脚本工具

> 本页只记录当前仓库实际存在的 Linux/WSL 工具。普通开发直接使用 mise 和各子项目的原生命令，不需要额外 runtime fallback。

## 可直接使用

以下脚本都从仓库根目录执行，并通过脚本位置解析仓库根目录，不依赖个人盘符：

| 脚本 | 是否修改文件/环境 | 用途 |
|---|---|---|
| `scripts/agent-context.sh` | 否 | 输出工具路由、项目事实和建议验证命令 |
| `scripts/check-agent-context.sh` | 否 | 审计 AGENTS 文件大小和根指令加载规则 |
| `scripts/check-docs.sh` | 否 | 校验 wikilink、Entity/Controller 数量、配置和过期引用 |
| `scripts/check-module-boundaries.sh` | 否 | 校验 Java 包、Maven 直接依赖和模块边界 |
| `scripts/import-regions.sh` | 只写入明确指定的隔离数据库 | 受 `SPECTRA_REGION_IMPORT=true` 保护的行政区划导入 |
| `scripts/sync-website-docs.sh` | Preview 不修改；Apply 修改网站生成目录 | 同步项目文档、附件、侧边栏和清单 |

```bash
./scripts/agent-context.sh --facts
./scripts/check-agent-context.sh
./scripts/check-docs.sh
./scripts/check-module-boundaries.sh
```

这些脚本都不负责激活 mise，也不会替代 `mise exec`。日常启动和安装依赖不需要它们：

- `agent-context.sh`、`check-agent-context.sh` 只服务于 Agent 路由和指令审计，完全可跳过。
- `check-docs.sh` 在文档、配置、Entity 或 Controller 变更后运行。
- `check-module-boundaries.sh` 是后端模块边界的推荐质量门禁，不是每次启动的前置步骤。
- `import-regions.sh` 只在明确需要导入行政区划数据且目标是隔离数据库时运行。
- `sync-website-docs.sh` 只在发布网站文档时运行。

首次使用前可执行：

```bash
chmod +x scripts/*.sh scripts/tests/*.sh
```

## 本机配置

- 后端配置：`spectra-admin/.mise.local.toml`，从 `.mise.local.toml.example` 复制。
- Web 配置：`spectra-ui/.env.development`，从 `.env.example` 复制。
- 证书：`spectra-admin/files/ssl/keystore.p12`，仅保存在本机。

这些文件可能包含密码、Token、私钥或证书私钥；脚本只读取项目模板和路径，不读取或输出本机敏感值。

## 工具要求

| 工具 | 用途 |
|---|---|
| Bash、`find`、`stat`、`git`、`rg` | 脚本执行和检查 |
| Python 3.12+ 标准库 | 文档、JSON、XML 和网站同步实现 |
| mise | 固定 Java、Node 和 pnpm 版本 |
| OpenSSL、`keytool` | 本机证书检查或生成 |

普通开发终端只需保证 `mise` 在 PATH 中，并在对应子项目目录执行 `mise exec -- ...`。

## 网站文档同步

网站同步入口为 `scripts/sync-website-docs.sh`，参数使用 POSIX 长选项：

```bash
./scripts/sync-website-docs.sh \
  --website-root /path/to/website \
  --mode Preview

./scripts/sync-website-docs.sh \
  --website-root /path/to/website \
  --mode Apply --prune-legacy --build
```

Preview 不修改网站仓库；Apply 不自动执行 Git commit 或 push。同步会拒绝 `.env*`、`.mise.local.toml`、P12/JKS/PEM/KEY 以及名称包含 secret/token/password 的文件。
