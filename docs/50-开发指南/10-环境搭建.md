# 环境搭建

> Spectra 项目完整开发环境搭建指南。

## 前置依赖

| 依赖 | 版本 | 安装方式 |
|---|---|---|
| JDK | 25 (Temurin) | 通过 mise 或手动安装 |
| Node.js | 24.14.0 | 通过 mise 管理 |
| pnpm | 11.0.9 | 通过 mise 管理 |
| Maven | 3.9.12 | 项目自带 `mvnw` wrapper |
| PowerShell | 7.6 或更高版本 | 使用 `pwsh.exe`，不支持 Windows PowerShell 5.1 |
| PostgreSQL | 18 | Docker 或本地安装 |
| Redis | — | Docker 或本地安装 |

## Windows PowerShell 配置

项目命令只支持 PowerShell 7.6 或更高版本，当前固定入口为：

```text
C:\Program Files\PowerShell\7\pwsh.exe
```

执行以下命令确认版本和实际程序路径：

```powershell
$PSVersionTable.PSVersion
(Get-Process -Id $PID).Path
```

预期主版本至少为 `7.6`，路径为 `C:\Program Files\PowerShell\7\pwsh.exe`。Windows PowerShell 5.1 的 `powershell.exe` 不作为项目运行环境，也不要为它维护项目 profile 或执行策略。根目录三个 `.ps1` 脚本都包含 `#requires -Version 7.6`，低版本会在执行前直接失败。

PowerShell 7 使用以下 profile：

| Shell | Profile |
|---|---|
| PowerShell 7 (`pwsh.exe`) | `C:\Users\<用户名>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1` |

Oh My Posh 主题放在用户可读目录，例如：

```text
C:\Users\<用户名>\Documents\PowerShell\themes\ys.omp.json
```

不要在 profile 中扫描 `C:\Program Files\WindowsApps` 查找主题；普通用户可能无法读取该目录，且 MSIX 版本目录会随升级变化。公共脚本直接使用固定用户路径：

```powershell
$themePath = Join-Path $env:USERPROFILE 'Documents\PowerShell\themes\ys.omp.json'

if (Get-Command oh-my-posh -ErrorAction SilentlyContinue) {
    if (Test-Path -LiteralPath $themePath -PathType Leaf) {
        oh-my-posh init pwsh --config $themePath | Invoke-Expression
    } else {
        oh-my-posh init pwsh | Invoke-Expression
    }
}
```

如果终端仍启动到 `powershell.exe`，应直接关闭并从 `C:\Program Files\PowerShell\7\pwsh.exe` 重开；不要通过放宽全局执行策略来兼容 5.1。

## mise 配置

项目使用 [mise](https://mise.jdx.dev/) 管理运行时版本。

根目录 `.mise.local.toml` 只保存本机环境变量；工具版本分别由四个子项目的 `mise.toml` 管理。`spectra-admin/mise.toml` 固定 JDK，三个 Node 项目各自固定 Node.js 与 pnpm。

完整环境变量清单以 `spectra-admin/.mise.local.toml.example` 为准：

| 分组 | 变量 | 说明 |
|---|---|---|
| 数据库 | `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` | PostgreSQL 连接 |
| 服务 | `SERVER_PORT`、`DEFAULT_PASSWORD` | 端口与默认密码 |
| Redis | `REDIS_HOST`、`REDIS_PORT`、`REDIS_DB`、`REDIS_PASSWORD` | 缓存连接 |
| SSL | `SSL_PASSWORD`、`SSL_TYPE`、`SSL_ALIAS` | 本地 HTTPS |
| S3 | `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION` | 对象存储 |
| AI | `AI_KEY`、`AI_BASE_URL`、`AI_MODEL` | AI 服务 |
| RAG | `RAG_KEY`、`RAG_BASE_URL`、`RAG_MODEL` | 检索增强生成 |

复制模板后只在被 Git 忽略的 `.mise.local.toml` 中填写真实值。本项目本地联调约定 `SERVER_PORT=4004`；不要把密码、Token、私钥或完整本地配置复制到文档、Agent 指令、Issue 或聊天中。

## 初始化步骤

### 1. 配置后端

```bash
# 进入 spectra-admin 目录
cd spectra-admin

# 复制环境配置模板
copy .mise.local.toml.example .mise.local.toml

# 编辑 .mise.local.toml，填入实际的数据库/Redis/S3/AI 凭据
```

### 2. 配置前端

```bash
# spectra-ui（默认已配置，指向 localhost:4004）
cd spectra-ui
# .env 已存在，如需修改：
# VITE_API_URL=https://127.0.0.1:4004/

# spectra-app（默认已配置）
cd spectra-app
# .env.development 已存在：
# VITE_API_BASE_URL=https://127.0.0.1:4004
```

### 3. 启动数据库和 Redis

确保 PostgreSQL 和 Redis 服务已启动。

### 4. 启动后端 API

```powershell
Set-Location spectra-admin

# 先编译打包，再运行 spectra-launch 生成的可执行 JAR
.\mvnw.cmd clean package -DskipTests
$jar = Get-ChildItem .\spectra-launch\target\spectra-launch-*.jar -File |
    Where-Object { $_.Name -notlike '*.jar.original' } |
    Select-Object -First 1
java --add-modules ALL-SYSTEM --enable-native-access=ALL-UNNAMED `
    -Dspring.profiles.active=dev `
    -jar $jar.FullName
# API 运行在 https://127.0.0.1:4004/api
```

### 5. 启动前端

```bash
# Web 管理后台
cd spectra-ui
pnpm install
pnpm start           # → http://localhost:5173

# 移动端 H5
cd spectra-app
pnpm start           # → http://localhost:5174
```

`pnpm start` 已包含 type-check、lint 和 format。首次配置或依赖缺失时再执行 `pnpm install`，不要在每次启动前重复安装依赖。
