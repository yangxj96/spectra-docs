# 环境搭建

> 本页是新机器或新克隆工作区的唯一启动入口。除明确标成“本机配置”的内容外，命令都使用仓库相对路径。

## 先区分三类内容

| 分类 | 内容 | 使用方式 |
|---|---|---|
| 仓库内可直接复用 | 四个子项目的 `mise.toml`、`spectra-admin/mvnw.cmd`、各项目 `package.json` 脚本、`docs/sql/`、4004/5173/5174 端口约定 | 克隆后直接使用 |
| 必须创建的本机配置 | `spectra-admin/.mise.local.toml`、`spectra-ui/.env.development`、`spectra-app/.env.development` | 从相邻的 `.example` 文件复制；真实值不得提交 |
| 可选的个人工具配置 | PowerShell profile、Oh My Posh、CodeGraph、根目录 `.mise.local.toml`、`SPECTRA_AGENT_*`、Codex Maven 缓存 | 不影响普通构建和启动；只有确实使用对应工具时才配置 |

`127.0.0.1` 和 `localhost` 不是某个开发者的专属路径，而是“服务与客户端在同一台机器”的默认拓扑。数据库、Redis 或后端放在容器、虚拟机、局域网或远程服务器时，必须换成实际可访问地址。

## 前置依赖

| 依赖 | 版本/要求 | 是否由仓库提供 |
|---|---|---|
| Git | 支持 submodule | 否 |
| PowerShell | 7.6 或更高版本，命令为 `pwsh` | 否 |
| mise | 能在终端中执行 `mise` | 否 |
| JDK | Temurin 25.0.2 | 版本由 `spectra-admin/mise.toml` 固定 |
| Node.js | 24.14.0 | 版本由三个 Node 项目的 `mise.toml` 固定 |
| pnpm | 11.0.9 | 版本由三个 Node 项目的 `mise.toml` 固定 |
| Maven | 3.9.12 | 是，使用 `spectra-admin/mvnw.cmd` |
| PostgreSQL | 18 | 否 |
| Redis | 支持密码认证 | 否 |

项目脚本要求 PowerShell 7.6+，但不要求 `pwsh.exe` 位于某个固定磁盘路径。这样检查当前机器：

```powershell
$PSVersionTable.PSVersion
(Get-Command pwsh).Source
mise --version
```

如果 `pwsh` 未找到或仍打开 Windows PowerShell 5.1，请安装 PowerShell 7，并在终端/IDE 中把默认 Shell 改成实际的 `pwsh`。`C:\Program Files\PowerShell\7\pwsh.exe` 只是 Windows 官方安装包常见位置，不是项目硬编码要求。

## 1. 克隆并确认子模块

```powershell
git clone --recurse-submodules https://github.com/yangxj96/spectra-docs.git spectra
Set-Location .\spectra
git submodule status
```

如果已经普通克隆：

```powershell
git submodule update --init --recursive
```

以下命令都假设当前目录是仓库根目录。仓库可以放在任意用户目录或磁盘，不要把文档中的 `spectra` 文件夹名理解为固定绝对路径。

## 2. 信任并安装项目固定运行时

mise 信任是一次性的人工安全决定。首次进入每个子项目时，如果 mise 提示未信任，先检查对应 `mise.toml`，然后在该子项目目录执行一次：

```powershell
mise trust
mise install
```

正常终端建议按 mise 官方方式激活 PowerShell；没有写入 profile 时，可在当前终端临时激活：

```powershell
(& mise activate pwsh) | Out-String | Invoke-Expression
```

根目录 `scripts/agent-runtime.ps1` 是 Codex/CI 沙箱回退工具，不是普通开发者的必经步骤，详见 [[20-常见命令]]。

## 3. 创建后端本机配置

仓库提交的是模板，真实配置文件被 Git 忽略：

```powershell
Copy-Item .\spectra-admin\.mise.local.toml.example .\spectra-admin\.mise.local.toml
```

编辑 `spectra-admin/.mise.local.toml`。当前配置类会在启动时创建数据库、Redis、S3、聊天模型和向量模型相关 Bean，因此模板中的变量都应保留；含义分为两档：

创建本机文件后，如果 mise 针对新文件再次提示未信任，应先审查内容，再在 `spectra-admin/` 中重新执行 `mise trust`；不要自动信任未知配置。

| 级别 | 变量 | 要求 |
|---|---|---|
| 启动必须真实可用 | `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_DB`、`REDIS_PASSWORD` | PostgreSQL 和 Redis 必须能连接 |
| 启动必须存在，功能启用时必须真实可用 | `S3_*` | 首次只验证基础 API 时可保留模板中的本机占位地址；调用上传前必须接入真实服务 |
| 本机策略 | `SERVER_PORT`、`SERVER_SSL_ENABLED`、`SSL_*` | 模板默认 4004 + HTTPS；首次启动前需准备本机 P12 证书并填写密码 |

注意：

- `spectra-admin/.mise.local.toml` 是团队推荐的后端配置位置。
- 根目录 `.mise.local.toml` 是当前维护者可能使用的个人上层覆盖文件，新克隆不需要创建，也不能把其中内容复制进文档。
- 新增用户和密码重置使用随机临时凭证，不再配置共享的 `DEFAULT_PASSWORD`。
- 接口加解密不读取 `SPECTRA_SYSTEM_SM_*` 环境变量；当前开关和密钥在 `spectra_core.sys_config` 的 `crypto.*` 项中动态管理，初始数据默认关闭。
- 通知模块开关和运行时加密密钥在 DEV_OPS 首次登录后的系统设置引导中配置，`NOTIFICATION_*` 不再是首次启动必填环境变量；Worker/清理任务的调度参数使用 application 默认值。

## 4. 准备 PostgreSQL 与 Redis

### PostgreSQL

先创建与 `DB_URL` 一致的空数据库；数据库已经存在时跳过 `createdb`：

```powershell
createdb -h 127.0.0.1 -U postgres devops00_spectra_db
```

新环境由 Flyway 从单一 `V1__init_db.sql` 初始化当前目标结构和全部普通种子；不要把旧版本迁移目录或 `db.dump` 当作另一套运行时结构事实源。应用使用的 Flyway 迁移目录是：

```text
spectra-admin/spectra-config/src/main/resources/db/migration/
```

`spring.sql.init` 的基础 `schema.sql`/`data.sql` 不与 Flyway 并行使用，以免产生两套结构和种子事实源。当前 V1 只负责结构和普通小体量种子，约 66.5 万行 `spectra_core.sys_region` 不再内嵌到 V1；区域 JSON 保存在 `spectra-admin/spectra-modules/spectra-core/src/test/resources/regions`，需要时通过仓库根目录的 `scripts/import-regions.ps1` 显式导入。该脚本受 `SPECTRA_REGION_IMPORT=true` 保护，并按省、市、区县、街道、村级顺序批量写入，普通测试和应用启动不会触发。`db.dump` 是同步导出的开发快照，是否包含区域数据取决于快照生成时机；用户、部门、凭据和 Security 初始化数据不从普通种子自动创建。

如果需要检查迁移状态，可连接目标数据库查询 `flyway_schema_history`；数据库非空但没有匹配的 Flyway 历史时，不要设置 `baselineOnMigrate=true` 绕过校验，应先清理为新库或执行经过审查的一次性迁移流程。

本次将旧 V1～V34 重整为单一 `V1__init_db.sql` 后，已经执行过旧迁移链的数据库不属于可直接升级范围；直接启动会触发历史版本缺失或 checksum mismatch。开发库应重建，保留数据的环境必须先完成审查后的一次性结构/数据迁移，不能仅执行 Flyway `repair` 掩盖差异。

### Redis

确保 Redis 已启动，并为它配置与 `REDIS_PASSWORD` 相同的密码。当前后端使用带密码的 Redis URL；没有密码的本地 Redis 不能直接套用模板。

支持 `--askpass` 的 redis-cli 可以这样验证，不把密码写进命令历史：

```powershell
redis-cli -h 127.0.0.1 -p 6379 --askpass ping
```

预期返回 `PONG`。PostgreSQL 或 Redis 由 Docker、Windows 服务还是远程主机提供均可，关键是本机配置中的地址和凭据必须与实际服务一致。

## 5. 创建前端本机配置

两个前端只提交 `.env.example`。新克隆后必须复制，不能假设 `.env` 或 `.env.development` 已存在：

```powershell
Copy-Item .\spectra-ui\.env.example .\spectra-ui\.env.development
Copy-Item .\spectra-app\.env.example .\spectra-app\.env.development
```

模板与后端首次启动策略一致，默认使用 HTTPS：

```dotenv
# spectra-ui/.env.development
VITE_API_URL=https://127.0.0.1:4004/

# spectra-app/.env.development
VITE_API_BASE_URL=https://127.0.0.1:4004
```

两者的尾部斜杠约定不同，保持模板写法。后端换端口或不在本机时，这两个 URL 必须同步修改；协议保持 HTTPS。

## 6. 安装依赖

首次克隆或锁文件变化后执行一次：

```powershell
Push-Location .\logicflow-plugin-flowable; pnpm install; pnpm run build; Pop-Location
Push-Location .\spectra-ui; pnpm install; Pop-Location
Push-Location .\spectra-app; pnpm install; Pop-Location
```

Web 通过本地 `file:` 依赖使用流程插件，因此首次安装 Web 前先构建插件更容易排查问题。

## 7. 启动

### 后端终端

```powershell
Set-Location .\spectra-admin
.\mvnw.cmd clean package -DskipTests
$jar = Get-ChildItem .\spectra-launch\target\spectra-launch-*.jar -File |
    Where-Object { $_.Name -notlike '*.jar.original' } |
    Select-Object -First 1
java --add-modules ALL-SYSTEM --enable-native-access=ALL-UNNAMED `
    -Dspring.profiles.active=dev `
    -jar $jar.FullName
```

### Web 终端

```powershell
Set-Location .\spectra-ui
pnpm start
```

### H5 终端

```powershell
Set-Location .\spectra-app
pnpm start
```

`pnpm start` 会通过 `prestart` 自动执行项目自己的格式、lint 和类型检查；不需要在同一启动命令里再重复串联。

## 8. 验证

默认 HTTPS 首次启动：

| 项目 | 地址 |
|---|---|
| 后端健康检查 | `https://127.0.0.1:4004/api/actuator/health` |
| Web | `https://localhost:5173` |
| H5 | `https://localhost:5174` |

后端成功日志应包含 `Started LaunchApplication`，并显示 4004 端口。若前端页面能打开但接口失败，优先核对：后端协议（HTTP/HTTPS）、端口、两个前端环境文件和浏览器证书状态。

## 本地 HTTPS 证书

首次启动需要本机开发证书：

1. 按 [[40-SSL证书配置]] 生成 `spectra-admin/files/ssl/keystore.p12`。
2. 在后端本机配置中保持 `SERVER_SSL_ENABLED=true`，并填写匹配的 `SSL_PASSWORD`、`SSL_TYPE`、`SSL_ALIAS`。
3. Vite 会通过 `SSL_PASSWORD` 加载同一个 `keystore.p12`，Web 访问地址使用 `https://localhost:5173`。
4. 只在本机信任自己生成的开发 CA；私钥、P12 和密码不得提交。

## 个人路径与 Agent 回退变量

以下变量只解决特定机器或沙箱的运行时发现问题，普通开发者通常不需要：

| 变量 | 作用 |
|---|---|
| `SPECTRA_AGENT_JAVA_HOME` | 指定 Agent 使用的 JDK 根目录 |
| `SPECTRA_AGENT_NODE_BIN` | 指定 Node 可执行文件所在目录 |
| `SPECTRA_AGENT_PNPM` | 指定 pnpm 可执行文件 |
| `SPECTRA_AGENT_MAVEN_REPO` | 指定 Agent 可写的 Maven 本地仓库 |

不要把某台机器的 `<系统盘>:\Users\<用户名>\...`、`<开发盘>:\<个人目录>\...` 或 IDE 临时目录写进公共启动命令；使用环境变量、`$env:USERPROFILE`、`$env:TEMP` 或仓库相对路径。
