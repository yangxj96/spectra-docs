## Windows PowerShell 配置

项目命令默认在 PowerShell 7 中运行，当前应使用：

```text
C:\Program Files\PowerShell\7\pwsh.exe
```

PowerShell 7 和 Windows PowerShell 5.1 使用不同的 profile 目录：

| Shell | Profile |
|---|---|
| PowerShell 7 (`pwsh.exe`) | `C:\Users\<用户名>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1` |
| Windows PowerShell 5.1 (`powershell.exe`) | `C:\Users\<用户名>\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1` |

两个 profile 应共同加载一个公共脚本。Oh My Posh 主题放在用户可读目录，例如：

```text
C:\Users\<用户名>\Documents\PowerShell\themes\ys.omp.json
```

不要在 profile 中扫描 `C:\Program Files\WindowsApps` 查找主题；普通用户可能无法读取该目录，且 MSIX 版本目录会随升级变化。公共脚本直接使用固定用户路径：

```powershell
$themePath = Join-Path $HOME 'Documents\PowerShell\themes\ys.omp.json'

if (Get-Command oh-my-posh -ErrorAction SilentlyContinue) {
    if (Test-Path -LiteralPath $themePath -PathType Leaf) {
        oh-my-posh init pwsh --config $themePath | Invoke-Expression
    } else {
        oh-my-posh init pwsh | Invoke-Expression
    }
}
```

如果 Windows PowerShell 5.1 报“在此系统上禁止运行脚本”，只对当前用户设置执行策略，并解除 profile 的下载阻止标记：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force
Unblock-File -LiteralPath "$HOME\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1"
Unblock-File -LiteralPath "$HOME\Documents\PowerShell\Microsoft.PowerShell_profile.ps1"
Unblock-File -LiteralPath "$HOME\Documents\PowerShell\profile-common.ps1"
```

不要把全局执行策略设置为 `Bypass` 或 `Unrestricted`。

## mise 配置

项目使用 [mise](https://mise.jdx.dev/) 管理运行时版本。

根目录 `mise.toml` 定义全局工具版本。`spectra-admin/.mise.local.toml` 定义后端专用配置。

完整环境变量清单参见 `spectra-admin/README.md` 和 `.mise.local.toml.example`：

| 分组 | 变量 | 说明 |
|---|---|---|
| 数据库 | `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` | PostgreSQL 连接 |
| 服务 | `SERVER_PORT`、`DEFAULT_PASSWORD` | 端口与默认密码 |
| Redis | `REDIS_HOST`、`REDIS_PORT`、`REDIS_DB`、`REDIS_PASSWORD` | 缓存连接 |
| SSL | `SSL_PASSWORD`、`SSL_TYPE`、`SSL_ALIAS` | 本地 HTTPS |
| S3 | `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION` | 对象存储 |
| AI | `AI_KEY`、`AI_BASE_URL`、`AI_MODEL` | AI 服务 |
| RAG | `RAG_KEY`、`RAG_BASE_URL`、`RAG_MODEL` | 检索增强生成 |

```toml
# spectra-admin/.mise.local.toml （从 .example 复制并修改）
[tools]
java = "temurin-25.0.2+10.0.LTS"

[env]
# 数据库
DB_URL = "jdbc:postgresql://localhost:5432/devops00_spectra_db"
DB_USERNAME = "postgres"
DB_PASSWORD = "xxx"
# 服务
SERVER_PORT = "8080"
DEFAULT_PASSWORD = "admin123"
# Redis
REDIS_HOST = "127.0.0.1"
REDIS_PORT = "6379"
REDIS_DB = "0"
REDIS_PASSWORD = "XXX"
# SSL（可选）
SSL_PASSWORD = "xxx"
SSL_TYPE = "PKCS12"
SSL_ALIAS = "tomcat"
# S3（可选）
S3_ENDPOINT = ""
S3_ACCESS_KEY = ""
S3_SECRET_KEY = ""
S3_BUCKET = ""
S3_REGION = ""
# AI（可选）
AI_KEY = ""
AI_BASE_URL = ""
AI_MODEL = ""
# RAG（可选）
RAG_KEY = ""
RAG_BASE_URL = ""
RAG_MODEL = ""
```

## 初始化步骤

### 1. 配置后端

```bash
# 进入 spectra-admin 目录
cd spectra-admin

# 复制环境配置模板
copy .mise.local.toml.example .mise.local.toml

# 编辑 .mise.local.toml，填入实际的数据库/Redis/S3/AI 凭据
```

### 2. 配置前端

```bash
# spectra-ui（默认已配置，指向 localhost:4004）
cd spectra-ui
# .env 已存在，如需修改：
# VITE_API_URL=https://127.0.0.1:4004/

# spectra-app（默认已配置）
cd spectra-app
# .env.development 已存在：
# VITE_API_BASE_URL=https://127.0.0.1:4004
```

### 3. 启动数据库和 Redis

确保 PostgreSQL 和 Redis 服务已启动。

### 4. 启动后端 API

```powershell
Set-Location spectra-admin

# 先编译打包，再运行 spectra-launch 生成的可执行 JAR
.\mvnw.cmd clean package -DskipTests
$jar = Get-ChildItem .\spectra-launch\target\spectra-launch-*.jar -File |
    Where-Object { $_.Name -notlike '*.jar.original' } |
    Select-Object -First 1
java --add-modules ALL-SYSTEM --enable-native-access=ALL-UNNAMED `
    -Dspring.profiles.active=dev `
    -jar $jar.FullName
# API 运行在 https://127.0.0.1:4004/api
```

### 5. 启动前端

```bash
# Web 管理后台
cd spectra-ui
pnpm install
pnpm start           # → http://localhost:5173

# 移动端 H5
cd spectra-app
pnpm start           # → http://localhost:5173
```

`pnpm start` 已包含 type-check、lint 和 format。首次配置或依赖缺失时再执行 `pnpm install`，不要在每次启动前重复安装依赖。
