# 常见命令

> 日常开发中常用的命令速查。

## Windows / Codex 启动前约定

- 所有 Windows 项目命令统一使用 PowerShell 7.6 或更高版本；Windows PowerShell 5.1 的 `powershell.exe` 不受支持。
- 正常开发终端已通过 PowerShell 7 profile 激活 mise，不需要每次重复执行 `mise activate pwsh`。
- `pwsh` 应解析到 `C:\Program Files\PowerShell\7\pwsh.exe`；若 `Get-Command pwsh -All` 仍指向 `WindowsApps`，先修复 PowerShell 安装路径再启动项目。
- 根目录的 `agent-runtime.ps1`、`agent-context.ps1`、`check-docs.ps1` 均通过 `#requires -Version 7.6` 拒绝低版本执行。
- 第一次在根目录或 `spectra-admin/` 使用 mise 时，如果出现配置未信任提示，只执行一次 `mise trust`；不要复制 `.mise.local.toml` 中的密钥。
- `spectra-admin` 的后端端口为 `4004`，使用 HTTPS，API 上下文为 `/api`；`spectra-ui` 使用 5173，`spectra-app` H5 使用 5174。

Codex/CI 沙箱不应自动修改 mise 的信任状态；信任项目属于一次性的人工安全决策。Agent 执行后端任务时优先直接调用 Maven Wrapper，源码查询优先使用已安装的 Spectra 插件/CodeGraph MCP，避免仅为读取项目而重复触发 mise。

如果 Agent 沙箱中的 mise 未信任，或运行时被 WindowsApps shim 干扰，在仓库根目录点源一次项目回退脚本。它只修改当前 PowerShell 会话，直接选用项目固定的 Java 25.0.2、Node 24.14.0 与 pnpm 11.0.9，并暴露 Maven 仓库路径；不会修改 mise 信任状态：

```powershell
. .\scripts\agent-runtime.ps1

# 后端命令显式复用本机已有 Maven 缓存
Set-Location .\spectra-admin
.\mvnw.cmd "-Dmaven.repo.local=$env:SPECTRA_MAVEN_REPO" spotless:check
```

如果 Maven 报 `Could not create local repository at C:\.m2\repository`，显式指定本地仓库；正常用户终端不需要这一步：

```powershell
$mavenRepo = Join-Path $env:TEMP 'spectra-maven-repository'
.\mvnw.cmd "-Dmaven.repo.local=$mavenRepo" clean package -DskipTests
```

## spectra-admin（后端）

```powershell
# 从 spectra-admin/ 目录执行

# 编译打包（跳过测试）
.\mvnw.cmd clean package -DskipTests

# 启动已打包的 API JAR
$jar = Get-ChildItem .\spectra-launch\target\spectra-launch-*.jar -File |
    Where-Object { $_.Name -notlike '*.jar.original' } |
    Select-Object -First 1
java --add-modules ALL-SYSTEM --enable-native-access=ALL-UNNAMED `
    -Dspring.profiles.active=dev `
    -jar $jar.FullName

# 只编译，不打包
.\mvnw.cmd clean compile

# 运行测试
.\mvnw.cmd test

# 生产依赖安全门禁（CVSS >= 7 时失败）
# 首次同步 NVD 数据量较大，建议在本机或 CI 配置 NVD_API_KEY
.\mvnw.cmd -Psecurity-audit verify -DskipTests

# 渐进格式检查（默认只检查相对 origin/master 变更的 Java 文件）
.\mvnw.cmd spotless:check

# 格式化当前渐进范围
.\mvnw.cmd spotless:apply

# 全量格式检查；PowerShell 中系统属性必须加引号
.\mvnw.cmd spotless:check "-Dspotless.ratchetFrom=NONE"

# 只编译单个模块
.\mvnw.cmd clean compile -pl spectra-core -am
# -pl: 指定模块
# -am: also-make，同时编译依赖的模块

# Codex/CI 沙箱中 Java user.home 不可写时，显式指定 Maven 本地仓库
$mavenRepo = Join-Path $env:TEMP 'spectra-maven-repository'
.\mvnw.cmd "-Dmaven.repo.local=$mavenRepo" clean package -DskipTests
```

OWASP Dependency-Check 会在 `target/` 生成 HTML、JSON 和 SARIF 报告。CI 工作流会读取可选的 `NVD_API_KEY` Secret 并缓存漏洞数据库；本机首次无 Key 同步可能耗时很长，配置 Key 后可执行：

```powershell
.\mvnw.cmd -Psecurity-audit verify -DskipTests "-DnvdApiKey=$env:NVD_API_KEY"
```

后端启动成功的关键日志为 `Tomcat started on port 4004 (https)` 和 `Started LaunchApplication`。健康检查地址为：

```text
https://127.0.0.1:4004/api/actuator/health
```

本地证书未被系统信任时，浏览器或命令行可能提示证书问题；只要日志显示启动完成、4004 端口监听，并且 health 返回 `status: UP`，后端即可用。

## 停止本地开发进程

优先在启动服务的终端按 `Ctrl+C`。如果启动终端没有把信号传递给子进程，只停止明确占用开发端口的进程：

```powershell
$ports = @(4004, 5173, 5174)
$listeners = Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in $ports } |
    Select-Object LocalPort, OwningProcess

$listeners | Format-Table -AutoSize

# 确认只包含本次开发服务的 PID 后执行
$listeners.OwningProcess | Sort-Object -Unique | ForEach-Object {
    Stop-Process -Id $_ -Force
}
```

停止后用下面的命令确认 4004、5173 和 5174 没有 `LISTENING` 记录：

```powershell
netstat -ano | Select-String -Pattern ':4004|:5173|:5174'
```

## spectra-ui（Web 管理后台）

```bash
# 从 spectra-ui/ 目录执行

pnpm install         # 安装依赖
pnpm start           # 启动开发服务器（:5173），自动 format+lint+type-check
pnpm build           # 生产构建
pnpm preview         # 预览生产构建
pnpm lint            # ESLint 检查
pnpm type-check      # TypeScript 类型检查
pnpm format          # Prettier 格式化
pnpm format:check    # Prettier 只检查不改写
pnpm test            # Vitest 单次测试
```

## spectra-app（移动端）

```bash
# 从 spectra-app/ 目录执行

pnpm install         # 安装依赖
pnpm start           # H5 开发（http://localhost:5174），自动 type-check+lint+format
pnpm dev:mp-weixin   # 微信小程序开发
pnpm build:h5        # H5 构建（pnpm build 为同义入口）
pnpm build:mp-weixin # 微信小程序构建
pnpm format:check    # Prettier 只检查不改写
```

## AI Agent 快速入口

以下命令只读取项目事实，适合 Agent 在开始任务时快速定位，不需要重新猜测目录或工具版本：

```powershell
# mise 未信任或 Agent 沙箱运行时异常时，先在仓库根目录点源一次
. .\scripts\agent-runtime.ps1

# 输出模块、工具链、源码数量、活动计划和高频验证命令
.\scripts\agent-context.ps1

# 校验 Obsidian wikilink、Entity/Controller 数量和已完成计划残留
.\scripts\check-docs.ps1

# CodeGraph MCP 不可用时的本机 CLI 回退
& 'D:\Develop\Platform\codegraph\bin\codegraph.cmd' explore "要查询的符号或问题"
```

在 ChatGPT 桌面端的 **Local environments** 中，可把后端构建、Web 检查、App 检查和文档检查配置为 Actions；动作脚本直接使用本节已有命令，避免再维护第二套命令定义。

## VS Code 启动配置

四个子项目均提供 `.vscode/launch.json` 和 `.vscode/tasks.json`，需要在 VS Code 中分别打开对应的项目根目录：

| 项目 | 默认启动配置 | 说明 |
|---|---|---|
| `spectra-admin` | 终端执行“mise + Maven package + JAR” | 当前仓库没有 `spectra-admin/.vscode/launch.json`；后端按上面的先打包、再运行 JAR 流程启动，并由已激活的 mise 提供 JDK 与环境变量 |
| `spectra-ui` | `Web 管理后台 · Vite（mise）` | 执行 `mise.exe exec -- pnpm start` |
| `spectra-app` | `移动端 H5 · uni（mise）` | 执行 `mise.exe exec -- pnpm start` |
| `logicflow-plugin-flowable` | `流程建模插件 · tsup watch（mise）` | 执行 `mise.exe exec -- pnpm run dev`，监听并重新构建插件；另有 `流程建模示例 · Vite（mise）` 可启动 `examples/` 画布 |

按 `F5` 后可在运行配置下拉框中选择快速模式、微信小程序模式或插件构建模式。配置只调用 `mise.exe exec`，不会在 VS Code 文件中复制后端密钥；后端环境变量仍由本机的 `.mise.local.toml` 提供。

后端项目的 `.vscode/settings.json` 会把 mise 管理的 Temurin Java 25 注册给 VS Code Java 扩展，并将 Spring Boot Tools 的 `API_VERSIONING_NOT_CONFIGURED` 诊断设为 `IGNORE`（项目通过配置文件集中配置 API 版本）。如果更换机器导致 JDK 路径不同，可执行 `mise.exe which java`，取其上级 JDK 目录更新该设置，然后运行 `Java: Clean Java Language Server Workspace` 并重启窗口。

## Git 约定

```bash
# 提交格式（Conventional Commits）
# type(scope): 中文描述

# 示例
git commit -m "feat(core): 新增用户批量导入功能"
git commit -m "fix(security): 修复 Token 刷新异常"
git commit -m "refactor(upload): 重构分片上传逻辑"

# 常见 type
# feat     — 新功能
# fix      — 修复 Bug
# refactor — 重构
# docs     — 文档更新
# style    — 代码格式
# test     — 测试
# chore    — 构建/工具变更
```
