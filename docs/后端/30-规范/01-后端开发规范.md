# 后端开发规范

> 本页提供后端实现细则，统一架构、复杂度、协议与验证以 [[开发指南/04-工作区工程标准|工作区工程标准]] 为主。标准于 2026-10-03 确认，不代表存量源码和检查已经全部迁移；实际状态见 [[开发指南/05-集中治理与验收|集中治理与验收]]。

## 代码格式化与校验

- 后端 Java 代码统一使用 `spectra-admin/config/eclipse-java-formatter.xml` 中的 Eclipse JDT Formatter 配置。
- 缩进使用 4 个空格，不使用 Tab；右边距统一为 150 列。
- 使用 Spotless Maven Plugin，Windows 经 mise 执行 `.\mvnw.cmd spotless:apply` 整理格式，`spotless:check` 检查格式；检查与修复分开，完整 `verify` 在模块完成或代码交付时执行。
- 当前配置保留 `origin/master` ratchet 基线；集中治理采用全量检查 `-Dspotless.ratchetFrom=NONE`，不能以渐进检查结果代表全项目符合新标准。
- Spotless 使用 Eclipse JDT Formatter，不依赖本机 IntelliJ IDEA；IDEA 侧如需保持编辑器即时格式化，可导入同一份 Eclipse formatter XML。
- 项目编译基线为 JDK 25；可以使用 JDK 25 的稳定语言特性，但不得为了语法简短牺牲请求绑定、校验或领域语义。
- Java 源码中的类型声明、方法签名、泛型、构造调用和方法引用必须使用简单类名并通过 `import` 引入；只有两个同名类型确实发生导入冲突时，才允许其中一个使用全限定名。禁止写 `java.util.UUID id`、`java.util.List.of(...)` 这类无冲突全限定名。
- 业务状态、类型、渠道、动作等值域封闭且由本系统控制的字符串必须定义为枚举，并通过枚举值或 `name()` 持久化/传输；不得散落 `"SENT"`、`"FAILED"` 等魔法字符串。第三方协议中开放或供应商自定义的状态码可以保留 `String`，但必须在适配边界集中归一化为内部枚举。
- 开发节奏遵循“先实现、后整理”：功能或模块开发过程中不要求每次修改都执行完整 `mvn verify`，优先按需运行目标模块的 `compile` 或 `test` 获取快速反馈；模块完成或准备提交时，再统一执行格式整理和质量门禁。

## 1. 注释规范

- 使用传统 Javadoc 块注释（`/** ... */`），不使用 Java 23+ 的三斜杠 Markdown 文档注释
- 每个 Java 文件必须包含 Apache License 2.0 头部
- 类注释必须包含 `@author`、`@version`、`@since`
- `javabean/entity/` 下的实体类注释使用中文，说明实体代表的数据或关系；每个实体声明的实例字段都必须有中文 Javadoc，解释字段业务含义。继承字段在声明它们的基类中统一说明。
- Apache License 2.0 头部统一采用 `spectra-admin` 的 `entity-full.java` 示例格式，包括版权行及注释星号后的空格排版。
- 接口方法声明、Controller/配置/监听器等没有接口契约可复用的公开方法必须有方法级 Javadoc，并在需要时使用 `@param`、`@return`、`@throws` 说明参数、返回值和异常。
- 实现接口的类中，带 `@Override` 的实现方法直接复用接口契约，不重复编写相同 Javadoc；只有实现新增了接口未表达的重要语义时才补充差异说明。
- 私有辅助方法（包括工具类中的私有计算、校验、转换和组装方法）必须有简短 Javadoc，说明其职责和关键边界；私有构造器不要求重复注释。
- 文档内容统一使用传统 Javadoc/HTML 语法：标题使用 `<h3>`，列表使用 `<ul>/<li>`，代码和类型使用 `{@code ...}` 或 `<code>...</code>`，代码示例使用 `<pre>`。
- 类级元信息使用普通的 `@author`、`@version`、`@since` 标签；方法参数、返回值和异常使用标准的 `@param`、`@return`、`@throws` 标签。
- record 组件的说明统一写在类级 Javadoc 中，不在组件声明上单独添加注释；每个 `@param` 的组件名和说明保持在同一行，同一 record 内的说明按最长组件名对齐。

```java
/**
 * 目录项 Service 实现
 *
 * @author yangxj96
 * @version 1.0
 * @since 2026/7/17
 */
```

record 的类级注释示例：

```java
/**
 * 通知请求完成持久化和任务展开后的入队回执。
 *
 * @param requestId        通知模块内部的逻辑请求 ID
 * @param status           逻辑请求当前状态
 * @param taskCount        本次请求已展开的接收人×渠道任务数
 * @param idempotentReplay 是否因命中幂等键而返回已存在的请求结果
 * @author yangxj96
 * @version 1.0
 * @since 2026/8/11
 */
public record NotificationReceipt(UUID requestId, String status, int taskCount, boolean idempotentReplay) {
}
```

## 2. 包结构

### 简单模块（扁平结构）

适用于实体少、业务简单的模块（如 ai、upload、workflow）：

```
com.devops00.spectra.{module}
├── {Module}Module.java              # 模块入口（@ComponentScan + @MapperScan）
├── configuration/                    # 配置类
├── controller/                       # REST 端点
├── javabean/
│   ├── converter/                    # MapStruct 转换器
│   ├── entity/                       # 数据库实体
│   ├── domain/                       # 领域值对象和 Mapper 查询行模型
│   ├── enums/                        # 业务枚举
│   ├── constant/                     # 领域常量
│   ├── from/                         # 请求表单对象
│   └── vo/                           # 响应视图对象
├── mapper/                           # MyBatis-Plus Mapper
├── service/                          # 业务逻辑接口
│   └── impl/                         # Service 实现
└── properties/                       # 配置属性（可选）
```

扁平分层是基础结构，不代表所有组件都必须塞入 `service`。按真实职责增加下列同级包：

- `provider/`、`provider/impl/`：第三方能力 SPI 与具体 Provider。
- `sender/`、`sender/impl/`：发送策略及渠道发送器。
- `dispatch/`：Worker、调度器、任务领取与状态推进组件。
- `strategy/`、`policy/`、`validator/`、`observability/`：可替换策略、规则、校验器与指标/观测组件。
- `client/`、`adapter/`：外部系统客户端及边界适配。
- `support/`：依赖领域服务、权限上下文或流程端口的跨子域复用组件；应使用明确的领域名称，不能退化为静态工具类。
- `utils/`：无状态、无领域依赖、可复用的纯函数工具。

`service/` 只放应用服务接口及其实现，不放 Provider、Sender、Worker、Listener、Client 或纯工具类。复杂模块的每个子域同样遵循该职责分包规则。

### MyBatis Mapper 与 XML

- 仅对 MyBatis 持久化 Mapper 接口（位于 `mapper/`，使用 MyBatis `@Mapper` 或继承 MyBatis-Plus `BaseMapper`）执行本规则。每个 Mapper Java 必须有一个同名 XML，放在所属模块 `src/main/resources/mapper/<领域>/` 下；领域目录应与 Mapper 包中的领域路径对应，共享基础映射放在 `common/`。XML 的 `namespace` 必须是 Mapper 接口完整包名。
- SQL 统一写在对应 XML 的 `<select>`、`<insert>`、`<update>` 或 `<delete>` 中，参数使用 `#{...}` 绑定。Mapper 接口禁止使用 `@Select`、`@Insert`、`@Update`、`@Delete`、`@SelectKey` 及其 Provider 注解；仅继承 `BaseMapper`、没有自定义 SQL 的接口仍需提供仅含对应 `namespace` 的 XML。
- XML 的 `resultMap` 和 `Base_Column_List` 按 `UserMapper.xml` 的样式排版：映射标签分行、`column` 与 `property` 对齐，列清单每列一行并保持统一缩进。Entity 字段新增、删除或改名时，同步检查 `BaseResultMap` 与列清单；持久化字段必须有映射，删除的字段不得遗留旧映射。`@TableField(exist = false)` 字段只能放在确实需要它的专用结果映射中，不进入实体基础映射。
- 本规则不适用于 `javabean/converter/` 下的 MapStruct `@Mapper`，也不适用于 `TimeMapper` 等非 MyBatis Mapper。

### 复杂模块（子域拆分）

适用于实体多、业务复杂的模块（如 core、oa）：

```
com.devops00.spectra.{module}
├── {Module}Module.java
├── {subdomain}/                      # 子域（如 auth/、system/、user/）
│   ├── controller/
│   ├── javabean/
│   │   ├── converter/
│   │   ├── entity/
│   │   ├── domain/
│   │   ├── enums/
│   │   ├── constant/
│   │   ├── from/
│   │   └── vo/
│   ├── mapper/
│   └── service/
│       └── impl/
├── common/                           # 跨子域共享代码（可选）
└── configuration/                    # 模块级配置
```

技术基础类型按能力归属在 `spectra-framework` 中使用：持久化基类和分页入参分别位于
`framework.persistence.base`、`framework.persistence.pagination`，PostgreSQL/MyBatis Handler 位于
`framework.persistence.mybatis`；统一 HTTP 响应包装位于 `framework.web.response`。`spectra-common`
只保留跨模块契约、值对象和端口，不得因为业务模块复用方便而重新放入 ORM、Web 或数据库实现。

## 3. Controller 规范

### 基本规则

- 统一 `@RequiredArgsConstructor` + `private final` 构造器注入
- Controller 负责协议绑定、入口校验、身份与接口级授权及用例调用，不包含业务决策；Service 是最终业务授权边界
- 除路径参数（`@PathVariable`）外，请求参数统一使用 `From` 入参对象接收；禁止在 Controller 中直接使用 `String`、数值、布尔值、`Map` 或 `List` 接收查询参数/请求体。分页查询可组合使用 `framework.persistence.pagination.PageFrom` 与业务 `XxxPageFrom`。
- 禁止返回 `Object`，必须返回具体类型（`IPage<XxxVO>`、`XxxVO`、`List<XxxVO>`、`void`）
- 统一方法命名：`created`/`modify`/`deleteById`/`page`

### 注解使用

| 注解 | 规则 |
|---|---|
| `@Audit` | **所有需要记录审计的接口方法必须加**。GET 用简短描述，POST/PUT/DELETE 用详细描述；复杂动作直接调用 `AuditService` |
| `@PreAuthorize` | **所有接口必须加**。公开接口用 `permitAll()` 显式标注 |
| `@Validated` | **所有写操作必须加**。使用 `Verify.Insert.class` 或 `Verify.Update.class` 分组 |
| `@Slf4j` | 有日志职责时使用；记录必要且安全的上下文，不整包输出敏感入参 |
| `version` | Mapping 注解中统一 `version = "1.0.0"` |

### @Audit 描述格式

统一中文动宾短语：

| HTTP 方法 | 描述风格 | 示例 |
|---|---|---|
| GET | 简短 | `'查询记录列表'`、`'获取流程定义图'`、`'查询待办任务'` |
| POST | 详细 | `'创建记录'`、`'部署流程定义'`、`'启动流程'` |
| PUT | 详细 | `'更新记录'`、`'修改角色'` |
| DELETE | 详细 | `'删除记录'`、`'删除用户'` |

### @PreAuthorize 规则

- 所有接口必须加
- 公开接口用 `@PreAuthorize("permitAll()")` 显式标注
- 权限控制用 `@PreAuthorize("hasPermission(null, 'MODULE:ACTION')")`
- 角色控制用 `@PreAuthorize("hasRole('ROLE_xxx')")`

### @Slf4j 规则

- Controller 层必须加 `@Slf4j`
- 使用较低级别 `log.debug()` 记录请求入参
- Controller 层不直接写日志表（审计由 `@Audit`/`AuditService` 和统一 Core sink 负责）

### 典型模板

```java
@Slf4j
@RestController
@RequestMapping("/catalog/items")
@RequiredArgsConstructor
public class CatalogItemController {

    private final CatalogItemService catalogItemService;

    @Audit("'查询记录列表'")
    @GetMapping(value = "", version = "1.0.0")
    @PreAuthorize("isAuthenticated()")
    public IPage<CatalogItemVO> page(PageFrom page, CatalogItemPageFrom params) {
        return catalogItemService.page(page, params);
    }

    @Audit("'创建记录'")
    @PostMapping(value = "", version = "1.0.0")
    @PreAuthorize("hasPermission(null, 'catalog:item:create')")
    public void created(@Validated(Verify.Insert.class) @RequestBody CatalogItemSaveFrom from) {
        catalogItemService.created(from);
    }
}
```

## 4. Service 规范

### 接口

- 应用 Service 统一使用接口 + Impl。实体 CRUD 服务可继承 `framework.persistence.base.BaseService<Entity>`，不直接依赖 MyBatis-Plus 的 `IService`；编排或非实体用例使用明确操作并组合协作者，不机械继承通用 CRUD。
- CRUD 用例沿用 `created`/`modify`/`deleteById`/`page`，状态变化等使用有业务含义的专用操作；返回具体结果类型。
- Core 跨域只调用公开 Service 或必要 Facade 的业务操作，不调用对方 Mapper、Impl 或继承的通用 CRUD；跨模块使用公共契约，不能引用对方内部 Entity、Mapper 或实现。
- Worker、Policy、Adapter 等内部协作者按职责组织，不一律配置接口；新抽象说明必要性和验证依据。

```java
public interface CatalogItemService extends BaseService<CatalogItem> {
    IPage<CatalogItemVO> page(PageFrom page, CatalogItemPageFrom params);
    void created(CatalogItemSaveFrom from);
    void modify(UUID id, CatalogItemSaveFrom from);
    void deleteById(UUID id);
}
```

### 实现类

- 实现对应应用 Service 接口，实体 CRUD 实现可使用 `framework.persistence.base.BaseServiceImpl<Mapper, Entity>`；其他用例不绑定无关 Entity。
- 使用 `@Service`，默认构造器注入；有日志职责时使用 `@Slf4j`，记录关联标识、操作、结果和故障分类，避免重复日志及敏感字段。
- 应用 Service 确定需要原子提交的本地业务单元，必要处使用 `@Transactional`，同库跨域参与该事务；外部副作用按阶段、补偿或可靠任务处理。事务必要且短，不机械覆盖所有读写方法。
- 异常通过统一映射提供安全提示、真实 HTTP 状态和稳定领域 `error_code`；具体实现迁移在治理台账中记录。
- Converter 通过构造器注入，负责必要的结构映射；业务校验和数据库访问不塞入结构映射。

### 公共逻辑提取

- 两处及以上出现语义和实现都相同的内部方法时必须评估提取；三处及以上重复默认应提取，除非能说明它们会独立演进。
- 纯计算、格式化、基础摘要等无状态且不依赖领域端口的逻辑提取到按能力划分的 `common.foundation` 或 `common.security.crypto` `final` 工具类，使用私有构造器和静态方法；领域脱敏、协议摘要等带业务语义的逻辑留在所属 feature 的 `policy`/`security` 包。
- 需要 Mapper、Repository、配置、事务或领域规则的复用逻辑提取为命名清晰的 `@Component`/领域服务，禁止为了复用强行做成静态工具类。
- 优先复用已有公共能力（例如 `TimeMapper`、`SHA256Utils`），业务模块通过语义明确的 feature adapter 调用安全算法，不得在多个 Service 内再次包装同名的一行转发方法；也不得创建职责混杂的 `CommonUtils`、`BizUtils` 巨型工具类。

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class CatalogItemServiceImpl
        extends BaseServiceImpl<CatalogItemMapper, CatalogItem>
        implements CatalogItemService {

    private final CatalogItemConverter catalogItemConverter;

    @Override
    @Transactional
    public void created(CatalogItemSaveFrom from) {
        var entity = catalogItemConverter.toEntity(from);
        if (!this.save(entity)) {
            throw new DataSaveException("创建记录失败");
        }
        log.info("创建记录成功: id={}, name={}", entity.getId(), entity.getName());
    }
}
```

## 5. 异常处理

### 异常类型

统一使用项目自定义异常，**禁止裸 RuntimeException**：

| 异常类 | 说明 | 使用场景 |
|---|---|---|
| `DataNotExistException` | 数据不存在 | 查询/更新/删除时实体不存在 |
| `DataSaveException` | 数据保存失败 | insert/update 操作失败 |
| `EntityUpdateException` | 实体更新失败 | updateById 返回 false |
| `BuiltinDataException` | 内置数据不可操作 | 删除/修改系统内置数据 |
| `DefaultDataException` | 默认数据不可操作 | 删除默认角色/用户等 |

### 异常消息

- 统一中文（用户友好，前端可直接展示给用户）
- 示例：`"记录不存在"`、`"创建记录失败"`、`"内置角色,不可删除"`

### 异常使用原则

```java
// 正确：使用自定义异常
var entity = this.getById(id);
if (entity == null) {
    throw new DataNotExistException("记录不存在");
}

// 错误：禁止裸 RuntimeException
if (entity == null) {
    throw new RuntimeException("记录不存在");
}
```

## 6. 实体规范

- UUID 主键：`@TableId(type = IdType.INPUT)`，由全局 MyBatis-Plus `MetaObjectHandler` 在新增时自动生成 UUID v7
- 新增实体不得在 Service/Controller 中手工调用 `setId` 或 `UUID.randomUUID()` 设置数据库主键；只有更新已有记录时才允许回填已有业务 ID
- 审计字段：`createdBy`、`createdAt`、`updatedBy`、`updatedAt`（继承 `framework.persistence.base.BaseEntity`）
- 软删除：`Instant deleted`（null = 未删除）（继承 `framework.persistence.base.BaseEntity`）
- 乐观锁：`@Version`（继承 `framework.persistence.base.BaseEntity`）
- 默认排序：`@OrderBy` 设置
- 表名注解：`@TableName("xxx")`
- 字段注解：`@TableField("xxx")`

```java
@Getter
@Setter
@ToString
@TableName("catalog_item")
public class CatalogItem extends BaseEntity {

    @TableField("name")
    private String name;

    @TableField("code")
    private String code;
}
```

## 7. From 对象规范

- 统一后缀 `From`（**非 Form**）
- 包路径：`javabean/from/`
- 必填字段必须加 `@NotBlank`/`@NotNull` 等校验注解
- 使用 `@Data` 注解
- 提供清晰的中文 `message` 参数
- Controller 请求对象禁止声明为 `record`。请求绑定、Bean Validation、分组校验和后续字段演进统一使用普通 `class`；`record` 仅用于响应值、内部不可变命令/结果或无框架绑定要求的值对象。
- 现有 From 时间字段使用 ISO 8601 `String` 的约定继续作为具体绑定方式；按字段区分绝对时刻、日期和纯时间并严格校验。绝对时刻携带偏移或具有契约明确的时区上下文，不猜格式或补今天。

```java
@Data
public class CatalogItemSaveFrom {

    @NotBlank(message = "名称不能为空")
    private String name;

    @NotBlank(message = "编码不能为空")
    private String code;

    private String description;  // 可选字段不加校验注解
}
```

## 8. VO 对象规范

- 统一后缀 `VO`
- 包路径：`javabean/vo/`
- 使用 `@Data` 注解
- 分页查询返回 `IPage<XxxVO>`
- VO 的日期、纯时间保留对应语义；绝对时刻由后端按有效用户或显式系统默认时区转换，并输出明确偏移。可采用保留偏移的类型或经过验证的序列化契约，不能仅靠无偏移 LocalDateTime 表达绝对时刻。
- 简单不可变响应允许使用 `record`；需要 MapStruct、继承、分阶段组装或较多可选字段时使用普通 `class`。

## 9. Converter 规范（MapStruct）

### 结构映射

普通结构映射优先复用已有 MapStruct Converter；确需手写组装时明确职责并验证字段契约。不机械要求所有对象复制或所有转换都创建 Converter。业务规则、数据库访问和时区上下文的确定各有明确职责。

### 定义方式

```java
@Mapper(uses = TimeMapper.class, config = GlobalMapperConfig.class)
public interface CatalogItemConverter {

    /**
     * 实体转 VO
     */
    CatalogItemVO toVO(CatalogItem source);

    /**
     * From 转实体
     */
    CatalogItem toEntity(CatalogItemSaveFrom source);

    /**
     * 更新已有实体
     */
    void updateEntity(CatalogItemSaveFrom source, @MappingTarget CatalogItem target);
}
```

### 时间字段规范

- 按字段语义明确绝对时刻、日期和纯时间的 ISO 8601 契约；绝对时刻输入必须带偏移或具有契约声明的日期及时区上下文，不自动补今天，不依次尝试格式。
- 绝对时刻按 Instant/UTC 语义保存；日期与纯时间使用对应模型和数据库语义，不一律转换成 Instant。实际精度在数据库、Java 和 JSON 间保持一致。
- 绝对时刻响应由后端按有效用户时区转换并携带偏移；无用户或未设置时区采用显式系统默认时区，无效时区失败，不依赖操作系统默认值。
- TimeMapper 的现有宽松解析和无偏移输出不能作为目标行为；按主标准集中治理并验证所有直接、间接调用方，包括受影响的暂缓 OA/Workflow。
- 需要时间转换的 Converter 复用明确的边界能力，后台用户视角携带已经确定的时区上下文；业务规则使用可控时间源，夏令时歧义按契约验证。
- 实际 JSON、导出契约和生成类型一致；不能仅检查 Java 类型就认定时间协议正确。

### 包路径

统一放在 `javabean/converter/`

### 全局配置

引用 `GlobalMapperConfig.class` 和 `TimeMapper.class`，统一由 `spectra-framework` 提供。

## 11. 日志规范

### 日志级别使用

| 级别 | Controller 层 | Service 层 |
|---|---|---|
| `log.debug()` | 记录请求入参 | 查询条件、参数详情 |
| `log.info()` | — | 关键业务节点（创建成功、部署成功等） |
| `log.warn()` | — | 业务校验失败、降级处理 |
| `log.error()` | — | 异常捕获、系统错误 |

### 日志消息格式

- 使用中文
- 关键节点必须记录实体 ID
- 示例：`log.info("创建记录成功: id={}, name={}", entity.getId(), entity.getName())`

- SecurityConfig 中配置白名单作为兜底

## 14. Maven 代码质量门禁

后端质量检查统一由 Maven 本地执行，不依赖 IDE、Docker 或 Sonar 服务：

| 工具 | 职责 | 生命周期 |
|---|---|---|
| Spotless | Java 格式、缩进、换行和 import 自动修复/校验 | `verify` |
| Checkstyle | 命名、import 合法性和基础编码约定 | `verify` |
| PMD | 源码坏味道、复杂度、异常处理和高价值最佳实践 | `verify` |
| SpotBugs + FindSecBugs | 编译字节码 Bug 与 Java Web 安全风险 | `verify` |

依赖边界需要按主标准评审及验证。本页不将尚未确认接入的 ArchUnit 当作已运行门禁；自动化架构检查的选择及接入状态在治理台账中记录。

执行时机约定：

- 功能开发中：不强制执行完整 `verify`，按需运行目标模块的 `compile` 或 `test`。
- 模块完成后：完成必要的格式整理，再独立运行检查，验证当前模块、依赖及实际影响范围。
- 代码交付前：执行适用的完整门禁；集中治理使用全量格式范围。只修改文档且不涉及 Java/Maven 时核对内容和链接，不执行无关构建。

```powershell
# 在 spectra-admin 执行；按实际 reactor 项目选择模块
mise exec -- .\mvnw.cmd verify -pl spectra-core -am

# 完整检查，独立于源码自动修复
mise exec -- .\mvnw.cmd verify '-Dspotless.ratchetFrom=NONE'
```

检查失败时定位并处理根因后重跑，不通过 skip、整域排除、关闭门禁或无理由 suppression 规避。普通业务评审触发值为圈复杂度超过 15、Java NPath 超过 200、嵌套超过 3、参数超过 5；超标按职责调整或登记有效定点例外，生成及特殊代码按主标准处理。

当前 PMD 方法 30、类 200、NPath 10000 等旧配置不能作为目标达标依据；工具边界校准、结构化例外自动核对和存量全量统一尚待实施。不是逐步沿用旧阈值放行。完整验收还包括行为风险、实际协议、真实依赖、故障恢复和多实例验证。
