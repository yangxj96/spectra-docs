# 后端 `spectra` 配置说明

本文说明后端 `spectra:` 配置树中每个配置项的含义、默认值和生效方式。配置分为三类：

- Spring Boot 启动配置文件中的配置，例如 `application-dev.yml` 和 `application-prod.yml`。
- 通过 `@ConfigurationProperties` 绑定到后端配置类的运行参数。
- 通过 `@ConditionalOnProperty` 或配置类直接读取的模块开关。

`spectra:` 配置不等同于数据库表 `spectra_core.sys_config`，也不等同于前端的 `VITE_*` 配置。通知模块有少量属性会在运行时读取 `sys_config`，本文会单独标明这类覆盖关系。

本文中的 `${NAME:default}` 表示优先读取环境变量 `NAME`，环境变量没有值时使用 `default`；`${NAME}` 没有默认值，必须由运行环境提供。示例只保留环境变量名和安全占位符，不记录密码、Token、私钥、证书或本机凭据。

## 配置树示例

下面的内容对应后端配置模板中的 `spectra:` 树。没有在模板中显式写出的绑定属性使用配置类默认值。

~~~yaml
spectra:
  security:
    secret:
      master-key: ${SPECTRA_SECURITY_SECRET_MASTER_KEY:}
    verification-code-max-attempts: ${SECURITY_VERIFICATION_CODE_MAX_ATTEMPTS:5}
    refresh-cookie-name: ${SPECTRA_SECURITY_REFRESH_COOKIE_NAME:__Host-spectra-refresh}
    refresh-cookie-secure: ${SPECTRA_SECURITY_REFRESH_COOKIE_SECURE:true}
    allow-insecure-refresh-cookie: ${SPECTRA_SECURITY_ALLOW_INSECURE_REFRESH_COOKIE:false}
    refresh-cookie-same-site: ${SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE:Strict}
    refresh-cookie-same-site-none-allowed: ${SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE_NONE_ALLOWED:false}
    refresh-cookie-path: ${SPECTRA_SECURITY_REFRESH_COOKIE_PATH:/}
    refresh-cookie-domain: ${SPECTRA_SECURITY_REFRESH_COOKIE_DOMAIN:}
    csrf-cookie-name: ${SPECTRA_SECURITY_CSRF_COOKIE_NAME:XSRF-TOKEN}
    csrf-header-name: ${SPECTRA_SECURITY_CSRF_HEADER_NAME:X-XSRF-TOKEN}
    crypto-request-max-body-bytes: ${SPECTRA_SECURITY_CRYPTO_REQUEST_MAX_BODY_BYTES:1048576}
    crypto-replay-window-seconds: ${SPECTRA_SECURITY_CRYPTO_REPLAY_WINDOW_SECONDS:300}
    redis:
      namespace: "sec:"
      fail-closed: true
      worker-batch-size: ${SPECTRA_SECURITY_REDIS_WORKER_BATCH_SIZE:100}
  system:
    base-dir: files
    cors:
      required: ${SPECTRA_CORS_REQUIRED:false}
      origin-patterns: ${SPECTRA_CORS_ORIGIN_ALLOWLIST:https://localhost:5173,https://127.0.0.1:5173,https://localhost:5174,https://127.0.0.1:5174}
  kaptcha:
    type: math
    verify: false
  file:
    upload:
      local:
        storage-root: ${spectra.system.base-dir}/uploads
        staging-root: ${spectra.system.base-dir}/temp
      s3:
        endpoint: ${S3_ENDPOINT}
        accessKey: ${S3_ACCESS_KEY}
        secretKey: ${S3_SECRET_KEY}
        bucket: ${S3_BUCKET}
        region: ${S3_REGION}
      default-storage: s3
      chunk-size: 8388608
      min-chunk-size: 5242880
      max-chunk-size: 67108864
      max-parts: 10000
      parallelism: 3
      task-ttl: 24h
      idle-timeout: 2h
      record-retention: 7d
      orphan-retention: 7d
      presign-ttl: 15m
  notification:
    enabled: true
    allowed-link-prefixes: /login,/security/authentication/,/oa/,/workflow/,/notification/,/notification-center/,/system/,/file/
    worker:
      fixed-delay-ms: 5000
      processing-timeout-seconds: 300
      retry-base-delay-seconds: 5
    cleanup:
      enabled: true
      fixed-delay-ms: 3600000
      batch-size: 100
      retention-seconds: 86400
  scheduler:
    quartz:
      enabled: true
      table-prefix: spectra_quartz.QRTZ_
      clustered: true
      jdbc-store: true
      job-store-class: org.springframework.scheduling.quartz.LocalDataSourceJobStore
      thread-count: 10
      history-retention-days: 90
      history-cleanup-batch-size: 500
      history-running-timeout: 24h
      database-retry-interval: 10s
~~~

## spectra.security

安全配置的前缀是 `spectra.security`。Token、Session、验证码、防重放和登录失败锁定使用安全 Redis 作为事实源；安全 Redis 连接或命令失败时，相关安全操作保持拒绝状态。

### 根密钥

#### `spectra.security.secret.master-key`

- 类型：Base64 字符串。
- 默认值：空字符串；配置模板通过 `SPECTRA_SECURITY_SECRET_MASTER_KEY` 注入。
- 作用：作为数据库 Secret 值加密器的 AES-256-GCM 部署根密钥，保护安全配置中保存的密钥明文。
- 约束：Base64 解码结果必须正好 32 字节。空值、非法 Base64 或长度不正确时不能执行密钥加解密。
- 安全要求：只通过环境变量或 Secret 管理系统提供，运行日志、工单、截图和网站文档不得出现实际值。

### 认证、会话和白名单

#### `spectra.security.whitelists`

- 类型：字符串列表。
- 代码默认值：`/common/kaptcha`、`/security/authentication/login`、`/system/initialization/status`、`/system/initialization/start`、`/system/initialization/complete`、`/security/authentication/refresh`、`/security/authentication/sms`、`/security/authentication/email`、`/actuator/health`、`/actuator/info`、`/system/crypto/config`、`/system/bootstrap`、`/notification/provider/callback/**`。
- 作用：声明无需登录即可进入安全过滤链的窄路径。
- 约束：列表不能为空，最多 64 项；每项必须以 `/` 开头且不超过 200 个字符；不能使用单独的 `/**` 放行全部请求。
- 说明：回调路径的 `/**` 只匹配该回调路径前缀，不等同于根路径的全量放行。

#### `spectra.security.access-token-expire`

- 类型：整数，单位为秒。
- 代码默认值：`300`，即 5 分钟。
- 作用：设置 Access Token 的有效期。
- 约束：取值范围为 `1` 至 `31536000` 秒。

#### `spectra.security.refresh-token-expire`

- 类型：整数，单位为秒。
- 代码默认值：`604800`，即 7 天。
- 作用：设置 Refresh Token 的有效期。
- 约束：取值范围为 `1` 至 `31536000` 秒。Refresh Token 通过 Cookie 传递时，还同时受 Cookie 属性约束。

#### `spectra.security.sec-mode`

- 类型：`SecMode` 枚举。
- 代码默认值：`REDIS`。
- 作用：选择安全会话适配模式。
- 约束：`REDIS` 是当前安全会话运行模式，安全状态不通过本地内存缓存替代。

#### `spectra.security.lockout-max-attempts`

- 类型：整数。
- 代码默认值：`5`。
- 作用：设置登录失败锁定计数达到锁定前允许的最大失败次数。
- 约束：取值范围为 `1` 至 `100`。

#### `spectra.security.lockout-seconds`

- 类型：整数，单位为秒。
- 代码默认值：`300`。
- 作用：设置达到失败次数后账户或登录主体的锁定时间。
- 约束：取值范围为 `0` 至 `86400` 秒；`0` 表示不设置锁定时长。

#### `spectra.security.min-effective-dev-ops-users`

- 类型：整数。
- 代码默认值：`1`。
- 作用：设置系统中必须保留的有效 DevOps Root 用户数量下限。
- 约束：取值范围为 `1` 至 `100`，用于保护最后一个有效 Root 用户不被移除或失效。

#### `spectra.security.max-dev-ops-users`

- 类型：整数。
- 代码默认值：`3`。
- 作用：设置 DevOps Root 用户数量上限。
- 约束：取值范围为 `1` 至 `100`，并且不能小于 `min-effective-dev-ops-users`。

#### `spectra.security.session-concurrency-mode`

- 类型：`SessionConcurrencyMode` 枚举。
- 代码默认值：`ALLOW`。
- 作用：设置同一用户的并发会话处理策略。
- 说明：会话策略还可以由 `session_policy` 数据配置覆盖；该配置项本身定义应用默认策略。

#### `spectra.security.max-sessions`

- 类型：整数。
- 代码默认值：`5`。
- 作用：设置单个用户允许保留的最大活动会话数。
- 约束：取值范围为 `1` 至 `100`。

### 验证码限制

#### `spectra.security.verification-code-expire`

- 类型：整数，单位为秒。
- 代码默认值：`300`。
- 作用：设置短信、邮件等验证代码的有效期。
- 约束：取值范围为 `1` 至 `86400` 秒；验证码状态存放在安全 Redis 中。

#### `spectra.security.verification-code-max-attempts`

- 类型：整数。
- 默认值：通过 `SECURITY_VERIFICATION_CODE_MAX_ATTEMPTS` 注入，模板默认 `5`，配置类默认也是 `5`。
- 作用：设置同一个验证码窗口允许的最大校验次数。
- 约束：取值范围为 `1` 至 `100`；达到次数上限后，后续校验被拒绝。

#### `spectra.security.verification-code-length`

- 类型：整数。
- 代码默认值：`6`。
- 作用：设置验证码长度。
- 约束：当前实现只接受 `6`，启动校验会拒绝其他长度。

### Refresh Cookie 和 CSRF

#### `spectra.security.refresh-cookie-name`

- 类型：字符串。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_NAME` 注入，默认 `__Host-spectra-refresh`。
- 作用：设置保存 Refresh Token 的 Cookie 名称。
- 约束：默认名称使用 `__Host-` 前缀；使用该前缀时 Domain 必须为空，Path 必须为 `/`。

#### `spectra.security.refresh-cookie-secure`

- 类型：布尔值。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_SECURE` 注入，默认 `true`。
- 作用：控制 Refresh Cookie 是否只通过 HTTPS 发送。
- 说明：开发和生产模板均以 HTTPS 与 `Secure` Cookie 为默认边界。

#### `spectra.security.allow-insecure-refresh-cookie`

- 类型：布尔值。
- 默认值：通过 `SPECTRA_SECURITY_ALLOW_INSECURE_REFRESH_COOKIE` 注入，默认 `false`。
- 作用：明确允许隔离的 HTTP 开发环境使用非 Secure Refresh Cookie。
- 约束：生产配置保持关闭；开启时不能使用 `__Host-` Cookie 名称。

#### `spectra.security.refresh-cookie-same-site`

- 类型：字符串，取值对应 Cookie SameSite 属性。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE` 注入，默认 `Strict`。
- 作用：控制浏览器在跨站请求中是否发送 Refresh Cookie。
- 说明：`None` 只适用于明确的跨站部署，并且必须同时使用 Secure Cookie、精确 CORS Origin 和 CSRF 校验。

#### `spectra.security.refresh-cookie-same-site-none-allowed`

- 类型：布尔值。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_SAME_SITE_NONE_ALLOWED` 注入，默认 `false`。
- 作用：控制是否允许 `SameSite=None`。
- 约束：默认拒绝；开启后仍需满足 HTTPS、精确 Origin 和 CSRF 防护条件。

#### `spectra.security.refresh-cookie-path`

- 类型：字符串。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_PATH` 注入，默认 `/`。
- 作用：设置 Refresh Cookie 的 Path。
- 约束：使用 `__Host-` Cookie 名称时必须是 `/`。

#### `spectra.security.refresh-cookie-domain`

- 类型：字符串。
- 默认值：通过 `SPECTRA_SECURITY_REFRESH_COOKIE_DOMAIN` 注入，默认空值。
- 作用：设置 Refresh Cookie 的 Domain；空值表示 Host-only Cookie。
- 约束：使用 `__Host-` Cookie 名称时必须为空。

#### `spectra.security.csrf-cookie-name`

- 类型：字符串。
- 默认值：通过 `SPECTRA_SECURITY_CSRF_COOKIE_NAME` 注入，默认 `XSRF-TOKEN`。
- 作用：设置双提交 CSRF Cookie 的名称。
- 约束：不能与 CSRF Header 名称相同。

#### `spectra.security.csrf-header-name`

- 类型：字符串。
- 默认值：通过 `SPECTRA_SECURITY_CSRF_HEADER_NAME` 注入，默认 `X-XSRF-TOKEN`。
- 作用：设置客户端回传 CSRF 值时使用的请求头名称。
- 约束：不能与 CSRF Cookie 名称相同。

### 请求加密和防重放

#### `spectra.security.crypto-request-max-body-bytes`

- 类型：整数，单位为字节。
- 默认值：通过 `SPECTRA_SECURITY_CRYPTO_REQUEST_MAX_BODY_BYTES` 注入，默认 `1048576`，即 1 MiB。
- 作用：限制进入 JSON 解析和请求解密流程的请求体大小。
- 约束：取值范围为 `1024` 至 `10485760` 字节；超过限制的请求被拒绝。

#### `spectra.security.crypto-replay-window-seconds`

- 类型：整数，单位为秒。
- 默认值：通过 `SPECTRA_SECURITY_CRYPTO_REPLAY_WINDOW_SECONDS` 注入，默认 `300`。
- 作用：限制加密请求中的时间戳和 nonce 的有效时间窗口。
- 约束：取值范围为 `1` 至 `3600` 秒；nonce 的消费状态使用安全 Redis 保存。

### 安全 Redis

#### `spectra.security.redis.namespace`

- 类型：字符串。
- 固定值：`sec:`。
- 作用：作为安全 Redis Key 的固定前缀，区分 Token、Session、验证码、防重放和登录失败锁定数据。
- 约束：启动校验要求保持为 `sec:`，不能改为普通缓存命名空间。

#### `spectra.security.redis.fail-closed`

- 类型：布尔值。
- 固定值：`true`。
- 作用：定义安全 Redis 不可用时的处理方式。
- 约束：启动校验要求保持为 `true`；连接失败、命令失败或无法确认状态时，相关安全操作必须拒绝。

#### `spectra.security.redis.worker-batch-size`

- 类型：整数。
- 默认值：通过 `SPECTRA_SECURITY_REDIS_WORKER_BATCH_SIZE` 注入，默认 `100`。
- 作用：限制使用安全 Redis 的可靠 Worker 单批处理数量。
- 约束：取值范围为 `1` 至 `1000`；只限制批量大小，不改变安全 Redis 的事实源语义。

## spectra.system

系统配置的前缀是 `spectra.system`，由 Web 层和文件目录管理使用。

### 基础运行参数

#### `spectra.system.base-dir`

- 类型：路径字符串。
- 代码和模板默认值：`files`。
- 作用：定义后端运行目录下的文件基础目录。本地上传目录和临时目录可以引用该值派生。
- 生效方式：应用启动时绑定；本地文件 Provider 会将派生目录转换为绝对规范路径并创建目录。

#### `spectra.system.package-prefix`

- 类型：字符串。
- 代码默认值：`com.devops00.spectra`。
- 作用：提供给仍需要生成或匹配完整 Java 类名的技术场景使用。
- 约束：该值不会修改源码实际包名，也不会替换代码中固定写入的类名。

### MVC 参数

#### `spectra.system.mvc.api-header`

- 类型：字符串。
- 代码默认值：`Api-Version`。
- 作用：指定客户端传递 API 版本的请求头名称。

#### `spectra.system.mvc.api-version`

- 类型：字符串。
- 代码默认值：`1.0.0`。
- 作用：客户端没有传递 API 版本请求头时使用的默认 API 契约版本。

### CORS 参数

#### `spectra.system.cors.mapping`

- 类型：字符串。
- 代码默认值：`/**`。
- 作用：指定 CORS 规则应用到的请求路径模式。

#### `spectra.system.cors.origin-patterns`

- 类型：字符串列表；配置模板使用逗号分隔的环境变量值。
- 代码默认值：空列表。
- 开发模板默认值：`https://localhost:5173`、`https://127.0.0.1:5173`、`https://localhost:5174`、`https://127.0.0.1:5174`。
- 生产模板默认值：空值，由 `SPECTRA_CORS_ORIGIN_ALLOWLIST` 提供实际 HTTPS Origin。
- 作用：定义允许访问后端的浏览器 Origin。
- 约束：应用配置使用精确 Origin，不使用 `*`；跨域携带 Cookie 时，Origin 必须和 Cookie、CSRF 策略共同匹配。

#### `spectra.system.cors.required`

- 类型：布尔值。
- 代码默认值：`false`。
- 开发模板值：通过 `SPECTRA_CORS_REQUIRED` 注入，默认 `false`。
- 生产模板值：通过同名环境变量注入，默认 `true`。
- 作用：定义是否要求部署提供至少一个 CORS Origin allowlist。
- 说明：生产配置的默认值要求显式提供实际允许来源；纯同源服务可以使用关闭状态。

#### `spectra.system.cors.methods`

- 类型：字符串列表。
- 代码默认值：`GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`OPTIONS`。
- 作用：定义预检请求允许声明的 HTTP 方法。

#### `spectra.system.cors.headers`

- 类型：字符串列表。
- 代码默认值：`Accept`、`Authorization`、`Content-Type`、`Api-Version`、`X-Client-Type`、`X-CSRF-Token`、`X-XSRF-TOKEN`、`X-Requested-With`、`X-Spectra-Initialization-Token`。
- 作用：定义跨源请求允许携带的请求头。

#### `spectra.system.cors.credentials`

- 类型：布尔值。
- 代码默认值：`true`。
- 作用：控制跨源请求是否允许携带 Cookie 或其他凭证。
- 约束：开启时不能使用通配 Origin，必须使用明确的 allowlist。

#### `spectra.system.cors.max-age`

- 类型：整数，单位为秒。
- 代码默认值：`3600`。
- 作用：设置浏览器缓存 CORS 预检结果的时间。

## spectra.kaptcha

验证码配置的前缀是 `spectra.kaptcha`。

#### `spectra.kaptcha.type`

- 类型：`KaptchaType` 枚举。
- 代码和模板默认值：`math`，对应 `MATH`。
- 作用：选择图形验证码生成类型。

#### `spectra.kaptcha.verify`

- 类型：布尔值。
- 代码默认值：`true`。
- 开发模板值：`false`。
- 生产模板值：`true`。
- 作用：控制认证流程是否执行图形验证码校验。
- 说明：该开关只控制图形验证码校验；验证代码的有效期和最大校验次数仍由 `spectra.security.verification-code-expire`、`spectra.security.verification-code-max-attempts` 和 `spectra.security.verification-code-length` 控制。

#### `spectra.kaptcha.duration`

- 类型：Spring `Duration`。
- 代码默认值：`1m`。
- 作用：设置图形验证码在缓存中的保存时长。

## spectra.file.upload

文件上传配置的前缀是 `spectra.file.upload`。上传会话、分片元数据和文件资产使用数据库记录；文件内容由本地 Provider 或 S3 Provider 保存。

### 上传通用参数

#### `spectra.file.upload.default-storage`

- 类型：`StorageProviderType` 枚举。
- 配置类默认值：`LOCAL`。
- 开发和生产模板值：`s3`。
- 作用：选择默认的文件存储 Provider。
- 说明：模板显式设置为 `s3` 时，默认上传路径使用 S3；只有使用本地 Provider 的上传路径才会写入本地目录。S3 Provider 没有完整配置时不会静默切换到本地 Provider。

#### `spectra.file.upload.max-file-size`

- 类型：整数，单位为字节。
- 代码默认值：`1073741824`，即 1 GiB。
- 作用：限制单个上传会话声明的文件大小。
- 说明：应用模板中的 `spring.servlet.multipart.max-file-size` 和 `max-request-size` 也设置为 `1GB`，它们是 HTTP multipart 层限制；本属性是上传会话服务层限制。

#### `spectra.file.upload.chunk-size`

- 类型：整数，单位为字节。
- 代码默认值：`8388608`，即 8 MiB。
- 模板值：`8388608`。
- 作用：计算上传会话的默认分片大小和总分片数。
- 约束：必须处于 `min-chunk-size` 和 `max-chunk-size` 之间；配置值是字节数，不是 `DataSize` 字符串。

#### `spectra.file.upload.min-chunk-size`

- 类型：整数，单位为字节。
- 代码默认值：`5242880`，即 5 MiB。
- 模板值：`5242880`。
- 作用：定义允许的最小分片大小边界。

#### `spectra.file.upload.max-chunk-size`

- 类型：整数，单位为字节。
- 代码默认值：`67108864`，即 64 MiB。
- 模板值：`67108864`。
- 作用：定义允许的最大分片大小边界。

#### `spectra.file.upload.max-parts`

- 类型：整数。
- 代码默认值：`10000`。
- 模板值：`10000`。
- 作用：限制单个上传会话的最大分片数。
- 说明：创建上传会话时根据文件大小和 `chunk-size` 计算总分片数，超过该值会被拒绝。

#### `spectra.file.upload.parallelism`

- 类型：整数。
- 代码默认值：`3`。
- 模板值：`3`。
- 作用：设置文件上传任务执行器的核心线程数和最大线程数；其队列容量为该值的两倍。
- 约束：上传服务校验该值必须大于 `0`。

#### `spectra.file.upload.max-concurrent-tasks-per-user`

- 类型：整数。
- 代码默认值：`3`。
- 作用：限制同一用户同时处于活动状态的上传会话数量。
- 说明：创建上传会话前会查询该用户的活动会话数，达到上限时返回上传并发限制错误。

### 上传会话生命周期

#### `spectra.file.upload.task-ttl`

- 类型：Spring `Duration`。
- 代码默认值：`24h`。
- 模板值：`24h`。
- 作用：设置上传任务的过期时间。创建会话时写入 `expires_at`，超过有效期的会话不能继续上传。

#### `spectra.file.upload.idle-timeout`

- 类型：Spring `Duration`。
- 代码默认值：`2h`。
- 模板值：`2h`。
- 作用：定义上传会话无活动的时间窗口。上传清理服务使用该值识别空闲会话。

#### `spectra.file.upload.record-retention`

- 类型：Spring `Duration`。
- 代码默认值：`7d`。
- 模板值：`7d`。
- 作用：设置取消、过期、失败等上传记录在数据库中的保留时间，也用于失败校验记录的清理时间。

#### `spectra.file.upload.orphan-retention`

- 类型：Spring `Duration`。
- 代码默认值：`7d`。
- 模板值：`7d`。
- 作用：设置没有有效业务引用的文件资产或对象进入孤儿清理判断前的保留时间。

#### `spectra.file.upload.presign-ttl`

- 类型：Spring `Duration`。
- 代码默认值：`15m`。
- 模板值：`15m`。
- 作用：设置 S3 分片直传预签名 URL 的有效期。
- 说明：URL 过期后不能继续用于对应的预签名操作。

### 本地存储

#### `spectra.file.upload.local.storage-root`

- 类型：路径字符串。
- 代码默认值：`uploads`。
- 模板值：`${spectra.system.base-dir}/uploads`。
- 作用：设置本地 Provider 的文件存储根目录。
- 说明：本地 Provider 启动时会将路径转换为绝对规范路径，并确保目录存在。

#### `spectra.file.upload.local.staging-root`

- 类型：路径字符串。
- 代码默认值：`temp`。
- 模板值：`${spectra.system.base-dir}/temp`。
- 作用：设置本地 Provider 的分片和临时文件目录。

## spectra.notification

通知配置的前缀是 `spectra.notification`。通知模块包含通知请求、Outbox 任务、渠道发送、站内信和清理 Job。

### 模块和链接

#### `spectra.notification.enabled`

- 类型：布尔值。
- 代码默认值和模板值：`true`。
- 作用：控制统一通知模块是否启用。
- 运行时覆盖：`spectra_core.sys_config` 中的 `notification.enabled` 存在时，`NotificationModuleProperties` 的 `enabled()` 使用该值覆盖绑定值。

#### `spectra.notification.allowed-link-prefixes`

- 类型：逗号分隔的站内路径列表。
- 代码默认值和模板值：`/login`、`/security/authentication/`、`/oa/`、`/workflow/`、`/notification/`、`/notification-center/`、`/system/`、`/file/`。
- 作用：限制通知消息中可写入的前端站内跳转链接前缀。
- 处理规则：运行时会去除空白、忽略非 `/` 开头的项并去重；结果为空时使用代码默认列表。
- 运行时覆盖：`spectra_core.sys_config` 中的 `notification.allowed-link-prefixes` 存在时，使用逗号分隔值覆盖绑定列表。

### 通知 Worker

#### `spectra.notification.worker.fixed-delay-ms`

- 类型：整数，单位为毫秒。
- 默认值：`5000`。
- 配置来源：通知配置模板写入该值。
- 当前运行事实：通知任务由统一 Quartz Job `notification.task-dispatch` 触发，Worker 本身没有使用该字段注册独立的 `@Scheduled` 方法；该字段目前是配置绑定项。

#### `spectra.notification.worker.processing-timeout-seconds`

- 类型：整数，单位为秒。
- 默认值：`300`。
- 作用：定义通知任务处于 `PROCESSING` 状态时的租约超时时间。Worker 恢复超过该时间仍未完成的任务。

#### `spectra.notification.worker.retry-base-delay-seconds`

- 类型：整数，单位为秒。
- 默认值：`5`。
- 作用：定义通知发送失败后指数退避的基础延迟。
- 说明：Worker 对可重试结果按任务状态处理，不是所有异常结果都会无条件重试。

### 通知清理

#### `spectra.notification.cleanup.enabled`

- 类型：布尔值。
- 代码默认值和模板值：`true`。
- 作用：控制通知敏感载荷清理 Job 是否启用。
- 运行时覆盖：`spectra_core.sys_config` 中的 `notification.cleanup.enabled` 存在时，使用该值覆盖绑定值。

#### `spectra.notification.cleanup.fixed-delay-ms`

- 类型：整数，单位为毫秒。
- 代码默认值和模板值：`3600000`，即 1 小时。
- 作用：提供通知清理周期配置。
- 处理规则：读取值小于等于 `0` 时归一化为 `3600000`。

#### `spectra.notification.cleanup.batch-size`

- 类型：整数。
- 代码默认值和模板值：`100`。
- 作用：限制单轮通知清理处理的最大请求或任务数量。
- 处理规则：读取值小于等于 `0` 时使用 `100`；大于 `1000` 时按 `1000` 处理。

#### `spectra.notification.cleanup.retention-seconds`

- 类型：整数，单位为秒。
- 代码默认值和模板值：`86400`，即 24 小时。
- 作用：定义终态通知记录中敏感载荷的保留时间。
- 处理规则：读取值小于等于 `0` 时归一化为 `86400`。

## spectra.scheduler.quartz

Quartz 配置的前缀是 `spectra.scheduler.quartz`。应用使用 PostgreSQL JDBC JobStore 和独立的 `spectra_quartz` schema 保存 Quartz 表、触发器和集群状态。

#### `spectra.scheduler.quartz.enabled`

- 类型：布尔值。
- 代码和模板默认值：`true`。
- 作用：控制 Quartz 生命周期管理是否启用。
- 说明：启用 Quartz 不代表可以绕过数据库启动门禁；数据库不可用时调度器保持未就绪。

#### `spectra.scheduler.quartz.table-prefix`

- 类型：字符串。
- 代码和模板默认值：`spectra_quartz.QRTZ_`。
- 作用：设置 Quartz 表使用的 schema 和表名前缀。
- 约束：启动校验要求以前缀 `spectra_quartz.QRTZ_` 开头，确保 Quartz 表位于独立 schema。

#### `spectra.scheduler.quartz.clustered`

- 类型：布尔值。
- 固定值：`true`。
- 作用：启用多实例 Quartz 集群协调。
- 约束：启动校验禁止关闭。

#### `spectra.scheduler.quartz.jdbc-store`

- 类型：布尔值。
- 固定值：`true`。
- 作用：启用持久化 JDBC JobStore。
- 约束：启动校验禁止关闭，不能使用 RAMJobStore 保存任务状态。

#### `spectra.scheduler.quartz.job-store-class`

- 类型：Java 类名字符串。
- 代码和模板默认值：`org.springframework.scheduling.quartz.LocalDataSourceJobStore`。
- 作用：指定 Quartz JobStore 实现类。
- 约束：不能为空，不能包含 `RAMJobStore`；实现类必须和应用 DataSource、事务以及 Quartz schema 匹配。

#### `spectra.scheduler.quartz.thread-count`

- 类型：整数。
- 代码和模板默认值：`10`。
- 作用：设置 Quartz 工作线程数。
- 约束：必须大于 `0`。

#### `spectra.scheduler.quartz.history-retention-days`

- 类型：整数，单位为天。
- 代码和模板默认值：`90`。
- 作用：设置 Quartz 执行历史终态记录的保留天数。
- 约束：必须大于 `0`。

#### `spectra.scheduler.quartz.history-cleanup-batch-size`

- 类型：整数。
- 代码和模板默认值：`500`。
- 作用：限制每轮执行历史清理的最大行数。
- 约束：必须大于 `0`。

#### `spectra.scheduler.quartz.history-running-timeout`

- 类型：Spring `Duration`。
- 代码和模板默认值：`24h`。
- 作用：定义执行历史处于 `RUNNING` 状态且长期没有完成回调时，被认定为节点中断的时间。
- 约束：必须大于 `database-retry-interval`。

#### `spectra.scheduler.quartz.database-retry-interval`

- 类型：Spring `Duration`。
- 代码和模板默认值：`10s`。
- 作用：定义 Quartz 数据库不可用时，生命周期管理重新检查数据库的间隔。
- 约束：必须大于 `0`；数据库不可用期间，重试不会启动没有数据库支撑的 Job。

## 配置来源和生效边界

配置文件中的属性在应用启动时由 Spring Boot 绑定。`SecurityProperties`、`SystemProperties`、`KaptchaProperties`、上传配置类、通知配置类和 `QuartzSchedulerProperties` 分别负责对应前缀；配置类的启动校验会拒绝不满足安全边界的值。

通知配置中的 `notification.enabled`、`notification.allowed-link-prefixes` 和 `notification.cleanup.enabled` 支持从 `spectra_core.sys_config` 读取运行时值。其余本页列出的属性来自启动配置绑定，文件上传和 Quartz 的周期、并发、存储位置等参数由应用启动实例使用。

与本页配置同时存在的 `server`、`spring`、`mybatis-plus` 配置属于 Spring Boot 或 MyBatis-Plus 配置树，不属于 `spectra:` 配置项；例如 HTTP multipart 总大小、数据库连接、Redis 连接超时和 Quartz 原生属性，需要分别查看对应配置章节和环境模板。
