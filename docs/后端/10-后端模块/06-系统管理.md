# 系统管理

> 核心系统管理功能：部门、区域、字典、菜单、系统配置、统一审计日志和 Quartz 调度管理。模块路径：`spectra-core/system`、`spectra-core/quartz`、`spectra-core/audit`。

## 实体总览

| Entity | 表说明 |
|---|---|
| `Department` | 组织架构（树形） |
| `Region` | 行政区划（树形） |
| `Menu` | 系统菜单（树形） |
| `DictGroup` | 字典分组 |
| `DictItem` | 字典项 |

## Department（部门）

树形结构，支持多级组织架构。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `name` | String | 部门名称 |
| `parentId` | UUID | 父部门 ID |
| `sort` | Integer | 排序 |
| `leader` | String | 负责人 |
| `phone` | String | 联系电话 |
| `status` | Integer | 状态 |

### 部门合并与部分拆分

部门重组通过 `AuthorizationController` 的 Preview/Apply 接口执行。合并只接受至少两个同一父级下的活动部门；新部门建在共同父级，源部门的直属下级迁入新部门并保持后代层级，源部门逻辑删除。部分拆分只迁移所选直属成员，新部门与源部门同级；源部门、未选成员和原有子树保留。

Preview 绑定操作者、操作类型、规范化请求和组织版本，令牌有效期为 5 分钟。Apply 会重新校验版本、来源部门和受影响成员/授权状态，在同一数据库事务中创建新部门、更新成员关系与活动授权引用、重建闭包并递增组织版本；失败时数据库变更回滚。合并只改写活动 RoleAssignment 的 Access/Grant 部门规则及未删除授权方案中的部门编码；拆分不改写角色边界或方案模板。OA 历史业务记录继续保留原部门 ID，历史名称解析可以读取逻辑删除部门；活动树、列表和选择器仍只返回活动部门。

## Region（区域）

行政区划数据，省/市/区县/乡镇街道/村级五级树形结构。

## Menu（菜单）

系统菜单树，支持任意层级嵌套。菜单只负责导航和角色可见性，页面组件由 Web 前端静态路由定义。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `name` | String | 菜单名称 |
| `pid` | UUID | 父菜单 ID |
| `menuType` | MenuType | `DIRECTORY` 或 `MENU` |
| `routeName` | String | `MENU` 对应的唯一 Vue Router 路由名 |
| `icon` | String | 图标 |
| `sort` | Integer | 排序 |

约束：`DIRECTORY` 不配置路由名并可拥有子节点；`MENU` 必须配置路由名且是叶子节点。Java Entity、From、VO 和数据库的菜单字段为 `menuType`、`routeName`、`icon` 与 `sort`，不包含 `path`、`component`、`layout`、`hide`、`metadata`。

菜单写入请求遵循全局 `SNAKE_CASE` JSON 约定，使用 `menu_type`、`route_name` 字段；Web API 适配层将前端的 `menuType`、`routeName` 转换为这两个请求字段。

运维管理下的 `文件管理` 目录由 Flyway V1 固定种子写入，与 `系统维护` 同级；其子菜单包括文件上传、文件资产、上传任务、文件引用和文件类型策略，对应 Web 静态路由 `/devops/file/upload`、`/devops/file/assets`、`/devops/file/upload-tasks`、`/devops/file/references` 和 `/devops/file/types`。菜单仅负责入口可见性，上传接口权限、管理写权限和文件资产访问权限仍由 Core 文件能力及业务引用上下文控制。

运行时接口：

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /menu/tree` | `MENU:QUERY` | 菜单管理和 RBAC 使用的完整管理树 |
| `GET /menu/current` | 已认证 | 合并当前用户启用角色的菜单并自动补齐祖先目录 |

菜单、用户角色关系、角色和角色菜单关系查询均显式添加 `deleted IS NULL`，不依赖 MyBatis-Plus 对 `Instant` 软删除字段的隐式过滤；角色菜单保存会拒绝软删除菜单。

## DictGroup / DictItem（数据字典）

两级结构：DictGroup 是字典分组（如"性别"），DictItem 是字典项（如"男"/"女"）。

字典项状态 `0` 表示启用、`1` 表示禁用。禁用项仍由字典查询接口返回，供历史值显示标签；`DictSelect` 将禁用项设为不可选，空值只采用启用的默认项。每个字典组最多有一个默认项，设为默认会替换组内原默认项，禁用默认项会清除其默认标记。字典项的所属组和值创建后不可修改，字典项不提供删除接口；包含字典项的字典组不能删除，以保留业务数据中的既有引用。

字典项生命周期接口：`POST /dict/data/{id}/disable` 需要 `dictionary:disable` 权限；`POST /dict/data/{id}/enable`、`PUT /dict/data/{id}/default` 需要 `dictionary:update`。默认接口请求体使用 `default_flag` 布尔值。字典组仍可删除，但必须为空。

## Configured / SysConfig（系统配置）

- `Configured` — 配置表，支持 Key-Value 对
- `SysConfig` — 系统参数，支持按模块分类

首次初始化会通过受控白名单向 `spectra_core.sys_config` 写入以下非敏感配置：

| Key | 类型 | 说明 |
|---|---|---|
| `system.name` | TEXT | 系统名称 |
| `system.short-name` | TEXT | 系统简称；为空时回退为系统名称 |
| `system.logo` | TEXT | Logo 地址或文件标识，可为空 |
| `system.default-locale` | SELECT | 系统默认语言，关联已有 `sys_language` 字典 |
| `system.default-timezone` | SELECT | 系统默认时区，关联已有 `sys_timezone` 字典；选项使用 IANA 时区标识 |
| `security.profile` | SELECT | 初始化时选择的安全策略，当前为 `STANDARD` / `STRICT` |

系统状态与引导状态共用 `spectra_core.sys_system_state`：`state_key=SYSTEM` 管理首次初始化生命周期，`state_key=SYSTEM_GUIDE` 管理初始化后的 DEV_OPS 系统设置引导，分别使用各自的状态值，不能合并为一个状态判断。DEV_OPS 首次登录完成系统引导时创建初始化根部门，并将 DEV_OPS 设置为该部门的主成员；引导完成后，`crypto.*`、`notification.*` 和 `copyright.*` 的运行时配置写入 `spectra_core.sys_config`。

系统设置引导当前负责以下运行时策略：

| Key | 类型 | 说明 |
|---|---|---|
| `crypto.enabled` | BOOL | 是否启用接口请求加解密；启用时自动生成 RSA 密钥 |
| `notification.enabled` | BOOL | 是否启用 Core 内置统一通知业务功能 |
| `notification.address-encryption-key` | TEXT | 通知外部地址 AES-GCM 密钥，由引导自动生成 |
| `notification.sensitive-payload-key` | TEXT | 通知敏感载荷 AES-GCM 密钥，由引导自动生成 |
| `notification.allowed-link-prefixes` | TEXTAREA | 消息中心允许的站内路由前缀 |
| `notification.cleanup.enabled` | BOOL | 是否清理终态通知中的敏感密文 |
| `copyright.enabled` | BOOL | 是否显示管理页面底部版权 |
| `copyright.name` | TEXT | 底部版权名称 |
| `copyright.url` | TEXT | 底部版权名称点击后的 HTTP/HTTPS 跳转地址 |

用户密码策略配置独立于初始化和 DEV_OPS 引导：

| Key | 类型 | 说明 |
|---|---|---|
| `user.default-password` | SECRET | 新建、导入和管理员重置共用的初始密码；系统设置页仅显示是否已设置，保存时使用当前密码策略校验并以 BCrypt 哈希存储，不回显哈希。留空更新表示保留已有值。 |

启动时应用仅在该配置行不存在时创建空 SECRET 项，不覆盖已有密码。该项为空时，新建用户、用户导入 Apply 和管理员重置均拒绝执行；管理员先在系统配置页面设置符合当前密码策略的值。新建、导入和重置设置 `mustChange=true`、`expiresAt=null`，因此用户必须在首次登录后立即修改密码，不依赖定时到期。管理员重置接口不返回口令，仍保留操作审计和目标用户会话撤销。

Web 系统配置页按系统、加密与安全、通知和其他业务分类展示表单。`GET /configured/settings` 返回配置项及服务端确定的分类；`PUT /configured/batch` 一次提交一个分类的完整表单，后端校验配置项均属于该分类后在单个事务中保存。表单控件由 `type` 决定：`TEXT` 为单行输入，`TEXTAREA` 为多行输入，`BOOL` 为开关，`SELECT` 通过 `dict_code` 读取字典选项；默认语言、默认时区分别复用 `sys_language`、`sys_timezone`。SECRET 值只返回是否已设置，留空保存保留原值；系统生成的通知密钥和由通知 Provider 专用接口维护的配置不返回明文，且拒绝通用表单修改。批量修改审计不采集请求参数，避免记录秘密配置。

必须改密的 Session 只允许读取密码规则和客户端私钥、修改密码及退出；其他个人资料、菜单、系统引导和业务接口均被拒绝。修改密码成功后撤销该用户全部 Session。数据库、Redis、SSL 证书、S3 等启动前置或外部服务凭据仍使用环境变量或密钥管理系统。

初始化接口不接受任意配置键；密码、Token、第三方凭据和私钥不写入这组配置。

## AuditLog（统一审计日志）

普通操作、安全操作、认证和授权事件都使用 common 的 `AuditRecord`，通过 `JdbcAuditEventWriter` 同步追加到唯一事实表 `spectra_core.sys_audit_event`。`AuditEvent` 实体映射分区父表；`AuditLogQueryMapper` 直接查询父表，PostgreSQL 会按 `occurred_at` 条件裁剪分区。该表按 `occurred_at` RANGE 分区，并以 `(event_id, occurred_at)` 作为主键；默认分区接收尚未配置专用时间分区的记录。应用不更新或删除审计记录。

`AuditAspect` 与显式业务审计共用 `AuditService` 和 `JdbcAuditEventWriter`。成功记录与业务事务一起提交；异常操作回滚后，独立事务保存 `failure_code`、`failure_type` 和脱敏的 `failure_reason`。审计存储不可用时，高风险变更 fail-closed。

查询入口为 `/api/audit/page`、`/api/audit/{event_id}?occurred_at=...` 和 `/api/audit/export`，统一页面使用 `DevopsAuditLog` 菜单。分类筛选包括 `OPERATION` 与 `SECURITY`；`operator` 筛选同时接受用户 ID 和姓名，姓名由当前 `sys_user.real_name` 查询；事件类型筛选同时匹配稳定 `event_type` 和操作说明，列表优先显示 `@Audit.value`。安全记录继续应用高风险隐藏和 operator/target 可见性规则。

运行时应用角色只读、追加；分区创建、默认分区迁移及数据清理由 DBA 负责。应用不提供 outbox、归档、恢复或保留策略 API，分区操作说明见 [[../../部署运维/06-审计日志分区维护说明]]。

## Quartz 调度管理

Quartz JobStore 使用独立的 `spectra_quartz` schema；`QRTZ_*` 表保存 JobDetail、Trigger、集群心跳和锁，Core 不再维护旧的 `scheduler_*` 状态机。Job 只能从代码白名单创建，普通 Job 使用服务端生成的 JobKey，且每个 Job 只绑定一个 Cron 或 Simple Trigger。`spectra_core.quartz_job_execution_history` 是应用自建的脱敏执行观测表，按项目数据库标准保留 `BaseEntity` 审计字段；表和每个字段的注释由 V15 migration 完整提供。

管理 API 为 `/api/scheduler/quartz`，Job/Trigger 查询由 `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS`、`ROLE_AUDIT` 使用，普通 Job 变更由前两类角色使用，立即触发属于 `ROLE_DEV_OPS` 高风险操作。调度管理只提供 Quartz Job、Trigger、执行历史和受控操作。
