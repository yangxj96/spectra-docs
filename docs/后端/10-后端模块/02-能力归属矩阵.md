# 后端能力归属

本页说明当前后端能力由哪个模块、哪个包域和哪个公共契约负责。模块边界以实际运行职责划分，公共契约与技术实现分离，业务模块之间不直接依赖对方的内部持久化实现。

## 归属原则

- `spectra-common` 只提供跨模块可复用的类型、端口、事件和值对象。
- `spectra-framework` 提供 Spring、Web、安全、Redis、持久化、序列化、验证码和健康技术实现。
- `spectra-core` 提供系统必需的业务能力和业务编排。
- `spectra-workflow` 只负责 Flowable 流程引擎领域。
- `spectra-oa` 只负责办公自动化业务领域。
- `spectra-launch` 只负责组合、启动和启动时校验。
- 跨模块能力通过 `common.port`、公共服务接口或事件交互，不共享内部 Entity、Mapper 和实现类。

## 认证与授权

认证和授权的业务编排归 `spectra-core`：

- 用户、角色、权限、组织、授权方案和 RoleAssignment 位于 `core.user` 与 `core.security`。
- 登录、登出、Token、Session、验证码、CSRF、请求限流和安全 Redis 技术实现位于 `spectra-framework.security`。
- 认证主体、Session、Token、验证码和安全上下文端口位于 `spectra-common.port.security`。
- 授权快照、数据权限边界、密码策略和安全策略契约位于 `spectra-common.security`。
- 安全审计的业务事件、审计查询和归档编排位于 Core；审计端口位于 `common.port.audit`，归档存储适配位于 Core 文件能力。

认证请求和授权请求的 API 版本固定为 `1.0.0`。安全 Redis 是 Token、Session、验证码、防重放和登录失败锁定的事实源，安全 Redis 不可用时相关操作保持拒绝状态。

## 系统管理

系统管理归 `spectra-core.system`，包括：

- 系统初始化和首次系统设置引导。
- 菜单树、授权菜单和动态路由数据。
- 字典组、字典项和系统配置读写。
- 行政区域和区域名称缓存。
- 服务监控、依赖健康、运行指标和告警。
- 缓存监控、已登记普通缓存清理和安全计数维护。

Web CORS、统一响应、API 版本请求头、异常处理和请求关联属于 `spectra-framework.web`。业务系统配置项写入 `spectra_core.sys_config`，配置绑定对象只承载启动配置和技术运行参数。

## 文件能力

文件能力的完整业务闭环归 `spectra-core.upload`：

- 上传任务、分片、文件资产、文件引用、文件类型和清理任务由 Core 管理。
- 本地文件系统和 S3 存储 Provider 位于 Core 的 `upload.storage`。
- 文件流、文件资产、文件引用和上传完成事件通过 `common.port.file` 与其他模块交互。
- 操作和安全审计共用 `spectra_core.sys_audit_event`；时间分区由 DBA 管理，Core 不提供归档或清理任务。
- Web 请求层的上传请求、下载响应和错误处理适配位于 framework；OA 只保存业务文件引用，不引用 Core 的存储实现。

## 通知能力

统一通知归 `spectra-core.notification`：

- 模板、模板版本、通知请求、任务、投递、站内收件箱和用户偏好由 Core 持久化和编排。
- Provider 配置、健康检查、受控测试发送和外部回执由通知子域管理。
- Worker 负责通知任务租约、发送、状态推进、有限重试和 Delivery 记录。
- 敏感载荷加密、摘要和清理由通知子域负责；Provider 密钥由密钥管理提供。
- Core 通过公共通知端口向其他业务提供通知能力，OA 和 Workflow 不直接调用 Provider。

## 调度能力

Quartz 调度归 `spectra-core.scheduler`：

- Job 类型来自代码注册的白名单定义。
- JobDetail、Trigger、暂停/恢复、删除、立即触发和执行历史由 Core 管理。
- Quartz JDBC JobStore、集群锁和引擎表位于独立的 `spectra_quartz` schema。
- Job 参数使用代码声明的 Schema 和白名单类型，外部请求不接受 Bean 名称、方法名、SQL、脚本或反射信息。
- `common.port.quartz` 提供跨模块注册任务的公共定义；业务模块不直接操作 Quartz 内部对象。
- Quartz 健康检查由 `QuartzSchedulerHealthIndicator` 提供，服务监控通过 Core 健康聚合读取结果。

## 工作流能力

Flowable 工作流归 `spectra-workflow`：

- 流程定义、部署、版本、流程实例、任务、审批回调和 Flowable 健康检查由 Workflow 管理。
- Flowable 引擎配置、Mapper、Service 和 Controller 保持在 Workflow 内部。
- OA 通过工作流公共端口发起流程、查询任务和处理审批，不引用 Workflow 内部实体。
- 流程建模器属于独立前端插件和 Web 宿主；后端 Workflow 负责 XML 部署和运行，不负责画布渲染。

## OA 能力

办公自动化归 `spectra-oa`，领域包括：

- 申请和申请类型。
- 请假、协同、报销、采购和资产。
- 考勤、日历、通讯录、合同和文档。
- 会议、公告、报表和工作台。

OA 依赖 Core 的用户、组织、通知、文件和系统公共能力。OA 的文件属于业务引用，文件存储、引用校验和访问权限由 Core 文件端口及当前业务上下文共同决定。

## 数据访问与持久化

持久化技术归 `spectra-framework.persistence`：

- `BaseEntity`、Service 基类、分页参数和数据库类型处理器属于 framework。
- MyBatis-Plus 配置、Mapper 拦截器、审计字段填充和数据权限 SQL 处理属于 framework。
- 业务 Entity、Mapper 和业务 Service 按领域分别位于 Core、Workflow 或 OA。
- 数据权限策略和授权快照属于 Core/common 的业务契约；SQL 拦截和请求上下文适配属于 framework。
- Flyway 迁移资源位于 `spectra-config`，数据库表的业务归属由对应模块文档说明。

## Web 与安全技术基础设施

以下能力全部归 `spectra-framework`，不向业务模块暴露内部实现：

- Spring MVC 和统一响应包装。
- API 版本请求头和请求关联。
- 请求/响应加解密 Advice。
- Cookie、CSRF、Token 过滤器和 Session Redis 仓储。
- 安全 Redis Key、原子操作、验证码存储和登录失败计数。
- CORS、Jackson、MapStruct、缓存、数据库连接和健康适配。

业务模块通过 `spectra-common` 的端口或公共策略访问这些能力，不能在业务模块内重新创建第二套 Token、Session、验证码、审计或健康协议。

## 装配与运行边界

- `spectra-launch` 组装 `spectra-config`、Core、Workflow 和 OA。
- Core 是系统必选业务核心；通知和文件能力随 Core 一起提供。
- Workflow 和 OA 的模块开关只控制对应模块的装配。
- Framework 的技术 Bean 由 framework 自身入口发现，Core 的业务 Bean 由 Core 入口发现。
- 健康结果统一使用 `common.health.DependencyHealthContributor` 协议，由 Core 聚合并接入 Actuator。
- 安全 Redis、数据库、S3、Quartz 和 Flowable 的依赖故障不能被空对象、普通缓存或本地状态伪装成可用。
