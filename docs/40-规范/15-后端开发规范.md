# 后端开发规范

> spectra-admin 后端 Java 代码的统一编写规范。所有后端代码编写必须遵循本文档。

## 代码格式化与校验

- 后端 Java 代码统一使用 `spectra-admin/config/eclipse-java-formatter.xml` 中的 Eclipse JDT Formatter 配置。
- 缩进使用 4 个空格，不使用 Tab；右边距统一为 150 列。
- 使用 Spotless Maven Plugin 执行格式化和校验：`./mvnw spotless:apply` 用于整理格式，`./mvnw spotless:check` 用于快速检查；完整的 `./mvnw verify` 在模块完成或提交前执行。
- Spotless 采用 `origin/master` 作为渐进校验基线，避免首次接入时批量改写历史代码；全量校验可使用 `-Dspotless.ratchetFrom=NONE`。
- Spotless 使用 Eclipse JDT Formatter，不依赖本机 IntelliJ IDEA；IDEA 侧如需保持编辑器即时格式化，可导入同一份 Eclipse formatter XML。
- 项目编译基线为 JDK 25；可以使用 JDK 25 的稳定语言特性，但不得为了语法简短牺牲请求绑定、校验或领域语义。
- Java 源码中的类型声明、方法签名、泛型、构造调用和方法引用必须使用简单类名并通过 `import` 引入；只有两个同名类型确实发生导入冲突时，才允许其中一个使用全限定名。禁止写 `java.util.UUID id`、`java.util.List.of(...)` 这类无冲突全限定名。
- 业务状态、类型、渠道、动作等值域封闭且由本系统控制的字符串必须定义为枚举，并通过枚举值或 `name()` 持久化/传输；不得散落 `"SENT"`、`"FAILED"` 等魔法字符串。第三方协议中开放或供应商自定义的状态码可以保留 `String`，但必须在适配边界集中归一化为内部枚举。
- 开发节奏遵循“先实现、后整理”：功能或模块开发过程中不要求每次修改都执行完整 `mvn verify`，优先按需运行目标模块的 `compile` 或 `test` 获取快速反馈；模块完成或准备提交时，再统一执行格式整理和质量门禁。

## 1. 注释规范

- 使用传统 Javadoc 块注释（`/** ... */`），不使用 Java 23+ 的三斜杠 Markdown 文档注释
- 每个 Java 文件必须包含 Apache License 2.0 头部
- 类注释必须包含 `@author`、`@version`、`@since`
- 接口方法声明、Controller/配置/监听器等没有接口契约可复用的公开方法必须有方法级 Javadoc，并在需要时使用 `@param`、`@return`、`@throws` 说明参数、返回值和异常。
- 实现接口的类中，带 `@Override` 的实现方法直接复用接口契约，不重复编写相同 Javadoc；只有实现新增了接口未表达的重要语义时才补充差异说明。
- 私有辅助方法（包括工具类中的私有计算、校验、转换和组装方法）必须有简短 Javadoc，说明其职责和关键边界；私有构造器不要求重复注释。
- 文档内容统一使用传统 Javadoc/HTML 语法：标题使用 `<h3>`，列表使用 `<ul>/<li>`，代码和类型使用 `{@code ...}` 或 `<code>...</code>`，代码示例使用 `<pre>`。
- 类级元信息使用普通的 `@author`、`@version`、`@since` 标签；方法参数、返回值和异常使用标准的 `@param`、`@return`、`@throws` 标签。
- record 组件的说明统一写在类级 Javadoc 中，不在组件声明上单独添加注释；每个 `@param` 的组件名和说明保持在同一行，同一 record 内的说明按最长组件名对齐。

```java
/**
 * 表单定义Service实现
 *
 * @author yangxj96
 * @version 1.0
 * @since 2026/7/17
 */
```

record 的类级注释示例：

```java
/**
 * 通知请求完成持久化和任务展开后的入队回执。
 *
 * @param requestId        通知模块内部的逻辑请求 ID
 * @param status           逻辑请求当前状态
 * @param taskCount        本次请求已展开的接收人×渠道任务数
 * @param idempotentReplay 是否因命中幂等键而返回已存在的请求结果
 * @author yangxj96
 * @version 1.0
 * @since 2026/8/11
 */
public record NotificationReceipt(UUID requestId, String status, int taskCount, boolean idempotentReplay) {
}
```

## 2. 包结构

### 简单模块（扁平结构）

适用于实体少、业务简单的模块（如 ai、upload、workflow）：

```
com.devops00.spectra.{module}
├── {Module}Module.java              # 模块入口（@ComponentScan + @MapperScan）
├── configuration/                    # 配置类
├── controller/                       # REST 端点
├── javabean/
│   ├── converter/                    # MapStruct 转换器
│   ├── entity/                       # 数据库实体
│   ├── from/                         # 请求表单对象
│   └── vo/                           # 响应视图对象
├── mapper/                           # MyBatis-Plus Mapper
├── service/                          # 业务逻辑接口
│   └── impl/                         # Service 实现
└── properties/                       # 配置属性（可选）
```

扁平分层是基础结构，不代表所有组件都必须塞入 `service`。按真实职责增加下列同级包：

- `provider/`、`provider/impl/`：第三方能力 SPI 与具体 Provider。
- `sender/`、`sender/impl/`：发送策略及渠道发送器。
- `dispatch/`：Worker、调度器、任务领取与状态推进组件。
- `strategy/`、`policy/`、`validator/`：可替换策略、规则与校验器。
- `client/`、`adapter/`：外部系统客户端及边界适配。
- `support/`：依赖领域服务、权限上下文或流程端口的跨子域复用组件；应使用明确的领域名称，不能退化为静态工具类。
- `utils/`：无状态、无领域依赖、可复用的纯函数工具。

`service/` 只放应用服务接口及其实现，不放 Provider、Sender、Worker、Listener、Client 或纯工具类。复杂模块的每个子域同样遵循该职责分包规则。

### 复杂模块（子域拆分）

适用于实体多、业务复杂的模块（如 core、oa）：

```
com.devops00.spectra.{module}
├── {Module}Module.java
├── {subdomain}/                      # 子域（如 auth/、system/、user/）
│   ├── controller/
│   ├── javabean/
│   │   ├── converter/
│   │   ├── entity/
│   │   ├── from/
│   │   └── vo/
│   ├── mapper/
│   └── service/
│       └── impl/
├── common/                           # 跨子域共享代码（可选）
└── configuration/                    # 模块级配置
```

## 3. Controller 规范

### 基本规则

- 统一 `@RequiredArgsConstructor` + `private final` 构造器注入
- 瘦 Controller：只做请求转发，不包含任何业务逻辑
- 除路径参数（`@PathVariable`）外，请求参数统一使用 `From` 入参对象接收；禁止在 Controller 中直接使用 `String`、数值、布尔值、`Map` 或 `List` 接收查询参数/请求体。分页查询可组合使用公共 `PageFrom` 与业务 `XxxPageFrom`。
- 禁止返回 `Object`，必须返回具体类型（`IPage<XxxVO>`、`XxxVO`、`List<XxxVO>`、`void`）
- 统一方法命名：`created`/`modify`/`deleteById`/`page`

### 注解使用

| 注解 | 规则 |
|---|---|
| `@Audit` | **所有需要记录审计的接口方法必须加**。GET 用简短描述，POST/PUT/DELETE 用详细描述；复杂动作直接调用 `AuditService` |
| `@PreAuthorize` | **所有接口必须加**。公开接口用 `permitAll()` 显式标注 |
| `@Validated` | **所有写操作必须加**。使用 `Verify.Insert.class` 或 `Verify.Update.class` 分组 |
| `@Slf4j` | **必须加**。使用 `log.debug()` 记录入参（较低级别） |
| `version` | Mapping 注解中统一 `version = "1.0.0"` |

### @Audit 描述格式

统一中文动宾短语：

| HTTP 方法 | 描述风格 | 示例 |
|---|---|---|
| GET | 简短 | `'查询表单列表'`、`'获取流程定义图'`、`'查询待办任务'` |
| POST | 详细 | `'创建表单定义'`、`'部署流程定义'`、`'启动流程'` |
| PUT | 详细 | `'更新表单定义'`、`'修改角色'` |
| DELETE | 详细 | `'删除表单定义'`、`'删除用户'` |

### @PreAuthorize 规则

- 所有接口必须加
- 公开接口用 `@PreAuthorize("permitAll()")` 显式标注
- 权限控制用 `@PreAuthorize("hasPermission(null, 'MODULE:ACTION')")`
- 角色控制用 `@PreAuthorize("hasRole('ROLE_xxx')")`

### @Slf4j 规则

- Controller 层必须加 `@Slf4j`
- 使用较低级别 `log.debug()` 记录请求入参
- Controller 层不直接写日志表（审计由 `@Audit`/`AuditService` 和统一 Core sink 负责）

### 典型模板

```java
@Slf4j
@RestController
@RequestMapping("/workflow/form-definitions")
@RequiredArgsConstructor
public class FormDefinitionController {

    private final FormDefinitionService formDefinitionService;

    @Audit("'查询表单列表'")
    @GetMapping(value = "", version = "1.0.0")
    @PreAuthorize("isAuthenticated()")
    public IPage<FormDefinitionVO> page(PageFrom page, FormPageFrom params) {
        return formDefinitionService.page(page, params);
    }

    @Audit("'创建表单定义'")
    @PostMapping(value = "", version = "1.0.0")
    @PreAuthorize("hasPermission(null, 'WF_FORM:INSERT')")
    public void created(@Validated(Verify.Insert.class) @RequestBody FormDefinitionSaveFrom from) {
        formDefinitionService.created(from);
    }
}
```

## 4. Service 规范

### 接口

- 接口继承 `BaseService<Entity>`（**禁止直接继承 MyBatis-Plus 的 `IService`**）
- 方法声明使用 `created`/`modify`/`deleteById`/`page` 等命名
- 返回类型使用具体 VO 类型

```java
public interface FormDefinitionService extends BaseService<FormDefinition> {
    IPage<FormDefinitionVO> page(PageFrom page, FormPageFrom params);
    void created(FormDefinitionSaveFrom from);
    void modify(UUID id, FormDefinitionSaveFrom from);
    void deleteById(UUID id);
}
```

### 实现类

- 继承 `BaseServiceImpl<Mapper, Entity>` 并实现对应接口
- 必须加 `@Slf4j`、`@Service`
- 详细日志：关键业务节点用 `log.info()`，异常用 `log.error()`
- 写操作必须加 `@Transactional`
- 异常消息统一中文
- 字段注入 Converter 负责 From→Entity 和 Entity→VO 转换

### 公共逻辑提取

- 两处及以上出现语义和实现都相同的内部方法时必须评估提取；三处及以上重复默认应提取，除非能说明它们会独立演进。
- 纯计算、格式化、摘要、脱敏等无状态且不依赖领域端口的逻辑提取到 `utils` 中的 `final` 工具类，使用私有构造器和静态方法。
- 需要 Mapper、Repository、配置、事务或领域规则的复用逻辑提取为命名清晰的 `@Component`/领域服务，禁止为了复用强行做成静态工具类。
- 优先复用已有公共能力（例如 `TimeMapper`、`SHA256Utils`），不得在多个 Service 内再次包装同名的一行转发方法；也不得创建职责混杂的 `CommonUtils`、`BizUtils` 巨型工具类。

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class FormDefinitionServiceImpl
        extends BaseServiceImpl<FormDefinitionMapper, FormDefinition>
        implements FormDefinitionService {

    private final FormConverter formConverter;

    @Override
    @Transactional
    public void created(FormDefinitionSaveFrom from) {
        var entity = formConverter.toEntity(from);
        if (!this.save(entity)) {
            throw new DataSaveException("创建表单定义失败");
        }
        log.info("创建表单定义成功: id={}, name={}", entity.getId(), entity.getName());
    }
}
```

## 5. 异常处理

### 异常类型

统一使用项目自定义异常，**禁止裸 RuntimeException**：

| 异常类 | 说明 | 使用场景 |
|---|---|---|
| `DataNotExistException` | 数据不存在 | 查询/更新/删除时实体不存在 |
| `DataSaveException` | 数据保存失败 | insert/update 操作失败 |
| `EntityUpdateException` | 实体更新失败 | updateById 返回 false |
| `BuiltinDataException` | 内置数据不可操作 | 删除/修改系统内置数据 |
| `DefaultDataException` | 默认数据不可操作 | 删除默认角色/用户等 |

### 异常消息

- 统一中文（用户友好，前端可直接展示给用户）
- 示例：`"表单定义不存在"`、`"创建表单定义失败"`、`"内置角色,不可删除"`

### 异常使用原则

```java
// 正确：使用自定义异常
var entity = this.getById(id);
if (entity == null) {
    throw new DataNotExistException("表单定义不存在");
}

// 错误：禁止裸 RuntimeException
if (entity == null) {
    throw new RuntimeException("表单定义不存在");
}
```

## 6. 实体规范

- UUID 主键：`@TableId(type = IdType.INPUT)`，由全局 MyBatis-Plus `MetaObjectHandler` 在新增时自动生成 UUID v7
- 新增实体不得在 Service/Controller 中手工调用 `setId` 或 `UUID.randomUUID()` 设置数据库主键；只有更新已有记录时才允许回填已有业务 ID
- 审计字段：`createdBy`、`createdAt`、`updatedBy`、`updatedAt`（继承 `BaseEntity`）
- 软删除：`Instant deleted`（null = 未删除）（继承 `BaseEntity`）
- 乐观锁：`@Version`（继承 `BaseEntity`）
- 默认排序：`@OrderBy` 设置
- 表名注解：`@TableName("xxx")`
- 字段注解：`@TableField("xxx")`

```java
@Getter
@Setter
@ToString
@TableName("wf_form_definition")
public class FormDefinition extends BaseEntity {

    @TableField("name")
    private String name;

    @TableField("code")
    private String code;
}
```

## 7. From 对象规范

- 统一后缀 `From`（**非 Form**）
- 包路径：`javabean/from/`
- 必填字段必须加 `@NotBlank`/`@NotNull` 等校验注解
- 使用 `@Data` 注解
- 提供清晰的中文 `message` 参数
- Controller 请求对象禁止声明为 `record`。请求绑定、Bean Validation、分组校验和后续字段演进统一使用普通 `class`；`record` 仅用于响应值、内部不可变命令/结果或无框架绑定要求的值对象。
- 日期、时间和日期时间入参统一声明为 ISO 8601 `String`，不得在 From 中直接使用 `Instant`、`LocalDateTime`、`OffsetDateTime` 等类型。

```java
@Data
public class FormDefinitionSaveFrom {

    @NotBlank(message = "表单名称不能为空")
    private String name;

    @NotBlank(message = "规则JSON不能为空")
    private String ruleJson;

    private String description;  // 可选字段不加校验注解
}
```

## 8. VO 对象规范

- 统一后缀 `VO`
- 包路径：`javabean/vo/`
- 使用 `@Data` 注解
- 分页查询返回 `IPage<XxxVO>`
- VO 的日期时间字段按展示语义使用 `LocalDate`、`LocalTime` 或 `LocalDateTime`，禁止向 API 响应暴露 `Instant`。
- 简单不可变响应允许使用 `record`；需要 MapStruct、继承、分阶段组装或较多可选字段时使用普通 `class`。

## 9. Converter 规范（MapStruct）

### 必须使用

所有模块必须使用 MapStruct Converter 进行对象转换，禁止手动 setter。

### 定义方式

```java
@Mapper(uses = TimeMapper.class, config = GlobalMapperConfig.class)
public interface FormConverter {

    /**
     * 实体转 VO
     */
    FormDefinitionVO toVO(FormDefinition source);

    /**
     * From 转实体
     */
    FormDefinition toEntity(FormDefinitionSaveFrom source);

    /**
     * 更新已有实体
     */
    void updateEntity(FormDefinitionSaveFrom source, @MappingTarget FormDefinition target);
}
```

### 时间字段规范

- `From` 入参中的日期、时间、日期时间统一使用 `String`，传输格式为 ISO 8601；日期可使用 `YYYY-MM-DD`，时间可使用 `HH:mm:ss`，日期时间优先使用带偏移量的形式（例如 `2026-08-09T10:30:00+08:00`）。
- Entity 中需要持久化的日期、时间、日期时间统一使用 `Instant`，数据库字段统一使用 `TIMESTAMP(6) WITH TIME ZONE`。
- VO 响应按展示语义使用 `LocalDate`、`LocalTime` 或 `LocalDateTime`，由 `TimeMapper` 按当前用户时区转换；禁止在 Service 中手工调用 `Instant.parse` 或手工拼接时区。
- `TimeMapper.toInstant(String)` 负责统一解析 ISO 8601 输入；无时区的字符串按当前用户时区解释。
- MapStruct Converter 必须声明 `uses = TimeMapper.class`；确需手工组装 VO 时注入 `TimeMapper`，使用 `toLocalDateTime`/`toInstant` 完成边界转换，不得使用系统默认时区自行转换。
- 代码审查必须同时检查三条不变量：Entity 无 `LocalDateTime` 等本地日期时间类型、From 无 Java 时间类型、VO 无 `Instant`。

### 包路径

统一放在 `javabean/converter/`

### 全局配置

引用 `GlobalMapperConfig.class` 和 `TimeMapper.class`，统一由 `spectra-framework` 提供。

## 10. 方法命名规范

| 操作 | 方法名 | 说明 |
|---|---|---|
| 创建 | `created` | 新增数据 |
| 更新 | `modify` | 修改数据 |
| 删除 | `deleteById` | 根据 ID 删除 |
| 分页查询 | `page` | 返回 `IPage<VO>` |
| 批量保存 | `saveBatch` | 批量插入 |
| 批量更新 | `updateBatch` | 批量更新 |
| 批量删除 | `deleteBatch` | 批量删除 |
| Upsert | `upsert` | 按唯一键去重的插入/更新 |

## 11. 日志规范

### 日志级别使用

| 级别 | Controller 层 | Service 层 |
|---|---|---|
| `log.debug()` | 记录请求入参 | 查询条件、参数详情 |
| `log.info()` | — | 关键业务节点（创建成功、部署成功等） |
| `log.warn()` | — | 业务校验失败、降级处理 |
| `log.error()` | — | 异常捕获、系统错误 |

### 日志消息格式

- 使用中文
- 关键节点必须记录实体 ID
- 示例：`log.info("创建表单定义成功: id={}, name={}", entity.getId(), entity.getName())`

## 12. 公开接口处理

- Controller 上加 `@PreAuthorize("permitAll()")` 显式标注
- SecurityConfig 中配置白名单作为兜底
- 两者结合使用，确保安全性

每个业务模块必须有一个 `*Module.java` 入口类：

@MapperScan("com.devops00.spectra.workflow.**.mapper")

}

## 14. Maven 代码质量门禁

后端质量检查统一由 Maven 本地执行，不依赖 IDE、Docker 或 Sonar 服务：

| 工具 | 职责 | 生命周期 |
|---|---|---|
| Spotless | Java 格式、缩进、换行和 import 自动修复/校验 | `verify` |
| Checkstyle | 命名、import 合法性和基础编码约定 | `verify` |
| PMD | 源码坏味道、复杂度、异常处理和高价值最佳实践 | `verify` |
| SpotBugs + FindSecBugs | 编译字节码 Bug 与 Java Web 安全风险 | `verify` |
| ArchUnit | Controller → Service → Mapper/Repository 等包依赖约束 | JUnit `test` |

执行时机约定：

- 功能开发中：不强制执行完整 `verify`，按需运行目标模块的 `compile` 或 `test`。
- 模块完成后：执行格式整理，并至少验证当前模块及其依赖。
- 提交代码前：执行全项目格式整理和完整质量门禁；仅修改文档且不涉及 Java/Maven 时可跳过无关的后端构建。

```bash
# 模块完成时（以下以 spectra-core 为例，替换为实际模块）
./mvnw -pl spectra-core -am spotless:apply
./mvnw verify -pl spectra-core -am

# 提交代码前
./mvnw spotless:apply
./mvnw verify
```

检查失败时必须定位并修复源码根因后重跑，不得通过 `skip`、`exclude`、关闭失败门禁或无理由 suppression 规避问题。仅生成代码或确认的工具误报可做最小范围、带注释的过滤。PMD 当前复杂度阈值（方法 30、类 200、NPath 10000）是存量编排代码的迁移基线，应随治理逐步降低。
