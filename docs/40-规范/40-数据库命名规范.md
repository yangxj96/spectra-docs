# 数据库命名规范

> 来源：[[00-项目总览|项目 VitePress 文档]]
>
> 适用范围：SPECTRA 平台所有数据库对象（表、字段、索引、约束）。

## 总体设计原则

### 1. 分层清晰

数据库对象必须体现系统层级与业务边界：

- **平台/核心能力层**：`SYS_`
- **基础资源域**：按资源域前缀（如 `ORG_`、`FILE_`）
- **业务域**：按业务域前缀（如 `PRJ_`、`ORD_`）

> 禁止所有业务表统一使用 `BIZ_`

### 2. 前缀即边界

一个前缀 = 一个逻辑域/子系统，用于权限、拆库、服务治理。

### 3. 命名稳定性

表名、字段名一旦上线，**原则上不修改**。

## 表命名规范

### 核心平台表（`SYS_`）

身份、权限、组织、配置、审计相关。

```
SYS_USER
SYS_ROLE
SYS_REL_USER_ROLE
SYS_ROLE_DATA_SCOPE
SYS_DICT
SYS_CONFIG
SYS_AUDIT_LOG
```

**强制规则**：SYS 表不得外键依赖任何业务表。

### 安全能力表（`SEC_`）

认证、授权、会话策略、多因素认证和安全审计相关表使用 `SEC_` 前缀，归属于 `spectra_security` schema。

```
SEC_PERMISSION
SEC_ROLE
SEC_ROLE_ASSIGNMENT
SEC_AUTHENTICATION_IDENTITY
SEC_SECURITY_AUDIT_EVENT
```

安全表可以引用 `SYS_` 平台主体表（如用户、部门和菜单），但不得反向被业务域表引用。

### 基础资源域表

```
ORG_ORGANIZATION
ORG_ORG_MEMBER
FILE_OBJECT
FILE_BUCKET
```

### 业务域表

```
{域前缀}_ + 表名

PRJ_PROJECT
PRJ_PROJECT_MEMBER
ORD_ORDER
ORD_ORDER_ITEM
```

### 关联/中间表

```
{域前缀}_REL_{主体1}_{主体2}

SYS_REL_USER_ROLE
PRJ_REL_PROJECT_USER
```

## 字段命名

### 通用字段

```sql
ID           UUID
CREATED_BY   UUID
CREATED_AT   TIMESTAMP(6) WITH TIME ZONE NOT NULL
UPDATED_BY   UUID
UPDATED_AT   TIMESTAMP(6) WITH TIME ZONE NOT NULL
DELETED      TIMESTAMP(6) WITH TIME ZONE
VERSION      BIGINT DEFAULT 0
```

### 物理字段顺序

所有新建表和重建表的物理列顺序固定为：

```text
ID -> 业务字段 -> 审计字段
```

其中：

- `ID` 是第一列，类型为 `UUID`，由 MyBatis-Plus `MetaObjectHandler` 在应用写入时生成 UUID v7；数据库默认值只作为原生 SQL 和迁移脚本的兜底。
- 业务字段包含外键、状态、时间、配置、JSONB 和业务唯一键等字段，保持实体定义中的业务顺序。
- 审计字段固定放在最后，顺序不可变：`CREATED_BY`、`CREATED_AT`、`UPDATED_BY`、`UPDATED_AT`、`DELETED`、`VERSION`。
- 关系表和单例表也必须遵守该顺序；自然键只能作为业务字段并通过唯一约束保护，不能替代技术主键。
- `spectra_security.sec_security_audit_event` 是分区审计事实表例外：必须保留 `(event_id, occurred_at)` 的分区唯一性和追加写入约束，但仍将技术 `id` 放在业务字段之前，公共审计字段放在最后。

完整的当前字段清单见 [[40-字段顺序清单]]。任何新增或删除实体，都必须同步更新该清单和对应 `docs/sql/<schema>/建表.sql`。

### `spectra_security` 字段契约

`spectra_security` 下的业务表、关系表、凭证表和策略表统一包含上述公共字段以及 `ID UUID` 技术主键；关系表和单例表保留业务唯一键，但不再使用复合键或业务键替代技术主键。关系唯一性通过 `UK_{TABLE_NAME}_...` 约束维护。

通过 MyBatis-Plus 新增安全实体时，实体必须继承 `BaseEntity` 并保持 `id` 为空，由全局 `MetaObjectHandler` 统一生成 UUID v7；数据库默认值只作为原生 SQL、迁移回填和其他非 MyBatis-Plus 写入的兜底机制。

安全审计事件是唯一的结构例外：它仍是按 `occurred_at` 分区的追加写入表，保留 `(event_id, occurred_at)` 不可变业务主键，同时补齐 `id` 和公共字段。审计事实的 `deleted` 固定为 `NULL`，禁止 UPDATE、DELETE 和软删除；技术主键唯一约束按 PostgreSQL 分区表规则包含分区键。

开发阶段的字段收口由 Flyway `V21__rebuild_security_column_order.sql`、`V22__rebuild_core_column_order.sql` 和 `V23__separate_organization_version_audit_field.sql` 完成：按“新表 -> 搬迁数据 -> 删除旧表 -> 重命名”的方式重建 `spectra_security` 与 `spectra_core` 项目表，统一物理列顺序、技术主键和业务唯一约束，并将组织业务版本与公共审计版本分离。种子元数据由 `V24__normalize_seed_audit_metadata.sql` 和 `V25__complete_schema_comments_and_oa_seed_metadata.sql` 固化：创建人和更新人使用零 UUID，创建时间和更新时间固定为 `1996-10-15 00:00:00+08`；固定单例种子的技术主键也使用零 UUID；V25 同时补齐公共技术字段注释，V26 `complete_core_business_column_comments` 补齐 Core 组织及初始化状态表的业务字段注释。该迁移不作为生产历史库兼容方案；正式发布前应从干净基线生成正式版本迁移。

### 外键字段

```
{引用表名}_ID

USER_ID
ROLE_ID
PROJECT_ID
```

### 枚举/类型字段

```
*_TYPE     → SCOPE_TYPE, TARGET_TYPE
*_STATUS   → USER_STATUS, ORDER_STATUS
*_FLAG     → default_flag, enabled_flag
```

## 索引命名

| 类型 | 格式 |
|---|---|
| 主键 | `PK_{TABLE_NAME}` |
| 唯一索引 | `UK_{TABLE_NAME}_{COLUMN}` |
| 普通索引 | `IDX_{TABLE_NAME}_{COLUMN}` |

## 禁止事项

- SYS 表引用业务表
- 不带前缀的业务表
- 表名使用动词
- 字段名使用拼音
- 不同语义字段复用同一名称

## 推荐前缀规划

```
SYS_   平台核心
SEC_   认证、授权与安全审计
ORG_   组织/租户
PRJ_   项目
WF_    工作流
ORD_   订单
FIN_   财务
FILE_  文件
```
