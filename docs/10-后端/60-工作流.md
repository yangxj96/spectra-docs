# 工作流

> 基于 Flowable 流程引擎的工作流管理模块。路径：`spectra-workflow`。

## OA 业务回调（P0）

业务流程启动时将 `businessKey` 统一设置为通用申请主表 `oa_application.id`。`WorkflowService` 维护“流程定义 KEY → `ApprovalCallback`”注册表；任务完成且 Flowable 流程进入历史结束态后，`TaskServiceImpl` 分发 `onApproved` / `onRejected`，终止流程时由 `ProcessInstanceServiceImpl` 分发 `onTerminated`。

回调实现必须按业务状态做幂等保护。当前请假流程注册 KEY 为 `oa_leave_approval`：通过回写 `oa_attendance_record`，驳回/撤回/取消释放预占额度，并向申请人写入 OA 消息。费用报销流程注册 KEY 为 `oa_reimbursement_approval`：审批回写申请状态，付款状态独立保持 `PENDING`，登记付款后转为 `PAID`。采购流程注册 KEY 为 `oa_purchase_approval`：审批回写申请状态，审批通过后进入 `NOT_STARTED` 执行状态，执行登记转为 `ORDERED`，收货按批次累计数量并转为 `PARTIAL_RECEIVED` 或 `RECEIVED`。

任务查询 VO 返回 `processDefinitionKey`、`businessKey`，供 Web/移动端审批中心定位 OA 业务详情。审批、驳回、转办和委派等写操作均从认证上下文取得当前用户名，并校验任务办理人所有权，不能只凭任务 ID 越权办理。OA 详情可见范围同时包含申请人、同部门用户、当前办理人和历史办理人。

流程终止采用幂等语义：业务撤回已经终止实例后，再执行业务取消只记录“实例已结束”并继续完成状态迁移，不因重复终止返回 404。旧 `leaveProcess` BPMN 已停止部署，数据库中的历史定义保持挂起；未被任何业务引用的 `oaSingleApproval`、`oaMultiApproval` 示例资源也已移除。当前自动部署并由 OA 使用的流程 KEY 仅为 `oa_leave_approval`、`oa_reimbursement_approval`、`oa_purchase_approval`。

Web 与移动端均提供审批中心，直接复用 `/workflow/tasks/todo`、`/workflow/tasks/done` 和任务动作端点，不另建 OA 审批任务表。2026-08-08 真实接口验收覆盖请假同意/撤回取消、报销驳回取消/同意付款、采购同意执行收货；所有流程进入历史结束态且运行中任务归零。
