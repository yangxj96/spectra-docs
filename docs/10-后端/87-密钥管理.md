# 密钥管理

密钥管理是 `ROLE_DEV_OPS` 专属的系统维护能力。页面和接口都只允许该角色访问，其他角色既不返回菜单，也不能调用接口。密钥值只在创建、导入或迁移时短暂进入请求，管理查询只返回状态、版本、来源和 SHA-256 摘要，不返回明文或数据库密文。

## 分层与事实源

系统只在部署环境保留一个根密钥 `SPECTRA_SECURITY_SECRET_MASTER_KEY`。它必须是 Base64 编码的 32 字节值，用于 AES-256-GCM 加解密 `spectra_security.sec_secret_version` 中的密文；根密钥不在页面编辑，变更必须通过重新部署完成。数据库密文绑定密钥编码作为 AAD，随机 nonce 单独保存。

页面按三类展示后端注册的密钥定义：

| 分类 | 内容 | 轮换方式 |
|---|---|---|
| 应用加密密钥 | RSA 通信密钥、通知地址和敏感载荷 AES 密钥 | 首次初始化自动生成；后续生成或手工新增版本，发布后支持热刷新 |
| 业务服务凭据 | SMS、EMAIL 及后续 OAuth、AI、Webhook、支付或外部 API 凭据 | 手工新增并发布版本；短信和邮件不做定时轮换 |
| 安全签名密钥 | 验证码 HMAC、授权变更令牌 HMAC、防伪和完整性签名密钥 | 首次初始化自动生成；后续手工新增并发布版本，按业务窗口切换 |

Session、Token、验证码、Nonce、防重放数据和登录失败锁定计数仍以安全 Redis 为事实源；它们由“缓存清理”页面按受控操作清理，不作为密钥值迁移。数据库、Redis、S3 连接信息也不进入本页面。

首次系统初始化完成时自动生成并发布四个 RSA 密钥、两个通知保护 AES 密钥和四个安全 HMAC 密钥，共 10 个内部密钥；生成操作在初始化事务中执行，重复启动不会重新生成或覆盖已有完整版本。短信、邮件等第三方服务凭据不自动生成，由运维人员后续导入或创建版本。

升级已经初始化但曾误开启接口加解密的旧数据库时，Flyway `V20__repair_incomplete_crypto_configuration` 会检查四个 RSA 密钥的 `ACTIVE` 版本数量；集合不完整时只关闭 `crypto.enabled`，不生成、删除或覆盖密钥版本，便于 DEV_OPS 先恢复页面访问，再补齐密钥后手工启用。

接口加解密开关没有显式配置时默认关闭；首次初始化会显式写入 `crypto.enabled=false`。只有 `crypto.enabled=true` 且四个 RSA 密钥均有 `ACTIVE` 版本时才启用。开关只在本页面操作，启用前会刷新并验证密钥运行态；显式开启但密钥缺失时保持 fail-closed，拒绝加密请求和响应，不降级为明文。

## 版本状态

每个注册编码只有一个 `ACTIVE` 版本。创建新版本、导入或一次性迁移都会生成 `PENDING` 版本；显式发布时在同一事务内退役旧版本并启用目标版本。`RETIRED`、`REVOKED` 和 `DESTROYED` 只保留审计元数据，不提供物理删除或覆盖历史版本的入口。

应用运行时通过 `RuntimeSecretProvider` 读取当前 `ACTIVE` 版本，数据库、解密或状态无法确认时 fail-closed。支持热刷新的组件在发布后可通过“刷新运行态”加载；根密钥变化不属于热刷新范围。

## 导入与导出

导出默认包含全部分类的当前 `ACTIVE` 版本，也可以按分类筛选。服务端每次生成一次性高强度口令，使用口令派生 AES-256-GCM 保护独立导出包；口令只在本次响应展示一次，不落库、不写日志、不写审计快照。导出包不绑定环境，可在下一次部署根密钥变化后导入。

导入必须先上传文件和口令执行预校验。预校验只返回编码、来源版本、分类和摘要；未知编码、重复编码等冲突会阻止导入，不覆盖目标环境已有版本。确认导入后所有记录均为 `PENDING`，必须逐项审核和发布。

## 三步迁移

迁移使用显式一次性命令，不在启动时自动执行：

1. `ApplicationSecretMigrationCommand` 迁移应用加密密钥；完成后运行时不再读取旧环境/旧配置入口。
2. `BusinessSecretMigrationCommand` 迁移业务服务凭据；完成后 Provider 只读取统一密钥运行时，非敏感配置仍可保留在普通系统配置中。
3. `SecuritySecretMigrationCommand` 迁移安全签名密钥；完成后验证码、授权变更等服务只从统一密钥运行时取当前版本。

命令接收经人工确认的旧来源快照，只返回迁移数量和编码，并统一写入 `MIGRATION` 来源的待启用版本；旧入口在对应步骤完成后删除，不保留双向读取或回退分支。

## 管理 API

所有端点版本为 `1.0.0`，基础路径为 `/api/security/secrets`，并使用 `@PreAuthorize("hasRole('ROLE_DEV_OPS')")`：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/definitions` | 查询注册定义及当前启用版本脱敏状态 |
| `GET` | `/settings` | 查询接口加解密开关、四个 RSA 密钥运行态和状态；响应保持明文 |
| `POST` | `/settings/crypto` | 修改接口加解密开关；启用前校验四个 RSA 密钥，响应保持明文 |
| `GET` | `/{code}/versions` | 查询版本元数据，不返回密文 |
| `POST` | `/{code}/versions` | 创建待启用版本，必填密钥值 |
| `POST` | `/{code}/versions/{versionId}/publish` | 确认发布，并自动退役原启用版本 |
| `POST` | `/{code}/versions/{versionId}/retire` | 退役当前启用版本 |
| `POST` | `/export` | 导出当前启用版本并返回一次性口令 |
| `POST` | `/import/preview` | 预校验导入包，不写库 |
| `POST` | `/import` | 导入为待启用版本，不覆盖历史 |
| `POST` | `/refresh` | 刷新支持热加载的本地运行态 |

导入包大小限制为 2 MiB。导出、导入、创建、发布、退役和刷新均写安全审计；审计只能保存脱敏元数据，禁止保存明文、密文、导出口令和导入口令。
