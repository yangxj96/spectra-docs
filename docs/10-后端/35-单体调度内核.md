# 单体调度内核

> `spectra-core` 提供的统一调度能力。调度器与业务 API 运行在同一个单体应用中，PostgreSQL 保存任务定义、租约、执行状态、循环会话、控制命令、操作审计和错误聚合，是唯一事实源；Redis 只用于既有安全域能力和可选加速，不参与调度正确性判断。

## 模块边界

调度公共契约位于 `spectra-common/common.scheduler`，包括离散任务处理器、LOOP 处理器、任务描述、执行上下文和结果类型。调度内核位于 `spectra-core/core.scheduler`，负责注册表、时区解析、启动门禁、到期派发、执行租约、循环会话、管理用例和管理接口；业务模块只通过注册处理器接入。

可执行能力只能来自代码注册的处理器。管理端不接受 Bean 名称、类名、方法名、SQL、脚本或反射信息。

## 任务类型与内置任务

| 类型 | 适用场景 | 运行方式 | 管理边界 |
|---|---|---|---|
| `OPS` | 可由运维配置的业务任务 | Cron、固定延迟或手工 | 可配置、启停、手工触发和安全重试 |
| `SYSTEM` | 系统内置维护任务 | 代码注册、数据库定义 | 只读和符合策略的受控触发；不可页面改配置、启停或普通重试 |
| `LOOP` | 通知 Worker、监控采集等高频循环 | 持久化会话 + 心跳 | 通过控制命令启动、排空停止、重启、强停和租约回收 |

V4 内置任务：

| job key | 类型 | 范围 | 作用 |
|---|---|---|---|
| `notification.task-worker` | `LOOP` | `PER_INSTANCE` | 领取通知任务并执行渠道投递；普通周期只更新循环计数，错误进入聚合 |
| `notification.cleanup-sensitive-payload` | `SYSTEM` | `SINGLETON` | 清理通知敏感载荷和过期短时数据 |
| `system.monitor.collect-snapshot` | `LOOP` | `PER_INSTANCE` | 采集服务监控快照 |
| `system.monitor.diagnostic-cleanup` | `SYSTEM` | `SINGLETON` | 清理过期监控诊断任务文件 |
| `oa.contract.milestone-reminder` | `OPS` | `SINGLETON` | 按系统时区发送合同履约节点提醒 |

## 启动门禁、时区与生命周期

调度器由 `SchedulerBootstrapService` 实现 `SmartLifecycle` 管理，不使用业务 Spring 定时注解。启用后启动顺序为：读取 V4 调度表、解析系统时区、校验注册表与数据库定义、初始化下一次计划时间、启动内部 tick。内部 tick 使用 JDK 25 虚拟线程执行器，但保持调度入口单线程串行，以保留现有租约和状态机的边界。应用正常停止时，先取消 tick，再按实例身份和会话版本 CAS 将本实例持有的活动 LOOP 会话置为 `STOPPED` 并清除租约；异常退出仍由租约过期回收，不会误停其他实例。任一数据库访问失败时保持 `NOT_READY`，停止新的派发、领取、控制和结果确认；健康检查恢复后重新执行启动门禁。

调度任务时区只取系统设置 `system.default-timezone`：值必须是有效 IANA `ZoneId`；配置缺失或无效时使用 UTC；不使用 JVM 或操作系统默认时区。Cron 的下一次时间保存为 `timestamptz` 对应的 `Instant`，修改系统时区只影响之后计算的计划，不改写已保存的历史执行时间。调度实体不保存独立的时区字段。

任务定义状态为 `REGISTERED`、`UNAVAILABLE`、`ARCHIVED`；期望状态由任务类型决定。启动时找不到代码处理器的定义标记为 `UNAVAILABLE`，不删除定义和历史执行；恢复注册后重新进入 `REGISTERED`。六张调度表保留 `deleted` 字段以满足 `BaseEntity` 结构兼容，但调度查询、状态机、租约和生命周期不读取、不写入该字段，归档使用 `definition_status`。

## 离散执行安全模型

离散执行状态为 `QUEUED`、`RUNNING`、`RETRY_WAIT`、`SUCCEEDED`、`FAILED`、`UNKNOWN`、`SKIPPED`、`CANCELLED`。到期派发在短事务内插入执行记录并推进 `next_fire_at`；`fire_key` 唯一约束保证同一计划不产生重复执行。处理器调用在事务外进行，领取、心跳和结果回写均使用实例、版本和租约 CAS。

外部副作用按至少一次执行处理，处理器使用 `fire_key` 或业务幂等键保证可安全重入。超时、租约过期、处理器异常或数据库故障导致结果无法确认时进入不可覆盖的 `UNKNOWN`；不得自动重试。人工重试创建新的执行记录，保留原执行并通过 `original_execution_id` 关联；人工确认通过 `resolution_status` 记录 `CONFIRMED_SUCCESS`、`CONFIRMED_FAILED` 或 `RETRIED`。

数据库不可用统一返回 HTTP `503` 和错误码 `SCHEDULER_DATABASE_UNAVAILABLE`。已经开始的外部操作不强行中断，无法确认的结果按 `UNKNOWN` 处理。所有写操作携带幂等键和操作原因，并由 `@ULog` 写入现有安全审计链路。

## LOOP 会话与错误日志

LOOP 不为每个周期创建离散执行记录，只维护 `scheduler_loop_runtime` 会话、心跳、租约、累计周期/处理/失败计数和运行状态。运行状态为 `STARTING`、`RUNNING`、`DEGRADED`、`DRAINING`、`STOPPED`、`CRASHED`、`UNKNOWN`。

控制命令先写入 `scheduler_control_command`，再由循环控制器消费并通过 CAS 应用；该表继续是 LOOP 控制命令、控制原因和命令结果的事实源。命令类型为 `START`、`DRAIN_STOP`、`RESTART`、`FORCE_STOP`、`FORCE_RECLAIM`。普通周期不输出成功日志；重复错误按任务、实例和错误指纹聚合，使用 `errorLogIntervalMs` 限制日志频率，并保存出现次数和抑制次数。错误正文只保存脱敏内容。

OPS/SYSTEM 的创建、修改、启停、归档/重新注册、手工触发、重试、取消和 UNKNOWN 解决，在同一管理事务中写入 `scheduler_operation_audit`。该表只记录管理操作的原因、幂等键、申请人、状态和结果；LOOP 控制命令不重复写入该表。管理端通过统一操作记录查询将两类事实记录合并展示，普通高频循环周期不产生操作记录。

## 数据表

V4 一次性迁移文件为 `spectra-config/src/main/resources/db/migration/V4__create_scheduler_tables.sql`，创建五张基础调度表；V6 迁移文件 `V6__create_scheduler_operation_audit.sql` 新增操作审计表。表均位于 `spectra_core`：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `scheduler_job` | 任务定义、代码处理器、调度策略和期望状态 | `job_key` 唯一；类型、范围、状态和计划定义由 CHECK 约束保护 |
| `scheduler_execution` | 离散执行、快照、租约、结果和 UNKNOWN 解决状态 | `fire_key` 唯一；任务和原始执行外键使用 `ON DELETE RESTRICT` |
| `scheduler_loop_runtime` | LOOP 会话、心跳、租约和累计指标 | `session_key` 唯一；会话状态与计数由 CHECK 约束保护 |
| `scheduler_control_command` | LOOP 控制命令及幂等处理结果 | `idempotency_key` 唯一；命令先持久化后应用 |
| `scheduler_loop_error` | LOOP 错误指纹聚合与日志限流 | `(job_id, instance_id, error_fingerprint)` 唯一 |
| `scheduler_operation_audit` | OPS/SYSTEM 管理操作原因、状态和结果 | `idempotency_key` 唯一；关联任务和可选执行 |

所有时间字段使用 PostgreSQL `timestamp(6) with time zone`，Java 使用 `Instant`；JSONB 通过 `PgJsonbTypeHandler` 显式映射。表保留 `deleted`，其含义仅为公共实体结构兼容。

### 字段说明

V5 迁移为五张基础调度表补充表级和字段级注释，V6 为操作审计表同步提供注释。以下字段语义与数据库注释保持一致，`deleted` 在所有表中仅为 `BaseEntity` 兼容字段，调度业务不读取、不写入。

| `run_scope` | 运行范围：`PER_INSTANCE` 每实例运行、`SINGLETON` 单实例运行 |

## 管理 API

控制器：`spectra-core/core/scheduler/controller/SchedulerAdminController`，公共 URL 前缀为 `/api/scheduler/admin`，API 版本为 `1.0.0`。

| 方法 | 路径 | 权限 | 作用 |
|---|---|---|---|
| `GET` | `/catalog` | `system:scheduler:query` | 查询代码注册处理器目录 |
| `GET` | `/jobs` | `system:scheduler:query` | 查询任务定义 |
| `POST` | `/jobs` | `system:scheduler:manage` | 创建 OPS 任务定义 |
| `PUT` | `/jobs/{id}` | `system:scheduler:manage` | 修改 OPS 任务定义 |
| `POST` | `/jobs/{id}/enable` | `system:scheduler:manage` | 启用 OPS 任务 |
| `POST` | `/jobs/{id}/disable` | `system:scheduler:manage` | 停用 OPS 任务 |
| `POST` | `/jobs/{id}/archive` | `system:scheduler:manage` | 归档 OPS 任务 |
| `POST` | `/jobs/{id}/trigger` | `system:scheduler:execute` | 手工触发离散任务 |
| `GET` | `/executions`、`/executions/{id}` | `system:scheduler:query` | 查询执行列表和详情 |
| `POST` | `/executions/{id}/retry` | `system:scheduler:retry` | 重试允许的 FAILED/UNKNOWN 执行 |
| `POST` | `/executions/{id}/cancel` | `system:scheduler:execute` | 取消尚未开始的离散执行 |
| `POST` | `/executions/{id}/resolve` | `system:scheduler:resolve` | 解决 UNKNOWN 原始执行状态 |
| `GET` | `/loops` | `system:scheduler:query` | 查询 LOOP 会话 |
| `POST` | `/loops/{jobId}/commands` | `system:scheduler:control` | 提交 LOOP 控制命令 |
| `GET` | `/loops/{jobId}/commands` | `system:scheduler:query` | 查询 LOOP 控制命令、控制原因和处理结果 |
| `GET` | `/jobs/{jobId}/operations` | `system:scheduler:query` | 统一查询 OPS/SYSTEM 操作审计和 LOOP 控制命令记录 |
| `GET` | `/loops/{jobId}/errors` | `system:scheduler:query` | 查询 LOOP 错误聚合 |

`ROLE_ADMIN_SYSTEM` 拥有查询、OPS 管理、安全执行、普通重试和普通 LOOP 控制；`ROLE_DEV_OPS` 拥有全部调度权限，并负责 SYSTEM 受控触发、UNKNOWN 处理、LOOP 重启/强停/强制回收等高风险动作；`ROLE_AUDIT` 只读查询。服务层会再次校验任务类型、定义状态、处理器声明、版本、幂等键和操作原因。

## Web 运维页面

Web 页面位于 `spectra-ui/src/views/Devops/Scheduler/`，路由为：

- `/devops/scheduler/task`：任务目录、任务定义、OPS 编辑/启停/归档、离散手工触发和 LOOP 会话入口。
- `/devops/scheduler/execution`：执行查询、详情、取消、FAILED/UNKNOWN 重试和 UNKNOWN 解决。
- 任务列表：三类任务统一提供“操作记录”入口，在独立弹窗中展示任务操作审计和 LOOP 控制命令的操作、来源、状态、控制原因和处理结果。
- LOOP 运行面板：展示会话心跳、累计计数、错误聚合和实时控制入口；控制命令历史统一从任务列表的“操作记录”查看，不在运行面板重复展示。

页面只展示注册目录声明的参数和动作，不提供动态执行入口。
