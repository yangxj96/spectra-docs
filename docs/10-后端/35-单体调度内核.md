# Quartz 调度内核

> `spectra-core` 使用 Quartz JDBC JobStore 承担定时任务调度。Quartz 的 `QRTZ_*` 表是调度状态、集群锁、JobDetail 和 Trigger 的唯一事实源；应用自有 `spectra_core.quartz_job_execution_history` 只记录执行观测和脱敏结果，不复制 Quartz 调度状态。

## 模块边界

Quartz 基础设施位于 `core.quartz`，执行历史实体、Mapper 和 Service 分别位于 `core.quartz.javabean`、`core.quartz.mapper` 和 `core.quartz.service`，实际业务 Job 放在所属功能包的 `job` 子包中。跨模块共享的 `QuartzJobDefinition`、`QuartzBuiltInJobDefinition`、`QuartzTriggerTemplate` 和 `QuartzParameterSchema` 位于 `common.port.quartz`；`QuartzJobCatalog` 只收集代码白名单定义，`QuartzJobRegistrar` 只在启动时补齐缺失的内置资源，`QuartzJobManagementService` 是管理 API 使用 Quartz 的唯一应用入口。

可执行能力只能来自代码注册的 `QuartzJobDefinition`。请求和数据库中都不接受 Bean 名称、任意类名、方法名、SQL、脚本或反射信息。JobDataMap 只保存白名单类型键、参数 schema 版本、校验后的非敏感参数 JSON 和摘要。

## 运行模型

```text
代码白名单 Job 定义
        │
        ├── SpringQuartzJobFactory 创建 Spring 管理的 Quartz Job
        │
        └── QRTZ_JOB_DETAILS ── 1:1 ── QRTZ_TRIGGERS
                                      │
                         spectra_quartz.QRTZ_* JDBC Cluster
                                      │
                         Quartz JobListener 采集执行结果
                                      │
                    spectra_core.quartz_job_execution_history
```

- 使用 Spring Boot 管理的 Quartz 版本和 `LocalDataSourceJobStore`，共享应用 PostgreSQL DataSource。
- `spectra_quartz` 是独立 schema，表前缀固定为 `spectra_quartz.QRTZ_`；不使用内存 JobStore，不创建第二个数据源。
- 开启 Quartz JDBC Cluster、数据库锁和 `instanceId=AUTO`；多个应用实例共同消费同一组 Trigger。
- `auto-startup=false`，由 `QuartzSchedulerLifecycle` 在应用完成基础装配后启动。数据库不可用时生命周期保持 `NOT_READY` 并按配置重试，管理 API 和 Job 执行均 fail-closed。
- 应用停止时取消恢复重试并调用 `shutdown(true)`，等待运行中的 Job 完成；Job 使用 `@DisallowConcurrentExecution` 时同一 Job 不并发。
- `requestsRecovery=false`，节点故障后的执行由 Quartz 持久化状态和下一次 Trigger 计划处理，不自动伪造恢复执行。

## Job 白名单和内置任务

每个定义包含稳定 `typeKey`、展示名、受信任 Job 类、参数 schema、内置标识和可选默认 Trigger。启动注册是 add-only：只创建缺失的内置 JobDetail/Trigger，不覆盖管理员已有的名称、参数、暂停状态或 Trigger 修改。

| typeKey | Job 作用 | 默认 Trigger |
|---|---|---|
| `notification.task-worker` | 批量领取并处理通知投递任务 | 每 5 秒 Simple |
| `notification.cleanup-sensitive-payload` | 清理通知中的过期敏感载荷 | 每 1 小时 Simple |
| `file.upload.cleanup` | 清理过期上传会话、孤儿资产和暂存对象 | 每 5 分钟 Simple |
| `system.monitor.collect-snapshot` | 采集系统服务监控快照 | 每 10 秒 Simple |
| `system.monitor.diagnostic-cleanup` | 清理过期运行时诊断文件 | 每 1 小时 Simple |
| `system.operation-log.outbox` | 消费普通操作日志 Outbox | 每 5 秒 Simple |
| `security.security-change.outbox` | 消费安全变更 Outbox | 每 5 秒 Simple |
| `security.security-audit.archive` | 处理安全审计归档 manifest | 每 10 秒 Simple |
| `system.scheduler.execution-history-cleanup` | 收敛超时历史并删除过期终态记录 | UTC 每日 02:00 Cron |
| `oa.contract.milestone-reminder` | 发送合同履约节点提醒 | UTC 每日 01:00 Cron |

内置 Job 位于 `SPECTRA_BUILTIN` 分组，普通管理端创建的 Job 位于 `SPECTRA_ADMIN` 分组。普通 Job 的 JobKey 由服务端生成；一个 Job 必须且只能绑定一个 Trigger。Trigger 只允许 Cron 和 Simple：Simple 可以是一次性或固定间隔。

## Trigger、时区和 misfire

Cron 请求必须同时提供 Quartz Cron 表达式和 IANA 时区（例如 `Asia/Shanghai`）；Simple 请求必须选择一次性或提供正数毫秒间隔。所有 Trigger 经过 `QuartzTriggerTemplate` 校验后才交给 Quartz。

支持的 misfire 策略为 `DO_NOTHING`、`FIRE_ONCE_NOW`、`NEXT_WITH_REMAINING_COUNT`。Quartz 以绝对时间维护 Trigger，Cron 自身保留 IANA 时区；接口 VO 的时间字段使用 `LocalDateTime`，由 `TimeMapper` 按当前用户时区转换后返回，不使用 JVM 默认时区。立即触发调用 Quartz `triggerJob(JobKey)`，不创建新的 Trigger，也不改变已有计划。

## 执行历史

`QuartzExecutionHistoryJobListener` 在 Job 开始、执行前否决和完成时写入 `spectra_core.quartz_job_execution_history`。监听器是 fail-open 的：历史写入失败只递增 `quartz_execution_history_write_failure_total` 并记录脱敏标识，不阻断 Quartz 业务 Job。状态只有：

| 状态 | 含义 | 终态 |
|---|---|---|
| `RUNNING` | 已收到开始回调，尚未收到完成回调 | 否 |
| `SUCCEEDED` | Job 正常完成 | 是 |
| `FAILED` | Quartz 回调带有执行异常 | 是 |
| `VETOED` | Job 在执行前被 JobListener/策略否决 | 是 |
| `ABANDONED` | 超过运行租约仍未收到完成回调 | 是 |

`fire_instance_id` 唯一约束保证重复回调幂等。结果只保存固定字段、非敏感参数 SHA-256、脱敏摘要和稳定错误编码，不保存完整 JobDataMap、参数原文、凭据或外部异常堆栈。每日清理 Job 先将超过 `history-running-timeout` 的 `RUNNING` 标记为 `ABANDONED`，再按 `history-retention-days` 分批物理删除终态记录。

### 历史表数据库标准

历史表是应用自建表，不使用 Quartz 表替代。它严格遵守项目数据库规范：物理字段顺序为 `id -> 业务字段 -> 审计字段`，时间字段为 `TIMESTAMP(6) WITH TIME ZONE`，UUID 主键使用 `BaseEntity`，公共审计字段固定放在最后：

```text
created_by -> created_at -> updated_by -> updated_at -> deleted -> version
```

`deleted` 保留为 `BaseEntity` 兼容字段，历史清理直接物理删除，查询和状态回写不依赖该字段；`version` 默认 0，用于状态回写的乐观锁语义。主键、唯一键、检查约束和索引遵循项目的 `pk_`、`uk_`、`ck_`、`idx_` 命名约定。

`V15__create_quartz_execution_history.sql` 为表和每一个字段提供数据库注释，字段含义如下：

| 字段 | 含义 |
|---|---|
| `id` | 执行历史 UUID 技术主键；应用写入由 `MetaObjectHandler` 生成 UUID v7，数据库 `uuidv7()` 作为原生写入兜底 |
| `fire_instance_id` | Quartz 单次触发实例的唯一标识 |
| `job_key`、`trigger_key` | 本次执行对应的 Quartz JobKey 和 TriggerKey 字符串 |
| `job_type` | 代码白名单中的任务类型键 |
| `job_class_name` | 实际执行的受信任 Job 类名，仅用于诊断展示 |
| `trigger_type` | 触发类型，例如 `CRON`、`SIMPLE` 或 `MANUAL` |
| `status` | `RUNNING`、`SUCCEEDED`、`FAILED`、`VETOED`、`ABANDONED` |
| `scheduled_fire_at` | Quartz 原计划触发时间 |
| `actual_fire_at` | Quartz 实际触发时间 |
| `started_at`、`finished_at` | Job 开始和结束时间；终态必须有结束时间 |
| `duration_ms` | Job 执行耗时，单位毫秒，不允许负数 |
| `scheduler_instance` | 执行该 Job 的 Quartz 实例标识 |
| `correlation_id` | 应用请求或后台流程关联标识 |
| `parameter_version` | 参数 schema 版本 |
| `parameter_sha256` | 校验后非敏感参数的 SHA-256 摘要，不是参数原文 |
| `result_summary` | 脱敏后的执行结果摘要 |
| `error_code`、`error_message` | 脱敏后的稳定错误编码和错误说明 |
| `created_by`、`created_at` | 创建人主键和创建时间；系统调度创建人可为空 |
| `updated_by`、`updated_at` | 最后更新人主键和最后更新时间；系统内部变更更新人可为空 |
| `deleted` | `BaseEntity` 兼容字段；历史清理不通过该字段软删除或过滤 |
| `version` | 乐观锁版本号；历史状态回写使用版本控制语义 |

## 数据库迁移

| 迁移 | 作用 |
|---|---|
| `V14__create_quartz_schema.sql` | 创建 `spectra_quartz` schema、完整 Quartz 2.5.2 PostgreSQL JobStore 表、外键、官方索引以及表/字段注释 |
| `V15__create_quartz_execution_history.sql` | 创建 Core 自有执行历史表、完整审计字段、状态/时间/耗时约束、查询索引以及表/字段注释 |
| `V16__drop_legacy_scheduler_tables.sql` | 按依赖顺序删除旧 `scheduler_*` 表；不迁移旧任务定义、执行、LOOP、命令、错误或操作审计数据 |

历史迁移链中的 `V4`、`V5`、`V6`、`V10` 保留为已执行版本事实；新环境会先按历史迁移创建/注册旧表数据，再由 `V16` 明确删除，不从旧模型回读或建立兼容别名。

## 管理 API

控制器为 `core.quartz.controller.QuartzAdminController`，公共 URL 前缀为 `/api/scheduler/quartz`，接口版本均为 `1.0.0`：

| 方法 | 路径 | 权限 | 作用 |
|---|---|---|---|
| `GET` | `/job-types` | `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS`、`ROLE_AUDIT` | 查询白名单 Job 类型、参数 schema 和 Trigger 能力 |
| `GET` | `/jobs`、`/jobs/{jobKey}` | 同上 | 查询 JobDetail 和唯一 Trigger |
| `POST` | `/jobs` | `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS` | 创建普通 Job |
| `PUT` | `/jobs/{jobKey}` | `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS` | 修改普通 Job 名称、参数和 Trigger |
| `DELETE` | `/jobs/{jobKey}` | `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS` | 删除普通 Job 和 Trigger；内置 Job 拒绝 |
| `POST` | `/jobs/{jobKey}/pause`、`/resume` | `ROLE_ADMIN_SYSTEM`、`ROLE_DEV_OPS` | 暂停或恢复 Job |
| `POST` | `/jobs/{jobKey}/trigger` | `ROLE_DEV_OPS` | 使用现有 JobDataMap 立即触发一次 |
| `GET` | `/triggers/{triggerKey}` | 三类角色 | 查询 Trigger 安全详情 |
| `GET` | `/execution-history`、`/{id}` | 三类角色 | 查询执行历史分页和详情 |

`ROLE_AUDIT` 只有查询权限；`ROLE_ADMIN_SYSTEM` 负责普通 Job 管理；`ROLE_DEV_OPS` 负责立即触发和内置 Job 相关高风险操作。Quartz/数据库不可用统一返回 HTTP `503` 和 `SCHEDULER_DATABASE_UNAVAILABLE`，不返回连接串、凭据或数据库异常原文。

## Web 页面

页面位于 `spectra-ui/src/views/Devops/Scheduler/`：

- `Task` 页面展示 JobKey、白名单类型、唯一 Trigger、状态、暂停/恢复、编辑、删除、立即触发和历史入口。
- `TaskEdit` 只展示服务端返回的 Job 类型和参数 schema，提供版本化 JSON 参数、Cron/Simple、一次性/固定间隔、IANA 时区和 misfire 配置。
- `Execution` 页面只查询 `RUNNING`、`SUCCEEDED`、`FAILED`、`VETOED`、`ABANDONED` 历史及脱敏详情；不提供旧 LOOP、UNKNOWN、retry、cancel 或 resolve 操作。
