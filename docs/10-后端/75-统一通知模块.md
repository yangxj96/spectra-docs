# 统一通知模块

`spectra-notification` 是通知领域的独立 Maven 模块，包名为
`com.devops00.spectra.notification`，由 `spectra-launch` 装配。业务模块只通过
`spectra-common.notification.NotificationGateway` 提交通知请求，不直接写通知表或依赖渠道实现。

## 当前边界

- PostgreSQL schema 为 `spectra_notification`，表前缀为 `ntf_`。
- `ntf_request` 表示一次逻辑通知，`ntf_task` 表示“接收人 × 渠道”任务，`ntf_delivery` 保存投递尝试。
- `ntf_inbox_message` 是消息中心的站内收件箱，`ntf_user_preference` 保存用途 × 渠道偏好，`ntf_template` 保存模板。
- `IN_APP` 由定时 Worker 投递，并使用 `task_id` 幂等写入收件箱；SMS/EMAIL 使用占位 Sender，返回 `CHANNEL_NOT_CONFIGURED`，不会伪装成成功。
- SMS/EMAIL 的 Provider 示例位于 `spectra-notification/src/test/java/.../service/impl/MockSmsSender.java` 和 `MockEmailSender.java`，只在测试类路径中生效，不会进入生产运行时。
- Core 提供收件人目录适配器，只返回启用用户和已验证的手机号/邮箱；直接地址只允许安全用途，并在 Request/Task 中使用 AES-GCM 密文存储。
- 收件人目录在展开业务受众前执行当前用户数据范围：`SELF` 只允许本人，`GLOBAL` 允许显式收件人，部门/自定义范围只允许解析到范围内的用户；系统任务无认证上下文时仅接受调用方显式用户 ID，不把全局或部门范围扩展为私人收件箱可见性。
- Worker 使用 `FOR UPDATE SKIP LOCKED`、处理租约超时恢复、CAS 抢占、指数退避、过期跳过和 Request 状态汇总。
- 提供低基数 `NotificationMetrics` 指标门面、`notification` 健康检查和批量敏感密文清理任务；清理只处理终态/过期记录，不输出业务正文、地址或用户标识。
- `NotificationPostgresIntegrationTest` 提供 10 项真实 PostgreSQL 回归（事务回滚、并发幂等、任务/站内信唯一约束、双 Worker 锁领取、租约恢复 CAS、过期过滤、敏感密文清理、关键索引和旧消息/偏好迁移）；仅在设置 `SPECTRA_NOTIFICATION_POSTGRES_TEST=true` 并提供 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 时启用。
- 免打扰窗口由 `NotificationDoNotDisturbPolicy` 按用户本地时间判断，支持跨午夜；Core 收件人目录同步提供用户时区，偏好 API 按当前用户时区解析和回显开始/结束时间。
- 管理端提供 Request/Task/Delivery 脱敏分页、失败任务重试、未完成任务取消和渠道可用性查询。
- 包结构按简单模块扁平分层：Controller 统一位于 `controller`，Entity/From/VO/Converter 位于 `javabean` 对应子包，Mapper 位于 `mapper`，Service 接口与实现位于 `service`、`service/impl`，配置与属性分别位于 `configuration`、`properties`。
- 六个通知实体统一继承 `BaseEntity`，所有 JSONB 字段显式使用 `PgJsonbTypeHandler`；表结构以 `docs/sql/spectra_notification/建表.sql` 为唯一契约，包含审计字段、软删除、乐观锁和标准约束/索引命名。

## 公共请求

`NotificationRequest` 是不可变请求，包含 `requestId`、`idempotencyKey`、`purpose`、渠道、用户收件人、受限直接地址、模板组、非敏感参数、敏感参数、业务弱引用和站内跳转链接。普通参数禁止出现验证码、密码、Token 等敏感字段；敏感参数和外部地址由通知模块使用 AES-GCM 加密后才落库，缺少密钥时入队失败。

用途和渠道分离：用途使用 `NotificationPurpose`，渠道使用 `NotificationChannel`。安全用途不能由普通偏好关闭；普通用途默认使用 `IN_APP`，用户偏好只影响可选渠道。

### 验证码安全契约

验证码只在生成和调用 Provider 的短暂内存中以明文存在。Redis 仅保存基于
`SECURITY_VERIFICATION_CODE_HMAC_KEY` 的 HMAC-SHA256 摘要，并使用
`SECURITY_VERIFICATION_CODE_MAX_ATTEMPTS` 限制校验次数；成功、过期、超限或投递失败都会清理摘要和尝试计数。相同渠道、地址和有效期窗口通过
`setIfAbsent` 与稳定幂等键去重，禁止自动重试 `UNKNOWN` Task。Request、Task、Delivery、日志、指标和 API 响应均不得包含验证码明文。

### 链接白名单

站内消息链接默认只允许 `/login`、`/auth/`、`/oa/`、`/workflow/`、`/notification/`、
`/notification-center/`、`/system/`、`/file/` 和 `/ai/`；系统设置引导会将白名单保存到
`spectra_core.sys_config` 的 `notification.allowed-link-prefixes`。Gateway 对外部 URL、协议相对 URL、反斜杠、路径穿越和编码后的 `..` 一律拒绝，并对未命中白名单的相对路径 fail-closed。

## 消息中心 API

当前用户 ID 始终从认证上下文取得，Self API 不接收 `userId`，Service 层的查询、已读和删除条件均包含收件人和软删除条件。通知模块不使用已移除的 `tenant_id` 字段。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/notification/list` | 当前用户分页查询；支持 `purpose`、`is_read`、关键词和时间参数 |
| GET | `/notification/{id}` | 当前用户消息详情 |
| GET | `/notification/unread-count` | 当前用户未读数 |
| PUT | `/notification/{id}/read` | 标记当前用户的一条消息已读 |
| PUT | `/notification/read-all` | 当前用户全部已读 |
| DELETE | `/notification/{id}` | 删除当前用户的一条消息 |
| POST | `/notification/batch-delete` | 仅删除当前用户拥有的批量 ID |
| GET/PUT | `/notification-center/preferences` | 用途 × 渠道偏好矩阵 |

## 管理端 API

管理端 API 只返回脱敏字段，`ROLE_AUDIT` 可只读查询，重试和取消仅限 `ROLE_DEV_OPS`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/notification/admin/channels/{channel}` | 查询 `IN_APP`、`SMS` 或 `EMAIL` 的可用状态和脱敏原因 |
| GET | `/notification/admin/requests` | 分页查询逻辑 Request |
| GET | `/notification/admin/tasks` | 分页查询投递 Task |
| GET | `/notification/admin/deliveries` | 分页查询投递尝试 |
| POST | `/notification/admin/tasks/{id}/retry` | 显式重试 FAILED/BLOCKED/UNKNOWN Task |
| DELETE | `/notification/admin/tasks/{id}` | 取消尚未完成的 Task |

任何不属于当前用户的消息都按“消息不存在”处理，不因为全局或部门权限扩大收件箱可见范围。

## 调用方迁移

Security 验证码、OA 的会议/公告/文档/请假/采购/报销/合同提醒、Workflow 待办与审批结果、AI RAG 索引结果均通过公共 Gateway，并使用稳定幂等键。Core 中旧的通知 Entity、Mapper、Service、Controller 和 Mapper XML 已移除；旧 `spectra_core.sys_notification` 与 `sys_notification_setting` 仅存在于离线迁移脚本，当前 V1 运行库不再保留。

当前干净基线的通知运行表直接由 Flyway V1 创建，旧 Core 通知表不再进入目标结构；`docs/sql/spectra_notification/建表.sql` 仅作为结构审查参考，后续读写只使用 `spectra_notification`。
