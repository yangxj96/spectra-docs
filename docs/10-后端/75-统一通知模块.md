# 统一通知模块

`spectra-notification` 是通知领域的独立 Maven 模块，包名为
`com.devops00.spectra.notification`，由 `spectra-launch` 装配。业务模块只通过
`spectra-common.notification.NotificationGateway` 提交通知请求，不直接写通知表或依赖渠道实现。

## 当前边界

- PostgreSQL schema 为 `spectra_notification`，表前缀为 `ntf_`。
- `ntf_request` 表示一次逻辑通知，`ntf_task` 表示“接收人 × 渠道”任务，`ntf_delivery` 保存投递尝试。
- `ntf_inbox_message` 是消息中心的站内收件箱，`ntf_user_preference` 保存用途 × 渠道偏好，`ntf_template` 保存模板。
- `IN_APP` 已实现并使用 `task_id` 幂等写入收件箱；SMS/EMAIL 使用占位 Sender，返回 `CHANNEL_NOT_CONFIGURED`，不会伪装成成功。
- 外部渠道任务由 PostgreSQL 任务表和定时 Worker 处理；当前仍缺少完整的地址目录、敏感载荷加密、锁超时恢复、指数退避、管理 API 和真实渠道 Provider。

## 公共请求

`NotificationRequest` 是不可变请求，包含 `requestId`、`idempotencyKey`、`purpose`、渠道、收件人、模板组、非敏感参数、业务弱引用和站内跳转链接。`sensitiveParameters` 已预留，但当前实现拒绝敏感载荷，验证码仍由 Security 计划负责接入和保护。

用途和渠道分离：用途使用 `NotificationPurpose`，渠道使用 `NotificationChannel`。安全用途不能由普通偏好关闭；普通用途默认使用 `IN_APP`，用户偏好只影响可选渠道。

## 消息中心 API

当前用户 ID 始终从认证上下文取得，Self API 不接收 `userId`，Service 层的查询、已读和删除条件均包含租户、收件人和软删除条件。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/notification/list` | 当前用户分页查询；兼容旧的 `type`、`is_read`、关键词和时间参数 |
| GET | `/notification/{id}` | 当前用户消息详情 |
| GET | `/notification/unread-count` | 当前用户未读数 |
| PUT | `/notification/{id}/read` | 标记当前用户的一条消息已读 |
| PUT | `/notification/read-all` | 当前用户全部已读 |
| DELETE | `/notification/{id}` | 删除当前用户的一条消息 |
| POST | `/notification/batch-delete` | 仅删除当前用户拥有的批量 ID |
| GET/PUT | `/notification/setting` | 旧设置 API 兼容门面 |
| GET/PUT | `/notification-center/preferences` | 用途 × 渠道偏好矩阵 |

`/notification-center/inbox/**` 继续作为消息中心旧路径别名。任何不属于当前用户的消息都按“消息不存在”处理，不因为全局或部门权限扩大收件箱可见范围。

## 调用方迁移

OA 的会议、公告、文档、请假、采购、报销和合同提醒已改用公共 Gateway，并为业务事件提供稳定幂等键。Core 中旧的通知 Entity、Mapper、Service、Controller 和 Mapper XML 已移除；旧 `spectra_core.sys_notification` 与 `sys_notification_setting` 只作为迁移来源保留。

迁移脚本位于 `docs/sql/spectra_notification/迁移/`，支持重复执行，不会删除旧数据。建表和迁移完成后，需按用户核对消息总数、未读数和抽样数据，再切换旧表的读写所有权。
