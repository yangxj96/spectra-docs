# 数据权限设计

> 二维数据权限过滤框架，基于 MyBatis-Plus DataPermissionInterceptor 自动注入 WHERE 条件。
> 当前实现已完成安全基线收敛：请求内只解析一次范围，缺失/空范围 fail-closed，手动绕过必须经过受控执行器。
>
> 模块：`spectra-common` + `spectra-framework` + `spectra-core`

## 数据范围类型

```java
public enum DataScopeType {
    GLOBAL(0, "全局"),              // 超管赋予，查看所有数据
    SELF(1, "本人"),                // 只能看自己创建的
    DEPT(2, "部门"),                // 看本部门数据
    DEPT_AND_CHILDREN(3, "部门及子部门"), // 本部门+所有子部门
    CUSTOM(4, "自定义");            // 手动指定可见部门
}
```

## 设计规则

| 规则 | 说明 |
|---|---|
| 用户覆盖角色 | `sys_user_data_scope` 有值时，忽略角色级别的 `sys_role_data_scope`；用户范围为 `null` 时表示继承角色 |
| 多角色取最大 | 用户未自定义时，遍历所有角色 scope，取范围最大者（GLOBAL > DEPT_AND_CHILDREN > DEPT > CUSTOM > SELF） |
| GLOBAL 仅超管赋予 | GLOBAL 只能由超管分配给特定用户/角色，管理员默认无 GLOBAL |
| SYS_ 表不过滤 | SYS_ 前缀系统表不参与数据范围过滤 |
| 无 `@DataScope` 不拦截 | Entity 上无 `@DataScope` 注解的表不注入 WHERE |
| fail-closed | 已标注实体但无法取得当前用户/有效范围时拒绝执行；CUSTOM/DEPT 空目标生成恒假条件 |
| 手动扩展 | 仅允许 `ROLE_DEV_OPS` 或 `*` 权限通过 `DataScopeExecutor.withoutScope(...)` 在 lambda 作用域内绕过 |
| 写入归属 | `MetaObjectHandlerImpl` 对声明 `departmentId` 的实体自动填充当前用户部门；会议服务同时强制发起人和部门归属 |

## 二维过滤模型

```
结构维度（部门归属）                   关系维度（多对多关联）
─────────────────                   ─────────────────
SELECT * FROM oa_meeting            SELECT * FROM oa_meeting
WHERE (                              WHERE (
    department_id IN (dept_ids)         ...
    OR created_by = current_user        OR id IN (
)                                           SELECT meeting_id FROM oa_meeting_participant
    ┌─ DEPT → 本部门                        WHERE user_id = ?
    ├─ DEPT_AND_CHILDREN → 本+子部门      )
    ├─ SELF → created_by              )
    └─ CUSTOM → 指定目标
```

## `@DataScope` 注解

```java
@Documented
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {

    /**
     * 结构维度过滤字段名，默认 department_id
     */
    String column() default "department_id";

    /**
     * SELF 范围的归属字段，默认 created_by；明细表可指定 user_id
     */
    String ownerColumn() default "created_by";

    /**
     * 是否忽略（SYS_ 表等）
     */
    boolean ignore() default false;

    /**
     * 关系维度——关联表
     */
    Relation[] relations() default {};

    @interface Relation {
        String schema() default "";           // 关联表 schema
        String table();                    // 关联表名
        String joinColumn();              // 关联表的外键字段
        String userColumn() default "user_id"; // 关联表的用户ID字段
        String mainColumn() default "id"; // 主表用于 IN 匹配的列
    }
}
```

### 使用示例

```java
// 仅结构维度
@DataScope
public class Asset extends BaseEntity { }

// 部门范围使用 department_id，本人范围使用 user_id
@DataScope(column = "department_id", ownerColumn = "user_id")
public class MeetingParticipant extends BaseEntity { }

// 结构 + 参会人关系
@DataScope(relations = {
    @DataScope.Relation(
        schema = "spectra_oa",
        table = "oa_meeting_participant",
        joinColumn = "meeting_id",
        userColumn = "user_id"
    )
})
public class Meeting extends BaseEntity { }

// 跨表关联（会议纪要通过 meeting_id 而非 id 匹配）
@DataScope(column = "department_id", relations = {
    @DataScope.Relation(
        table = "oa_meeting_participant",
        joinColumn = "meeting_id",
        userColumn = "user_id",
        mainColumn = "meeting_id"
    )
})
public class MeetingRecord extends BaseEntity { }
```

## OA 实体策略表

| Entity | 表名 | 结构维度 | 关系维度 |
|---|---|---|---|
| Asset | `oa_asset` | `department_id` | 无 |
| AttendanceRecord | `oa_attendance_record` | `department_id` | 请假申请审批通过后生成 |
| Calendar | `oa_calendar` | `department_id` | 无 |
| Contract | `oa_contract` | `department_id` | 无 |
| Document | `oa_document` | `department_id` | 无 |
| Notice | `oa_notice` | `department_id` | 无 |
| Meeting | `oa_meeting` | `department_id` | `participant.user_id`（参会人可见） |
| MeetingParticipant | `oa_meeting_participant` | `department_id`（SELF 使用 `user_id`） | 无 |
| MeetingRecord | `oa_meeting_record` | `department_id` | `participant` via `meeting_id`（参会人可见纪要） |

组织通讯录复用 Core 用户/部门数据范围，部门统计复用各来源业务实体的数据范围；两者不再维护独立 OA 实体。

## 核心流程

```
请求开始
  │
  └→ DataScopeContextFilter 建立 ThreadLocal 请求上下文
       └→ 首条受保护 SQL 触发 DataScopeResolver.resolve(userId)
            ├─ 查 sys_user_data_scope（有 → 覆盖角色）
            └─ 查 sys_role_data_scope（无 → 多角色取最大，兼容 sys_role.scope）
                 └→ 同一请求复用 EffectiveScope，结束时清理

请求任意 SQL
  │
  └→ DataScopeInnerInterceptor.getSqlSegment()
       ├─ 受控 bypass → return null（仅系统运维 lambda）
       ├─ GLOBAL → return null（不过滤）
       ├─ 缺少用户/范围 → 抛 DataScopeViolationException
       ├─ 无 @DataScope → return null
       ├─ ignore = true → return null
       └─ 生成 WHERE：
            ├─ 结构维度：column IN (targetIds) 或 column = userId
            ├─ 关系维度：mainColumn IN (SELECT joinColumn FROM relationTable WHERE userColumn = ?)
            └─ 两者 OR 连接
```
