# 数据权限设计

> Permission-aware 数据权限过滤框架，基于 MyBatis-Plus DataPermissionInterceptor 自动注入 WHERE 条件。
> 当前实现从 `AuthorizationSnapshot` 读取同一 Permission 的 Access Boundary；缺失 Permission、Boundary、资源策略或当前用户时 fail-closed，手动绕过必须经过受控执行器。
>
> 模块：`spectra-common` + `spectra-framework` + `spectra-core`

## Permission Scope 模式

`AuthorizationSnapshot` 为每个 Permission 独立提供 `NONE`、`ALL`、`SELF`、`RULES` Boundary。旧的
`DataScopeType` 枚举、用户/角色 Scope 表和 DTO 已删除；`@DataScope` 只负责声明资源的读、写、导出
Permission 及归属字段，运行时范围事实来自目标授权表。

当前开发数据库没有需要迁移的历史用户或旧 user-level Scope，因此没有待执行的逐账号 Boundary 映射。只有在未来导入历史业务库时，才允许依据 [[../50-开发指南/SECURITY-Migration-Inventory]] 逐条人工映射；不能把缺失历史数据自动转换为 `ALL` 或 Grant Boundary。

## 设计规则

| 规则 | 说明 |
|---|---|
| Permission-specific | 每个 Permission 独立读取自己的 Access Boundary；不同 Permission 的 Scope 禁止先 UNION 后重组 |
| Assignment-preserving | 多个 Assignment 只在同一 Permission 内 OR 合并，Grant Boundary 不得替代 Access Boundary |
| GLOBAL 仅超管赋予 | `ALL` 只能由统一 Root/授权治理链路赋予，普通管理员默认无 `ALL` |
| SYS_ 表不过滤 | SYS_ 前缀系统表不参与数据范围过滤 |
| 无 `@DataScope` 不拦截 | Entity 上无 `@DataScope` 注解的表不注入 WHERE |
| fail-closed | 已标注实体但无法取得当前用户、Permission、Boundary 或有效范围时拒绝执行；空 Boundary/空部门生成恒假条件 |
| 写读分离 | `readPermission`、`writePermission`、`exportPermission` 必须显式登记；写入和导出不得借用查询权限 |
| IDOR/批量/导出 | 详情、更新、删除、批量和导出调用 `ResourceAuthorizationGuard`，ScopeQuery 必须由服务端从资源事实构造 |
| 手动扩展 | 仅允许 `ROLE_DEV_OPS` 或显式通配权限通过 `DataScopeExecutor.withoutScope(...)` 在单个 lambda 作用域内绕过；业务请求不得默认使用 |
| 写入归属 | `MetaObjectHandlerImpl` 对声明 `departmentId` 的实体自动填充当前用户部门；会议服务同时强制发起人和部门归属 |

## 二维过滤模型

```
结构维度（部门归属）                   关系维度（多对多关联）
─────────────────                   ─────────────────
SELECT * FROM oa_meeting            SELECT * FROM oa_meeting
WHERE (                              WHERE (
    department_id IN (dept_ids)         ...
    OR created_by = current_user        OR id IN (
)                                           SELECT meeting_id FROM oa_meeting_participant
    ┌─ DEPT → 本部门                        WHERE user_id = ?
    ├─ DEPT_AND_CHILDREN → 本+子部门      )
    ├─ SELF → created_by              )
    └─ CUSTOM → 指定目标
```

## `@DataScope` 注解

```java
@Documented
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {

    String readPermission() default "";
    String writePermission() default "";
    String exportPermission() default "";

    /**
     * 结构维度过滤字段名，默认 department_id
     */
    String column() default "department_id";

    /**
     * SELF 范围的归属字段，默认 created_by；明细表可指定 user_id
     */
    String ownerColumn() default "created_by";

    /**
     * 是否忽略（SYS_ 表等）
     */
    boolean ignore() default false;

    /**
     * 关系维度——关联表
     */
    Relation[] relations() default {};

    @interface Relation {
        String schema() default "";           // 关联表 schema
        String table();                    // 关联表名
        String joinColumn();              // 关联表的外键字段
        String userColumn() default "user_id"; // 关联表的用户ID字段
        String mainColumn() default "id"; // 主表用于 IN 匹配的列
        String departmentColumn() default ""; // 关联表的部门归属列
    }
}
```

### 使用示例

```java
// 仅结构维度
@DataScope(readPermission = "oa:asset:read", writePermission = "oa:asset:update")
public class Asset extends BaseEntity { }

// 部门范围使用 department_id，本人范围使用 user_id
@DataScope(readPermission = "oa:meeting:read", writePermission = "oa:meeting:update",
        column = "department_id", ownerColumn = "user_id")
public class MeetingParticipant extends BaseEntity { }

// 结构 + 参会人关系
@DataScope(readPermission = "oa:meeting:read", writePermission = "oa:meeting:update", relations = {
    @DataScope.Relation(
        schema = "spectra_oa",
        table = "oa_meeting_participant",
        joinColumn = "meeting_id",
        userColumn = "user_id"
    )
})
public class Meeting extends BaseEntity { }

// 跨表关联（会议纪要通过 meeting_id 而非 id 匹配）
@DataScope(column = "department_id", relations = {
    @DataScope.Relation(
        table = "oa_meeting_participant",
        joinColumn = "meeting_id",
        userColumn = "user_id",
        mainColumn = "meeting_id"
    )
})
public class MeetingRecord extends BaseEntity { }
```

## OA 实体策略表

| Entity | 表名 | 结构维度 | 关系维度 |
|---|---|---|---|
| Asset | `oa_asset` | `oa:asset:read/update`；`department_id` | 无 |
| Application | `oa_application` | `oa:application:read/update`；`department_id` | 无 |
| Calendar | `oa_calendar` | `oa:calendar:read/update`；`owner_id`/`department_id` | 无 |
| Contract | `oa_contract` | `oa:contract:read/update`；`department_id`/`owner_id` | 无 |
| Document/Folder | `oa_document*` | `oa:document:read/update`；部门/所有者 | Folder 通过文档 Permission |
| Notice | `oa_notice` | `oa:notice:read/update`；`department_id` | 无 |
| Meeting/Participant/Record | `oa_meeting*` | `oa:meeting:read/update`；`department_id` | participant.user_id；Record meeting_id |
| Leave/Attendance | `oa_leave_*` | `oa:leave:read/update`；部门/用户 | 无 |
| Purchase/Receipt/Supply | `oa_purchase*`/`oa_supply_item` | `oa:purchase:read/update`；部门 | Receipt 明细通过父表部门关联 |
| Reimbursement/Item | `oa_reimbursement*` | `oa:reimbursement:read/update`；`department_id` | 无 |

组织通讯录复用 Core 用户/部门数据范围，部门统计复用各来源业务实体的数据范围；两者不再维护独立 OA 实体。

## 核心流程

```
请求开始
  │
  └→ DataScopeContextFilter 建立 ThreadLocal 请求上下文
       └→ 首条受保护 SQL 通过 AuthorizationSnapshotProvider.load(userId)
            └→ JdbcAuthorizationSnapshotLoader 读取 Assignment/Permission/Access Boundary
                 └→ 同一请求复用授权上下文，结束时清理

请求任意 SQL
  │
  └→ DataScopeInnerInterceptor.getSqlSegment()
       ├─ 受控 bypass → return null（仅系统运维 lambda）
       ├─ ALL/NONE Boundary → return null（该 Permission 不需要结构过滤）
       ├─ 缺少用户/Permission/Boundary → 恒假或抛 DataScopeViolationException
       ├─ 无 @DataScope → return null
       └─ ScopeSqlPolicy 生成 WHERE：
            ├─ RULES：column IN (department_ids)，下级部门使用 sys_department_closure
            ├─ SELF：ownerColumn = subjectId
            ├─ 关系维度：mainColumn IN (SELECT joinColumn ...)
            └─ 同一 Permission 的多个 Boundary OR 连接
```

## 关键文件路径

| `JdbcAuthorizationSnapshotLoader` | `spectra-core/.../security/authorization/service/impl/JdbcAuthorizationSnapshotLoader.java` | 从 security schema 读取快照 |
| `MyBatisPlusConfiguration` | `spectra-framework/.../MyBatisPlusConfiguration.java` | 注册拦截器 |
| OA 建表 DDL / 当前 V1 | `docs/sql/spectra_oa/建表.sql`、`spectra-config/db/migration/V1__init_target_schema.sql` | 归属列、关联列和 Scope 查询索引 |
