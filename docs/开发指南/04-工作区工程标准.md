# 工作区工程标准

本标准于 2026-10-03 经逐项讨论确认，是 Spectra 工作区在架构、复杂度、协议、运行保障和验证方面的主标准，人工与 AI 开发使用同一基线。领域文档提供实现细节，AGENTS 提供约束和入口，Skill 提供执行参考；发生冲突时按用户已确认的本标准修正相关入口，不沿用冲突的旧模板。

**状态：标准已确认，集中代码治理尚未完成。** 本文描述目标要求，不证明当前源码、检查配置或测试已经全部达标。实现状态、全量建账、例外和验收见 [[开发指南/05-集中治理与验收|集中治理与验收]] 及 [[开发指南/工程治理/README|工程治理台账]]。

## 1. 目标、范围与采用方式

Spectra 是通用应用底座：新增业务模块在同一工作区开发，由同一应用统一装配和部署。平台能力集中在 Core，只有新增业务功能使用独立模块；不以每项平台能力拆一个 Maven 模块作为默认做法。

范围包括后端 Common、Framework、Core、Launch、构建与部署，Web，公共脚本，以及插件的通用 TypeScript、公共导出、产物、构建和宿主边界。OA、Workflow 和流程相关业务的独立功能、架构及复杂度治理暂缓，暂缓不意味着停用或删除。

公共变更必须先从整个工作区完整分析直接与间接影响，再确定改造和验证范围。分析覆盖依赖、调用链、授权与事务、数据与序列化、前后端协议、装配构建及运行行为。受影响的 OA、Workflow、流程页面和插件同样纳入分析、必要的一致性改造及验收；不能预设只改直接调用方，或只保证一个模块编译。

存量采用**全量建账、一次性集中统一**：在一个集中治理周期内覆盖全部纳入范围，内部可按依赖关系分批执行，最终整体验收。9/28 计划已由用户确认完成，文件是主动移除；不得因计划文件缺失重新列为未完成。

每条规则区分强制要求、默认做法、适用例外和验证方式。改变已经确认的架构、协议或验收基线，需重新与用户明确讨论；普通实现选择及有效的定点例外按本标准执行，不增设逐项用户审批流程。

## 2. 职责、分层与抽象

- Launch 是统一装配与启动入口；业务模块依赖必要的 Framework 技术能力及 Common 公共契约。Common 不反向承载 ORM、Web 或数据库实现。实际依赖图需随公共变更复核。
- 承载用例的应用 Service 统一使用接口 + Impl。实体 CRUD 服务可使用已有 BaseService/BaseServiceImpl；编排或非实体用例按职责组合协作者，不为继承通用 CRUD 绑定无关 Entity。
- Core 内跨域调用公开应用 Service 或必要 Facade 的有业务含义的操作及必要 DTO，禁止直接使用对方 Mapper、Impl 或继承的通用 CRUD。跨 Maven 模块通过公共契约协作，不依赖对方内部 Entity、Mapper 或实现。
- 不默认每域设置 Facade，也不要求 Worker、Policy、Adapter 等内部类一律配置接口。按独立规则、安全或事务边界、外部适配、生命周期、实际复用或已确认的扩展需要提取职责。
- 抽象应能说明必要性、边界和验证方法。避免预设通用扩展引擎、无语义转发链、万能工具类，以及仅为降低指标而创建的包装对象或碎片方法。

## 3. 复杂度与例外

| 指标 | 普通业务代码的评审触发值 | 计数范围 |
|---|---|---|
| 圈复杂度 | 超过 15 | Java 方法、TypeScript 函数，使用各自固定工具口径 |
| NPath | 超过 200 | Java 方法 |
| 控制流嵌套 | 超过 3 层 | 单个函数内的实际控制结构 |
| 显式参数 | 超过 5 个 | 普通方法或函数声明的参数，可选和可变参数也计入 |

新增、实质修改及本次集中治理覆盖的存量代码，超标后必须按职责调整，或登记范围明确、理由充分、可验证的例外。行数、类汇总复杂度、依赖数量及调用层数是评审线索，不设额外的统一硬上限。评审还应检查状态、生命周期、副作用、调用链、修改影响和验证难度。

Java 使用项目固定版本 PMD，TypeScript 使用 ESLint **classic** 圈复杂度口径。对阈值相等与超过一单位的样例校准规则；分析工具升级时重新核对口径。PMD 方法圈复杂度达到报告值即报告，不能直接照抄 ESLint 的最大允许值配置；NPath 等其他规则也需各自验证边界。算法不承诺跨语言完全相同。[PMD design rules](https://docs.pmd-code.org/pmd-doc-7.17.0/pmd_rules_java_design.html)、[ESLint complexity](https://eslint.org/docs/latest/rules/complexity)。

嵌套从函数内顶层控制结构的一层开始，内嵌条件、循环、switch 和异常控制结构逐层累计；连续 else-if 及同级 case、catch/finally 分支本身不额外叠加，分支内新增结构继续累计。函数与回调使用独立计数作用域，同时审查捕获状态和调用链。嵌套三元另做可读性检查，其复杂度仍由相应工具计入。旧 Java 嵌套 if 规则不能证明混合控制流已覆盖，工具覆盖不到的情况登记评审；落地时逐项映射规则与样例，不默认开发自研分析器。[ESLint max-depth](https://eslint.org/docs/latest/rules/max-depth)。

特殊代码按以下规则处理：

- 依赖注入构造器审查依赖职责和聚合程度，不为凑参数上限增加包装层。
- 生成代码验证生成器、输入契约、可复现产物和构建，不套用手写源码阈值。
- 纯结构映射、配置、数据声明、框架装配及测试夹具按职责评审；其中手写业务规则和状态控制仍遵循普通规则，不以整个目录或类名豁免。
- 例外结构化记录具体文件、符号、规则、实测值、必要性、风险、验证依据、责任区域及重新评估条件。实质修改、范围扩大或工具口径变化时重新评估。
- 自动核对例外范围、抑制引用及失效记录，理由和行为证据由评审判断。不得全局调高阈值或整域禁用规则以通过门禁。

## 4. 工具、Java 与模型

保留既有格式和质量工具，配置向本标准对齐。版本以 mise、POM、packageManager 声明和锁文件为事实源；使用原生 PowerShell、项目包装器与 mise 管理的工具。检查命令与自动修复分开，生成和构建应可复现。文档中的旧版本号不覆盖真实配置。

Java 默认构造器注入；特殊生命周期或可选依赖说明依据。Controller 负责协议绑定、入口校验、身份与接口级授权及用例调用；应用 Service 承载用例，持久化层负责数据访问。

Entity 表达持久化数据，Form/Query 表达请求或查询职责，VO 表达响应，必要 DTO 表达跨边界数据。这里的 Form/Query 是职责名称，不自动将现有 `From` 后缀改名；现有具体类名遵循后端命名细则，统一命名变更应显式建账。请求不得直接绑定 Entity，模型按实际边界提供，不机械复制每一层。

结构转换使用既有 MapStruct 或必要的明确手写转换，业务校验和数据库访问由用例或明确的领域协作者承担。映射不能无意覆盖身份、系统控制字段或提交版本，也不能因忽略空值而破坏字段清空契约。

输入对象声明必填、长度、格式和范围等约束，在不可信入口执行；Service 校验关系、跨字段含义、状态和用例规则，数据库约束及原子条件保障并发不变量。内部调用、任务等非 HTTP 入口不能绕过必要校验；复用约束，避免各层复制相同手写判断。

## 5. API、错误与类型契约

API 契约版本保持 `1.0.0`。重构同步迁移所有受影响的仓库内调用方，删除旧入口、别名、回退读取和临时兼容分支；不默认承诺外部历史兼容。

以后端请求、响应定义及**实际序列化**为事实源，导出并验证 OpenAPI，生成 TypeScript 数据与端点类型并自动检查漂移。保留既有自定义请求客户端、手写薄 API 封装和必要页面状态模型；生成链路不能代替行为验证。

契约验证覆盖真实 HTTP 状态和包装、JSON 名称、字段可省略性、枚举、时间、分页、二进制和错误。JSON 与生成 API 类型保留 `snake_case`，Java 成员和前端自有状态使用 `camelCase`；确有需要时显式转换模型。

错误沿用统一异常映射与真实 HTTP 状态，响应包装的 `code` 表示 HTTP 状态，`msg` 是安全展示提示，增加稳定领域标识：Java 属性 `errorCode`，在线 JSON 为 **`error_code`**。采用 `DOMAIN_REASON`，例如 `USER_VERSION_CONFLICT`、`INFRA_REDIS_UNAVAILABLE`。标识按领域维护，前端行为分支与测试使用同一契约，不由消息或可任意重命名的异常类名临时拼接。

响应空值**保持现状**：保留当前 Jackson NON_NULL 及各端点真实行为，不统一补 `null`、`[]` 或 `data: null`；也不将端点原本自然返回的空集合改写为其他形状。生成契约准确描述哪些字段会省略，不能虚构固定完整响应。

普通编辑提交该用例全部可编辑字段，状态切换、改密码等采用专用操作契约。清空值按字段定义，并验证从绑定、映射到写库均生效。确需局部更新时采用强类型契约，明确“未传、不改”和“null、清空”等字段存在性语义；响应省略规则不替代更新语义。

## 6. 时间与上下文

绝对时刻按 Instant/UTC 语义保存；后端按有效用户时区转换，输出携带明确偏移，例如 `2026-10-03T09:00:00+08:00`。无用户上下文或用户未设置时区时使用平台显式声明的有效系统默认时区，无效时区明确失败，不依赖操作系统时区猜测。

按字段语义严格解析入参：绝对时刻携带偏移或使用契约明确的时区上下文；日期和纯时间使用对应语义模型，组合成时刻时明确日期和时区。不自动给纯时间补“今天”，不轮流猜格式，不把日期与纯时间一律转成 Instant。

用户视角的后台任务携带已确定的时区上下文。本地日程对夏令时造成的不存在或重复时刻有明确契约。业务到期、调度和规则计算使用可控时间源，数据库、Java 与 JSON 的语义和精度一致；时区、边界和歧义按行为风险验证。

## 7. 授权、事务与并发

HTTP 负责身份认证和接口级粗校验，应用 Service 是最终业务授权边界，保障操作权限及记录、数据范围，覆盖详情、修改、列表、计数、导出和批量。复用权限定义与校验能力；数据范围在查询、分页和统计前落实，写入同样检查。

内部调用和任务明确身份与授权上下文；缺少登录线程上下文不等于全量权限。匿名和系统用例明确范围。批量操作约定全部校验或逐项结果，不能默许夹带越权标识；任务授权有效期及执行时校验按业务承诺确定。

应用 Service 确定需要原子提交的本地数据库业务单元，同库跨域调用参与该事务。数据库事务保持必要且短，读取方法不机械套事务。外部调用、消息和文件操作按阶段、补偿或可靠任务处理；需要一致的持久化意图与业务写入同事务保存，提交后唤醒并可恢复。

可编辑业务记录默认乐观锁：客户端提交读取时的版本，数据库条件更新并检查结果；不能以服务端新读版本替换客户端旧版本绕过冲突。冲突使用 HTTP 409 和稳定 error_code，Web 保留编辑内容并支持刷新或重新处理。计数、任务领取及状态转换使用原子谓词，多行不变量另以事务及并发方案保障。

## 8. 异步、缓存及多实例

支持同一应用单实例和多实例，共享数据库、Redis 及适用文件存储。区分全局与实例局部状态，任务领取、调度、缓存及文件可访问性需跨实例验证。

异步可靠性按业务承诺分级：承诺受理、需要恢复或产生业务结果的工作持久化意图和状态，保障提交后执行、跨实例领取、幂等、受限且分类的重试及可观察结果。可丢失的采样或可重建刷新明确影响与恢复方法；提交后回调本身不等于持久可靠任务，不默认引入通用队列或额外 MQ。

外部副作用需要幂等或明确的结果未知处置，不能因超时盲目重复。现有同步审计不由本节自动迁移为异步。

数据库和缓存均为必需基础设施。缓存连接或命令失败统一拒绝相关业务，不降级为未命中、空数据或数据库回源继续服务；健康缓存的正常未命中可按既定流程查询、填充，必需基础设施不意味着所有数据都要增加缓存。

安全 Redis 是 Token、Session、验证码、防重放和登录失败锁定的事实源，无法确认状态必须 fail-closed。缓存定义事实源、业务和身份键范围、生命周期、失效与允许陈旧时间，验证提交后失效、并发回填、多实例及会话隔离。

数据库已提交后发生缓存或外部操作失败，必须如实区分已提交、未提交和结果未知，按契约恢复；不能虚构外部操作被数据库事务撤销，或诱导无幂等保障的重复提交。

## 9. 运行、配置与发布

启动时验证必需依赖，失败退出。运行期依赖故障保留进程但业务不就绪，拒绝业务并暂停新增依赖工作与任务领取；以受控间隔、退避和上限检测恢复。依赖、必要初始化及要求的一致性校验通过后恢复业务。

区分进程存活与业务就绪，实际依赖操作失败也应处理，先前健康检查成功不证明当前调用必然成功。健康和诊断入口不能作为业务降级入口。

静态配置强类型且约束可验证，默认值明确；动态业务设置有类型、范围和变更规则。凭据外部注入，不读取、输出或提交本机凭据和 `.mise.local.toml`。

Flyway 记录数据库演进，共享或正式环境已应用的迁移只追加。Entity、DDL、API 及数据模型文档同步；不以 repair、删除历史记录或忽略缺失迁移掩盖漂移。

维护窗口统一升级后端和 Web，运行实例保持同一版本；受控处理在途任务、数据库迁移及启动恢复验收，不默认承担混合版本滚动升级。发布产物、依赖与配置可复现；回滚结合数据库和业务数据状态，不能仅替换应用包就视为完成。

## 10. 数据生命周期与资源边界

普通业务记录默认使用删除时间软删除；关联关系、运行任务、会话、安全事实、审计和外部存储按领域生命周期明确例外。查询、计数、导出、唯一约束、关联与历史引用保持一致，明确保留期、最终清理和恢复需求。软删除不等于撤销安全访问或清理外部对象；不自动为每域增加回收站。

查询使用强类型用例契约、安全参数绑定和排序白名单。分页、批量与无分页集合有服务端规模边界，条数、时间和内存预算由契约、配置及容量验证确定，不凭空指定通用数值。

小规模导出同步处理，超过预算的导出或重任务使用可恢复持久任务，提供状态和结果；结果明确权限、领取授权、有效期和清理。流式处理同样有预算及一致性语义。批量操作明确整体原子或逐项结果，不无声部分成功；不默认新增通用查询 DSL 或导出框架。

## 11. Web 组织、类型与反馈

简单状态与交互留在页面或组件；具有独立职责、生命周期、复用或验证需要时提取 Hook，业务专属代码先放在所属目录。Pinia 只承载生命周期明确的跨页面、会话或应用共享状态，约定初始化、失效和退出登录清理。组件按展示、交互或实际复用职责拆分，不为行数机械切分。

TypeScript 保持严格类型，动态边界先验证再收窄，any 或未验证断言不能绕过契约。薄 API 封装继续使用既有请求客户端，不管理页面 loading、弹窗和路由；页面模型按需要与生成协议类型转换，不引入平行请求或状态抽象。

局部反馈默认：页面或所属 Hook 管理列表、表单和按钮 loading 及用例恢复，请求层统一错误分类和会话处理。同一失败由一个责任方提示，全局遮罩用于确需阻断应用交互的操作。明确加载、成功、空结果与失败状态。

防止旧请求覆盖当前查询或新会话，提交防重复，失败或冲突保留可恢复编辑内容，所有结束路径释放 loading。取消与失败区分，取消客户端等待不证明服务端回滚。重试有明确条件、次数及截止范围，写入和外部副作用需证明幂等或未执行。

页面和组件目录使用 PascalCase，入口 index.vue；独立组件 PascalCase.vue；普通 TS、API、Store 和 Hook 文件 kebab-case，Hook 文件 use-xxx.ts。组件和类型标识 PascalCase，函数与自有状态 camelCase；生成文件、入口与外部约定有明确范围。详见 [[前端/02-前端命名规范|前端命名规范]]。

## 12. 日志、审计、脚本与插件

运行日志记录关联标识、领域、操作、结果和故障分类，使用安全字段，在有上下文的责任边界记录，避免同一故障重复日志。审计沿用同步链路和 `@Audit`；需要审计的受保护写操作保障业务与成功审计的一致结果，不能审计缺失却返回成功。失败审计按明确的独立提交规则保存。健康、任务和指标范围明确，维度控制基数。

公共脚本声明输入输出、重复执行语义和失败退出；使用原生 PowerShell 与 mise，确实需要 Python 时使用工作区根 `.venv`，不污染全局环境。验证使用隔离输入或依赖，不对真实业务数据执行验收。

插件沿用通用 TypeScript、kebab-case 文件、公共 API 文档、ESM/CJS/类型产物及已有构建链路；核对公开导出、宿主依赖和构建顺序。流程业务仍按范围暂缓，公共变更影响应完整分析；新增公共能力有实际职责依据。

## 13. 验证与交付

以行为和风险作为门禁，覆盖率辅助寻找遗漏，不统一要求每类每行测试或设置统一覆盖率下限。验证可观察行为和关键失败路径，避免仅复述实现或断言内部调用次数。

| 层次 | 要求 |
|---|---|
| 规则与状态 | 有意义的行为、输入边界、状态转换及必要转换验证 |
| 真实依赖集成 | 隔离数据库、Redis，验证事务、并发、基础设施及安全故障、多实例协作 |
| 契约 | 实际 HTTP 与序列化、生成结果可复现和类型漂移 |
| Web | 关键操作、失败与冲突、会话、请求生命周期的浏览器验收 |
| 脚本与插件 | 纳入职责的输入输出、重复和失败、公开导出与宿主集成 |
| 完整质量门禁 | 适用格式、静态、类型、测试、构建及上述契约和风险验证 |

开发阶段优先目标检查；交付和集中治理验收执行适用的完整门禁。自动修复与检查分开；CI 不以自动写回源码为通过前提。纯文档修改核对内容、引用和入口，不机械运行无关构建。

时间和异步验证使用可控时间、明确竞争及恢复场景，避免大量固定等待。页面验收遵循直接 MCP Playwright，首次连接先列标签页；截图、快照及调试产物放根 `.temp/`。

新增或删除 Entity、Controller、模块、配置、依赖和迁移时，同步受影响知识库。交付说明区分已确认标准、已实施变化、实际通过的检查及未验证边界；未扫描或未验证的内容不能算通过。
