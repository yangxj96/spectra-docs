# 常见命令

> 本页只保存可复用命令。首次配置、环境变量分级和数据库初始化见 [[00-环境搭建]]。

> 工程门禁和检查/修复分工以 [[开发指南/04-工作区工程标准|工作区工程标准]] 为准，集中治理与尚待实现的检查见 [[开发指南/05-集中治理与验收|治理入口]]。

## 命令执行约定

- Bash 命令块仅适用于用户明确要求 Linux/WSL 时；当前工作区按全局 `AGENTS.md` 使用原生 PowerShell。Windows 后端使用 `.\mvnw.cmd`。
- 后端使用项目 Maven Wrapper，不依赖全局 Maven；Node 项目使用各自 mise 固定的 Node/pnpm。
- `.mise.local.toml`、`.env.development`、证书和 Provider 凭据是本机配置，必须先从 `.example` 创建。
- `pnpm install` 只在首次克隆或锁文件变化时执行，不是每次启动步骤。
- Docker 命令只属于部署参考，不属于日常开发流程。

## spectra-admin

以下命令从 `spectra-admin/` 执行：

```powershell
# 后端快速验证
mise exec -- .\mvnw.cmd -pl spectra-launch -am compile
mise exec -- .\mvnw.cmd test

# 本地开发启动
mise exec -- .\mvnw.cmd -pl spectra-launch -am spring-boot:run '-Dspring-boot.run.profiles=dev' '-Dmaven.test.skip=true'

# 整个治理周期的真实依赖测试：从 .mise.test.toml 加载测试数据库、Redis DB 5 和测试 S3 配置
mise -E test exec -- .\mvnw.cmd test '-Dspectra.test.real-deps=true'

# 使用相同测试环境启动后端；仍使用读取环境变量的 dev profile
mise -E test exec -- .\mvnw.cmd -pl spectra-launch -am spring-boot:run '-Dspring-boot.run.profiles=dev' '-Dmaven.test.skip=true'

# 模块级检查，按完整影响范围选择项目
mise exec -- .\mvnw.cmd verify -pl spectra-launch -am

# 全量格式检查
mise exec -- .\mvnw.cmd spotless:check '-Dspotless.ratchetFrom=NONE'

# 完整质量门禁，集中治理使用全量格式范围
mise exec -- .\mvnw.cmd verify '-Dspotless.ratchetFrom=NONE'

# 需要整理源码时单独执行，不作为 CI 检查前提
mise exec -- .\mvnw.cmd spotless:apply

# 测试、编译、打包
mise exec -- .\mvnw.cmd test
mise exec -- .\mvnw.cmd clean compile
mise exec -- .\mvnw.cmd clean package -DskipTests

# 只构建启动模块及其依赖
mise exec -- .\mvnw.cmd clean compile -pl spectra-launch -am
```

### 保留的后端回归检查

默认的 `mise exec -- .\mvnw.cmd test` 包含授权方案、文件资产和安全会话的删除副作用回归用例；行政区划导入测试使用 `manual-integration` 标签，不会在默认测试中执行。默认测试不等于新标准的全部真实依赖、故障和多实例验收。

真实依赖测试入口适用于所有后端治理批次。执行前确认 `.mise.test.toml` 所指向的 PostgreSQL 数据库为 `devops00_spectra_db_test`、Redis DB 为 `5`，对象存储桶为测试桶；测试通过环境变量读取连接信息，不能使用已移除的 `b02_test` 数据库用户。PostgreSQL 测试库可按需要重建；Redis 用例仅删除自己的测试键，不清空 DB 5。该文件不提交，命令和日志不得输出凭据。若 mise 加载失败，记录实际退出码，不能改用本地开发或业务数据冒充测试通过。

行政区划导入会向目标数据库写入完整区域数据，只能确认连接为隔离开发库后执行：

```powershell
pwsh -NoProfile -File .\scripts\import-regions.ps1
```

### 启动已打包 JAR

```bash
jar=$(find spectra-launch/target -maxdepth 1 -type f \
  -name 'spectra-launch-*.jar' ! -name '*.jar.original' -print -quit)
test -n "$jar"
mise exec -- java --add-modules ALL-SYSTEM --enable-native-access=ALL-UNNAMED \
  -Dspring.profiles.active=dev \
  -jar "$jar"
```

模板默认使用 HTTPS：`https://127.0.0.1:4004/api/actuator/health`。

## spectra-ui

以下命令从 `spectra-ui/` 执行：

```powershell
mise exec -- pnpm install
mise exec -- pnpm start
mise exec -- pnpm run format:check
mise exec -- pnpm run lint
mise exec -- pnpm run type-check
mise exec -- pnpm run test
mise exec -- pnpm run build
mise exec -- pnpm run preview
```

`pnpm start` 的 `prestart` 会执行会写回文件的 `format`、`lint:fix` 和类型检查。CI 或只读审查应使用
`format:check → lint → type-check → test → build`，并按行为风险执行契约和关键浏览器验收。

## logicflow-plugin-flowable

以下命令从 `logicflow-plugin-flowable/` 执行：

```powershell
mise exec -- pnpm install
mise exec -- pnpm run format:check
mise exec -- pnpm run build
mise exec -- pnpm run dev
```

修改插件源码并与 Web 联调时，保持 `pnpm run dev` 监听，再在另一个终端启动 `spectra-ui`。

## 一次检查三个工程

按上文分别进入各项目运行检查。插件先构建再验证 Web，公共变更的项目范围根据完整影响分析确定。

| 工作目录 | 检查 |
|---|---|
| `spectra-admin/` | mise + Maven Wrapper `verify`；集中治理追加全量格式参数 |
| `logicflow-plugin-flowable/` | mise + pnpm `format:check`、`build` 及适用宿主验证 |
| `spectra-ui/` | mise + pnpm `format:check`、`lint`、`type-check`、`test`、`build` 及适用行为验收 |

命令执行记录真实结果，不能在某项目检查失败后仍宣称三个工程整体通过。

## 停止开发服务

优先在对应启动终端按 `Ctrl+C`。只有确认端口确实由本次开发服务占用后，才终止对应 PID：

```bash
ss -ltnp | rg ':4004|:5173'
```

确认 PID 属于本次开发服务后，再使用 `kill -TERM <pid>`，不要终止不属于本项目的进程。

## CodeGraph

需要分析源码定义、实现、调用链或影响范围时，按根目录 `AGENTS.md` 从目标项目目录查询：

```powershell
codegraph explore "要查询的符号或问题"
```

构建、测试和项目启动本身不依赖 CodeGraph。

Codex 的 CodeGraph MCP 在用户级 `$CODEX_HOME/config.toml` 的 `[mcp_servers.codegraph]`
中全局注册，通过 mise 执行 `codegraph serve --mcp`。全局配置不固定 `cwd` 或 `--path`，
避免所有工作区共用某一个项目索引；查询独立子项目时使用工具的 `projectPath` 参数指定目标项目。
Spectra 插件不再重复注册 CodeGraph MCP。

项目级配置保留在本地 `.codex/config.toml`，包括 Spectra 插件启用设置和本地市场来源。
本地插件市场清单位于 `.agents/plugins/marketplace.json`，市场来源指向当前仓库根目录。
修改 MCP 配置或重新安装插件后，新建 Codex 会话加载更新。

更新仓库内 Skill 时先对齐工程主标准并验证入口、引用和受影响示例，再更新
`.agents/plugins/spectra/.codex-plugin/plugin.json` 的版本。现有版本格式为
`1.0.0+codex.<时间戳>`，替换旧时间戳，不叠加多个后缀。确认本地市场指向当前仓库：

```powershell
codex plugin marketplace list
codex plugin add spectra@spectra-project --json
```

安装结果会给出实际版本和缓存目录，应核对内容与仓库源码一致。源码更新、缓存安装、
会话加载分别确认，不直接修改安装缓存。安装完成后，新建会话核对 Skill 路径；
桌面端需要时重启应用，见 [官方插件文档](https://developers.openai.com/plugins/build/plugins)。

## VS Code

VS Code 任务和启动配置通过 PATH 中的 `mise` 使用项目固定工具链。如果找不到 `mise`，修复 VS Code
进程的 PATH 后重开窗口；不要把个人安装绝对路径提交进 `.vscode`。

## Git

提交、暂存、恢复和推送遵循项目 `spectra:git-execution-spec`。不要提交 `.mise.local.toml`、`.env*`
本机覆盖、证书、私钥、Token、密码、`.maven-repository/`、`.pnpm-store/` 或构建产物。
