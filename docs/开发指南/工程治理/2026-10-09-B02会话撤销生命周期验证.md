## 实现和影响

签发时，用户索引 `sec:ut:<userId>` 保留 Access 到期但 Refresh 仍有效的摘要；TTL 以 Redis 条件过期命令保证只延长不缩短，不同客户端的短策略不能截断长 Refresh。只有 Access 与 Refresh 都已失效才清除陈旧条目。并发策略将有效 Refresh 计入会话数；`KICK_OLD` 从 Refresh Hash 恢复客户端并撤销同端旧会话，`REJECT_NEW` 不能因 Access 到期放行超额登录。

撤销服务从 Access Hash 或仍有效的 Refresh Hash 确认用户、客户端、Family 和摘要映射。按用户、按客户端和不透明管理句柄下线覆盖 Access 已过期的 Refresh；按客户端不再只读取 `sec:uc:*` 的最新指针，`ALLOW` 同端多个会话均撤销。Refresh 登出不误清除其他会话的在线用户标识。映射摘要或归属不一致会拒绝操作；Refresh Hash 仍存在但用户索引已缺失的历史孤儿会话不能再次轮换，需重新登录。

CodeGraph 从 `spectra-admin` 追到 Framework 窄端口与 `SecuritySessionPortConfiguration`，当前源码 `rg` 核对了 Core 的 `CacheManagementServiceImpl`、`UserServiceImpl`、`RoleAuthorizationChangeServiceImpl`、`AuthorizationAssignmentChangeServiceSupport`、`OrganizationChangeServiceImpl`、`DepartmentRestructureServiceImpl`。OA/Workflow 没有直接调用会话撤销端口，但共享 Framework 认证事实源；全 Reactor 测试编译覆盖两模块，业务端到端未运行。Web CodeGraph 追到 `src/plugin/request/auth.ts`、`fetch-client.ts`、`xhr-client.ts`：Refresh 失败会清理本地会话，接口形状未变；B08 页面级身份失效和浏览器验收仍未执行。

## 验证含义及未完成场景

19 项专项证明：自然及模拟 Access 到期后按用户、客户端、句柄撤销仍拒绝旧 Refresh；同端多个 `ALLOW` 会话全部撤销，其他客户端保留；不同 TTL 不缩短索引；`KICK_OLD` 和 `REJECT_NEW` 计入有效 Refresh；孤儿 Refresh、映射摘要/归属损坏及 Redis `isMember=null` 均拒绝；Refresh 登出保留其他在线会话。另以两个独立 Lettuce 连接读写同一隔离 Redis 验证跨连接可见性，**不等同于两个独立应用进程**。

仍未运行两个应用进程的并发签发/撤销、Refresh 重放与撤销交错、Redis 断连后的恢复、Core 改密与授权变更实际 HTTP/数据库链路、OA/Workflow 业务端到端、Web 浏览器失效与重登录流程。并发 Family 围栏、max_sessions 原子性和空闲/绝对时限属于后续 B02 问题；本记录不据此关闭 `IMP-BASE-003`、`BC-BASE-002`、B02 或整个治理周期。`mise exec` 崩溃以及完整门禁的既有失败均保留原始退出码，不以专项通过代替完整验收。
