# B02 安全计数 TTL 验证（DIAG-BASE-018，2026-10-09）

## 当前源码与影响

本次只处理 `DIAG-BASE-018`，关联 `IMP-BASE-003` 和 `BC-BASE-003-COUNTER-TTL`。原诊断所见的 `increment` 后独立 `expire` 已由当前 `SecurityRedisCounter` 的单条 Lua 脚本替代：首次计数执行带 `PX` 的 `SET`，既有计数先检查正 TTL 再递增，后续递增不延长首次窗口。`SecurityLoginFailureStore` 与 `RedisSecurityVerificationStore` 都调用该实现。此次补上脚本返回 `null`、非正递增结果及负数读取结果的拒绝边界，没有改 Key、配置或公共端口。

CodeGraph 和当前源码 `rg` 核对到直接调用方为 Framework 登录失败锁定与验证码尝试计数；Core 的 `LoginServiceImpl`、邮件/短信登录 Provider 及缓存管理经公共端口使用这些状态。OA/Workflow 没有直接计数调用，但共享 Framework 认证边界；Web 的登录与清理安全状态入口没有接口或响应形状变化。本次没有修改这些调用方。Core 身份桶归一化仍归 `DIAG-CORE-020`，不能由本项计数 TTL 验证推定完成。

`SecurityCounterRedisTest` 在隔离 Redis 验证遗留无 TTL 计数会拒绝且不改写，受控清理后可重建有 TTL 的窗口；首次命令写入前超时不会留计数，写入后丢失回包会拒绝本次操作，但服务器上的计数已有 TTL，后续递增保留原窗口；32 个并发首次尝试没有丢计数。原先 `expire=false` 的两命令分支在当前实现中已不存在；遗留无 TTL 键是它可能留下的等效状态。`SecurityRedisCounterTest` 验证未知或无效脚本结果不能成为一次成功计数，健康未命中仍返回零。
