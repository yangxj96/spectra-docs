# B02 通知请求快照与静态门禁验证

> 本文记录当时的 B02/B00 实际执行。当前整个治理周期的后端真实依赖入口已迁移到 [[开发指南/工程治理/2026-10-10-集中治理后端测试环境迁移验证|测试环境迁移验证]]；下述旧库名和 Redis DB 12/14 只表示历史证据，不能作为现行测试命令。

## 范围与实现

2026-10-10 复核 Common 的 14 条 SpotBugs 发现：7 条 `EI_EXPOSE_REP`、7 条 `EI_EXPOSE_REP2`，集中在 `NotificationRequest.InAppInput`（2 条）、`NotificationService.UserNotificationRequest`（6 条）和 `DirectNotificationRequest`（6 条）。这些是通知公共请求容器可被构造方或访问方修改的问题，与 B00 已登记的 14 条框架固定签名 PMD `ExcessiveParameterList` 无关。该发现登记为 `DIAG-CORE-040`，归入通知 B06；本次提前修复以解除 B02 后端门禁的 Common 阻断。

三个 record 的构造器现在复制收件人、渠道、直接地址及参数容器，`null` 容器归一为空集合。渠道与直接地址的 `null` 元素继续跳过；收件人 `null` 元素及参数映射 `null` 键/值拒绝。已有 `NotificationSendRequest` 最终请求继续在 Builder 层复制容器。新 Common JUnit 测试覆盖输入后修改、访问器修改、空容器、跳过元素、非法映射，以及构造完成后调用方与观察方并发访问；参数对象的嵌套可变值不在本次浅层容器快照保证内。CodeGraph 与精确调用检索复核了 Common 定义、Core 网关/安全验证码、OA/Workflow 通知生产者以及 Web 非直接 Java 调用边界；没有需要迁移的公开构造器调用方。Core/OA/Workflow 的请求转换与编译由八模块测试编译覆盖，实际投递/HTTP 行为另按 B02/B06 证据验收。

## B00 真实依赖入口与数据边界

用户确认本机 `127.0.0.1:5432` PostgreSQL 和 `127.0.0.1:6379` Redis 是独立测试实例，允许使用 `b02_test`、`b02_root_test`、Redis DB 12/14。五个真实依赖测试入口由旧专用端口 25432/26379 改到 5432/6379；原有历史报告中的旧端口是当时的执行事实，不追改。PostgreSQL 预检发现 `b02_test` 角色和两库不存在，在独立实例中以无密码本机测试身份创建，随后 `psql -w` 连接两库通过；未对业务库迁移或运行故障测试。Redis 预检因认证返回 `NOAUTH`，测试连接增加仅从当前测试进程环境读取 `SPECTRA_TEST_REDIS_PASSWORD` 的支持；按用户提供的候选值顺序在进程内认证，成功后只报告 `PONG` 状态，不记录密码。运行前 DB 12/14 `DBSIZE` 均为 0。Redis 测试会 `FLUSHDB`，审计/Root 测试会 `TRUNCATE` 专用库合成表，不能指向共享或业务实例。既有 B00 端口测试入口仍需显式 `-Dspectra.test.redis.port=6379`、`-Dspectra.test.postgres.port=5432`；Root 测试另需 `SPECTRA_B02_ROOT_POSTGRES=true`。
