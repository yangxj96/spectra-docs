# B02 会话期限与活动时间验证（DIAG-BASE-005，2026-10-10）

## 实现与影响

Framework 的会话签发、Access 读取和 Refresh 轮换现在共同执行 `SessionPolicy` 的绝对与空闲期限。每代 Access/Refresh 分别保存不可延长的令牌截止时间；Refresh 保存原始 `loginTime` 和 `lastActiveTime`，即使旧 Access 自然过期，轮换也能保留同一 Family 的登录时间。有效 Access 读取会更新空闲活动时间，Redis Lua 在确认 Session、Refresh 映射和 Family 围栏后原子更新两个 Hash、在线摘要及其 TTL；撤销与并发读取不会留下无 TTL 的重建键。用户/客户端、Family、管理句柄及 Access→Refresh 索引保留各自原始令牌期内的可撤销性，不因首次空闲窗口到期而提前消失；实际认证仍按 Hash 与策略截止时间拒绝。后端统一注入 UTC `Clock`，测试可推进时间。缺失或损坏的必需时间字段、Lua 空结果及 Redis 命令失败均拒绝认证或刷新。

CodeGraph 与源码核对：Framework 端口经 `SecuritySessionPortConfiguration` 进入 Core 的登录和刷新服务，过滤器、在线会话查询以及 OA/Workflow 的公共身份上下文间接受期限约束。Web 的 Fetch/XHR 客户端在 Access 401 后共用一次 Refresh，刷新失败会清理本地 Session；路径、Cookie 和 DTO 未变，现有 Web 调用代码无需迁移。B08 浏览器身份失效验收仍需执行。新时间字段加入之前签发的旧 Redis Session 缺少可证明的原始令牌截止时间；本实现对该状态失败拒绝，部署时需协调旧会话重新登录，不能把它当作已验证的无缝续期。
