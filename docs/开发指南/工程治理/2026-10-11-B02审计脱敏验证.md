# B02 审计脱敏验证（DIAG-BASE-001，2026-10-11）

## 实现与影响

复核当前源码确认：Core 的 `JacksonAuditSanitizer` 已在审计切面处把表单、嵌套 Bean、record 展开为结构化数据，Common 的默认脱敏器也已拒绝保留未知 POJO；原登记的直接延迟序列化泄漏路径已有部分修复。但说明文本 `AuditRecord.reason` 未经过清洗，审计写入错误的底层异常仍可能被切面日志或业务异常的 suppressed 列表带出，Bean Validation 日志会打印含拒绝值的异常文本。本次补齐这些剩余边界。

`DefaultAuditSanitizer` 现在清洗普通文本中的敏感键值，包括带前缀的 `client_secret`、`x_private_key`、Token、密码和签名。`AuditRecord` 构造时清洗 `reason`，阻止说明文本绕开快照脱敏。Core `AuditAspect` 在审计写入失败时只记录事件类型及异常类；失败记录无法写入时仅追加固定安全说明，不附加可能含 SQL 参数的底层异常。Framework 对审计存储失败返回 503 但不记录原始异常栈，参数校验日志也不记录被拒绝的字段值或异常对象。

影响链为 Common 脱敏器/审计记录 → Core 审计切面和写入服务 → JSONB、查询与导出。OA 多个业务 Controller 和 Workflow 的任务、流程定义、流程实例 Controller 均使用同一个 `@Audit` 入口；本项没有改变注解或响应契约，源码不需另行改造。Web 审计列表、详情和导出消费既有 `reason`、快照字段，形状未变；详情展示会收到已脱敏的文本。`IMP-BASE-001` 还包含独立的 `DIAG-BASE-010` 错误协议治理，本项只处置 `DIAG-BASE-001`。

从后端目录运行 `codegraph explore "AuditAspect audit sanitizer AuditRecord CoreAuditService JdbcAuditEventWriter OA Workflow @Audit callers"`、从 Web 目录运行 `codegraph explore "AuditLogApi audit detail reason snapshot export callers"`，均退出 **0**。后端索引提示部分已改文件晚于索引，相关定义和调用处再以当前磁盘源码及 `rg` 复核；未把旧索引片段当作最终实现证据。
