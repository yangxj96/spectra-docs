# B02 有效 Root 保护验证（DIAG-CORE-019，2026-10-10）

## 范围与实现

当前源码和 CodeGraph 定位到 `JdbcLastEffectiveDevOpsGuard` 原先没有业务调用方；`JdbcRootPolicyRepository` 的有效人数 SQL 漏掉软删除用户、授权生效时间和凭据到期等条件。此次在用户状态变更、授权增删、登录身份绑定与解绑、密码凭据更新、密码策略更新和一次性用户入职编辑中接入同一保护。调用方须持有数据库事务，先锁定单例 Root 策略行并记录变更前人数，完成数据库变更后复核人数。人数减少到下限以下或增加到上限以上时抛冲突并回滚；数据库/审计状态无法确认时拒绝。密码策略缺失、已删除或不唯一时不计为零人。业务冲突由 Framework 异常解析器映射为 HTTP 409；无事务和基础设施异常保留失败拒绝。

人数使用不同用户计数，要求用户、角色、授权、身份及密码凭据有效且未软删除；授权须处于有效时段，凭据须未独立到期且符合密码策略年龄。撤销同一用户的冗余授权不减少人数。用户入职编辑和普通资料编辑在写用户行前获取 Root 行锁，以保持与授权及身份变更相同的锁顺序。已有授权的账号恢复登录身份也必须经过上限检查。未修改 API 路径、请求或响应 DTO。

从 Core 与 Web 的 CodeGraph 和全工作区精确调用搜索复核：Core 公共服务的直接调用方进入同一保护；当前 OA/Workflow 没有直接调用这些 Root 减少入口，其授权与目录读取属于 `IMP-CORE-001` 的间接影响。Web 用户编辑、角色授权编辑及个人资料身份解绑沿用现有错误展示；此次没有新增 Web 字段或路径。后续新公共调用方必须经过相同事务和锁。没有把 OA/Workflow 独立业务治理并入本项。
