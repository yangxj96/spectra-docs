# 集中治理后端测试环境迁移验证

## 周期级入口

本约定适用于 B00–B10 中所有需要后端真实依赖的检查，不属于 B02 的单独前置条件。用户指定 `spectra-admin/.mise.test.toml` 为测试环境配置：变量名与本地开发相同，PostgreSQL 测试库为可移除重建的 `devops00_spectra_db_test`，Redis DB 为 `5`，`S3_BUCKET` 指向测试桶。`mise -E test exec --` 应将该文件的环境交给 Maven Wrapper；同一环境可运行 `dev` profile 的后端进行 HTTP、后台任务及双实例验证。文件及凭据不纳入 Git、命令输出或证据。

原 B00/B02 用例中的 `b02_test` 数据库用户、`b02_test`/`b02_root_test` 库、Redis DB 12/14 和端口开关已从当前测试入口移除。真实依赖用例统一由 `-Dspectra.test.real-deps=true` 显式启用，读取 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_DB`、`REDIS_PASSWORD`。PostgreSQL 用例执行前拒绝非指定测试库，Redis 用例拒绝非 DB 5。Redis 会话和计数用例为每个测试生成独立物理键前缀，结束时只扫描并删除本用例前缀，不再 `FLUSHDB`。PostgreSQL 审计与 Root 用例仍会在专用测试库中创建及清空合成表；启动后端和执行数据库夹具应串行安排，避免覆盖同一库中的测试状态。

## 实际执行与边界

环境为原生 Windows PowerShell 7.6.6、mise 2026.10.4、mise 管理的 Temurin 25.0.2、仓库 Maven Wrapper 3.9.12。命令在 `spectra-admin/` 执行，原始日志保存在工作区 `.temp/b02/`。

| 检查 | 结果 |
|---|---|
| `mise -E test exec -- pwsh -NoProfile -Command '仅输出所需变量是否存在及测试目标布尔值'` | 退出 **101**；mise 在 `config_root.rs:95` 配置加载处 panic，子进程未启动，没有读取或输出环境值。不能据此确认 `.mise.test.toml` 已成功加载。 |
| `.\mvnw.cmd -fae test-compile` | 退出 **0**；八个 reactor 项目测试编译通过，包括五个调整后的真实依赖入口及新增 Redis 测试隔离辅助类。 |
| `.\mvnw.cmd -pl spectra-framework -am '-Dtest=RealRedisTestEnvironmentTest' '-Dsurefire.failIfNoSpecifiedTests=false' test` | 退出 **0**；2/2 无网络用例通过，验证同名逻辑键的物理隔离、跨用例拒绝反序列化，以及 DB 5 与连接参数守卫。 |
| `.\mvnw.cmd -pl spectra-framework -am '-Dspotless.ratchetFrom=NONE' com.diffplug.spotless:spotless-maven-plugin:3.9.0:check` | 退出 **0**，Framework 全量格式通过。 |
| `.\mvnw.cmd -fae '-DskipTests' '-Dspotless.ratchetFrom=origin/master' verify` | 退出 **1**；Common SpotBugs 为 0，Framework 既有 4 项 `AvoidStarImport` 阻断，下游跳过。 |
| `.\mvnw.cmd -fae '-Dspotless.ratchetFrom=NONE' com.diffplug.spotless:spotless-maven-plugin:3.9.0:check` | 退出 **1**；Framework 通过，Core 当前 2 个既有主源码文件格式不符，后续模块跳过。 |

本轮没有连接或清理 PostgreSQL 测试库、Redis DB 5 或测试 S3 桶，没有启动测试环境后端，也没有执行真实依赖、双实例、故障恢复及 HTTP 场景。先修复或绕开 mise 环境加载故障，再在只使用该测试环境的进程中执行 `mise -E test exec -- .\mvnw.cmd test '-Dspectra.test.real-deps=true'`；应单独记录实际命令、退出码、数据库与 Redis 目标校验结果及失败测试。此前 B02 在旧隔离库/DB 上的日志仍是历史执行事实，不能用于证明新入口已通过。
