# 实体清单

> spectra-admin 全部持久化实体完整字典。源码当前共 75 个带 `@TableName` 的 Entity（不含 BaseEntity）。

## 公共基类

### BaseEntity

> 所有实体的公共父类。
> 路径：`spectra-common/src/main/java/com/devops00/spectra/common/base/BaseEntity.java`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID (String) | 主键，UUID v7 |
| `createdBy` | String | 创建人 ID |
| `createdAt` | Instant | 创建时间 |
| `updatedBy` | String | 更新人 ID |
| `updatedAt` | Instant | 更新时间 |
| `deleted` | Instant | 软删除时间（NULL=未删除） |
| `version` | Integer | 乐观锁版本号 |

## 时间字段约定

所有实体中需要持久化的日期、时间和日期时间字段统一使用 `Instant`，数据库字段统一使用 `TIMESTAMP(6) WITH TIME ZONE`。用户生日、通知免打扰时间，以及 OA 合同、资产、库存、采购、报销、考勤等日期字段均遵循此约定；对应 VO 按展示语义使用 `LocalDate`、`LocalTime` 或 `LocalDateTime`。

## 统一通知模块

通知实体位于 `spectra-notification`，表统一属于 `spectra_notification` schema；旧 `spectra_core.sys_notification*` 仅保留为迁移来源，不再由 Core 映射。

| Entity | 表名 | 关键字段 |
|---|---|---|
| `NotificationTemplateEntity` | `ntf_template` | tenantId、templateGroupCode、channel、purpose、versionNo、模板正文、参数 schema、enabled、继承 BaseEntity |
| `NotificationRequestEntity` | `ntf_request` | externalRequestId、idempotencyKey、purpose、templateGroupCode、业务弱引用、敏感参数密文、接收/任务计数、状态、继承 BaseEntity |
| `NotificationTaskEntity` | `ntf_task` | notificationRequestId、receiverUserId、recipientKeyHash、channel、templateId、标题/正文快照、重试/租约/过期字段、继承 BaseEntity |
| `NotificationDeliveryEntity` | `ntf_delivery` | tenantId、notificationTaskId、attemptNo、provider、resultStatus、错误码、响应摘要、继承 BaseEntity |
| `NotificationInboxEntity` | `ntf_inbox_message` | notificationTaskId、notificationRequestId、receiverUserId、purpose、标题/正文、isRead/readAt、link、extra、继承 BaseEntity |
| `NotificationUserPreferenceEntity` | `ntf_user_preference` | tenantId、userId、purpose、channel、enabled、doNotDisturb、免打扰时间、继承 BaseEntity |

## 核心 — 用户

### User

> 路径：`core/user/javabean/entity/User.java`

| 字段 | 类型 | 说明 |
|---|---|---|
| `username` | String | 登录/展示用户名 |
| `avatar` | String | 头像 URL |
| `status` | UserStatus | `ACTIVE`、`LOCKED`、`DISABLED`、`DEPARTED`；仅 `ACTIVE` 可新建认证 Session |
| `realName` | String | 真实姓名 |
| `gender` | Short | 性别 |
| `departmentId` | UUID | 兼容读取字段；目标模型使用主部门/关联部门 membership |
| `securityVersion` | Long | Security Relevant Change 版本，用于 Session 失效 |

`DEPARTED -> ACTIVE` 只能通过显式重新入职流程执行，不自动恢复历史 RoleAssignment；所有生命周期状态变化都必须撤销该用户全部 Session 并写 Security Audit。

## OA 模块

文档管理首版实体：`Document`、`DocumentFolder`、`DocumentVersion`，对应文档元数据、部门目录和文件版本链。

合同管理首版实体：`Contract`、`ContractVersion`、`ContractMilestone`，对应合同台账、文件版本和履约节点。

### Asset / AssetCategory / AssetOperation / SupplyItem / SupplyOperation / Calendar / Contract / Document / Notice

> 路径：`oa/{module}/javabean/entity/`

各 OA 子模块的实体类，均继承 BaseEntity。

组织通讯录复用 Core 的 `User` / `Department`，部门统计直接聚合各业务表；旧 `Attendance`、`Contact`、`Report` 空壳实体及 `oa_attendance`、`oa_contact`、`oa_report` 表已移除。请假审批对考勤的真实影响保存在 `AttendanceRecord`。

| Entity | 表名 | 关键字段 |
|---|---|---|
| `Asset` | `oa_asset` | `category_id`、`asset_no`、`name`、`status`、`quantity`、`acquisition_amount`、`department_id`、`custodian_id`、采购来源字段 |
| `AssetCategory` | `oa_asset_category` | `pid`、`code`、`name`、`asset_type`、`sort`、`enabled` |
| `AssetOperation` | `oa_asset_operation` | `asset_id`、`operation_type`、部门/人员/位置变更、维修内容和费用、`operation_date` |
| `SupplyItem` | `oa_supply_item` | `sku`、`name`、`unit`、`current_stock`、`min_stock`、`status`、供应商/位置 |
| `SupplyOperation` | `oa_supply_operation` | `supply_id`、`operation_type`、数量增量、变动前后库存、操作人和来源 |

### Meeting / MeetingParticipant / MeetingRecord

> 路径：`oa/meeting/javabean/entity/`

- **Meeting** — 会议基本信息
- **MeetingParticipant** — 参会人员关联，部门范围字段 `departmentId`，SELF 所有人字段 `userId`
- **MeetingRecord** — 会议纪要
- **NoticeReader** — 公告阅读回执，`noticeId` + `userId` 唯一
