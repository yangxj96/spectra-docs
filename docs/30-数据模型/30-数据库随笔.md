# 数据库随笔

> PostgreSQL 18 的 Flyway 迁移、备份和恢复备忘。主机、端口、数据库名和账号都是环境变量，不是必须照抄的个人值。

## 路径与变量

| 内容 | 分类 |
|---|---|
| `spectra-admin/spectra-config/src/main/resources/db/migration/` | 仓库内唯一的数据库结构与固定种子来源 |
| `127.0.0.1:5432`、`devops00_spectra_db` | 推荐本机拓扑，可按环境覆盖 |
| 数据库用户、密码、Docker 容器名 | 本机/部署配置 |
| 备份输出目录 | 操作者自行选择，不写死宿主机绝对路径 |

PowerShell 示例可以先声明本机变量：

```powershell
$dbHost = '127.0.0.1'
$dbPort = 5432
$dbName = 'devops00_spectra_db'
$dbUser = 'postgres'
```

密码由 `psql` / `pg_dump` 交互询问，或通过本机安全凭据机制提供，不写入命令和文档。

## 项目数据库迁移

| 版本 | 文件 | 用途 |
|---|---|---|
| V1 | `spectra-config/src/main/resources/db/migration/V1__init_db.sql` | 当前目标 schema、基础表、约束、索引、注释和固定种子基线 |
| V2 | `V2__notification_template_lifecycle_constraints.sql` | 通知模板生命周期约束 |
| V3 | `V3__separate_user_login_username_and_contacts.sql` | 用户登录名与联系方式拆分 |
| V4 | `V4__create_scheduler_tables.sql` | 调度表 |
| V5 | `V5__comment_scheduler_columns.sql` | 调度字段注释 |
| V6 | `V6__create_scheduler_operation_audit.sql` | 调度操作审计 |

新环境的结构和普通种子唯一由上述 Flyway 迁移链管理。迁移默认不启用 `baselineOnMigrate`，非空旧库不能通过自动 baseline 冒充目标库；生产变更必须新增版本化 migration，不修改已执行版本。

基础小体量种子属于 Flyway V1 的一部分，不再与 Spring Boot `data.sql` 并行维护。`sys_region` 的约 66.5 万行是独立的参考数据包，不再塞入 V1；数据源为 `spectra-core/src/test/resources/regions` 下的五个 JSON，由 `scripts/import-regions.ps1` 在确认目标为隔离开发库后显式导入。这样 V1 保持可审查，区域数据仍可复现且不会在应用启动时隐式写入。用户、部门、凭据、MFA 和 RoleAssignment 不从普通种子自动恢复，首个账号由系统初始化 API 创建。

仓库不再保存按 schema 导出的建表 SQL 或数据库 dump；需要结构审查时直接查看 Flyway migration，需要数据备份时使用下方的 `pg_dump` 命令并将输出放在仓库外。

首次初始化顺序见 [[10-环境搭建#4. 准备 PostgreSQL 与 Redis]]。

## UUID v7

PostgreSQL 18 原生函数名是 `uuidv7()`。项目 SQL 若调用 UUID v7，应优先使用数据库实际提供的函数并在目标 PostgreSQL 版本验证，不要混用自定义的 `uuid_v7()` 名称。

应用侧通过 MyBatis-Plus 新增继承 `BaseEntity` 的实体时，保持 `id` 为空，由全局 `MetaObjectHandler` 使用 `UuidCreator.getTimeOrderedEpoch()` 自动生成 UUID v7；Service 不得手工调用 `setId` 生成新增主键。数据库默认 UUID 仅用于原生 SQL、迁移回填等非 MyBatis-Plus 写入场景。

## 备份

推荐使用 PostgreSQL custom format：

```powershell
pg_dump -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    -Fc -Z 9 --no-owner --no-privileges `
    -f .\spectra-backup.dump
```

只备份某个 schema：

```powershell
pg_dump -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    -n spectra_core -Fc -Z 9 --no-owner --no-privileges `
    -f .\spectra-core.dump
```

备份文件可能包含个人数据、账号散列、业务数据或敏感配置，不应提交到仓库；备份输出应放在受控目录，并按对应运维 Runbook 单独审查和保管。

## 恢复

恢复到已经创建的目标数据库：

```powershell
pg_restore -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    --no-owner --no-privileges .\spectra-backup.dump
```

恢复前确认目标数据库是否为空。`pg_restore --clean`、覆盖现有对象或删除 schema 都是破坏性操作，不放入默认复制即用命令。

## Docker 容器

容器环境同样由应用启动时执行 Flyway migration，不再复制或手工执行仓库建表 SQL。需要验证迁移结果时，连接实际数据库检查 `flyway_schema_history`，并确认应用启动日志中的迁移结果；容器名、数据库用户和数据库名必须以实际 Compose 配置为准。
