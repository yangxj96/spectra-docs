# 数据库随笔

> PostgreSQL 18 的项目脚本、备份和恢复备忘。主机、端口、数据库名和账号都是环境变量，不是必须照抄的个人值。

## 路径与变量

| 内容 | 分类 |
|---|---|
| `docs/sql/...` | 仓库相对路径，可直接复用 |
| `127.0.0.1:5432`、`devops00_spectra_db` | 推荐本机拓扑，可按环境覆盖 |
| 数据库用户、密码、Docker 容器名 | 本机/部署配置 |
| 备份输出目录 | 操作者自行选择，不写死宿主机绝对路径 |

PowerShell 示例可以先声明本机变量：

```powershell
$dbHost = '127.0.0.1'
$dbPort = 5432
$dbName = 'devops00_spectra_db'
$dbUser = 'postgres'
```

密码由 `psql` / `pg_dump` 交互询问，或通过本机安全凭据机制提供，不写入命令和文档。

## 项目 SQL

| Schema | 文件 | 用途 |
|---|---|---|
| `spectra_core` | `docs/sql/spectra_core/建表.sql` | 核心表 |
| `spectra_notification` | `docs/sql/spectra_notification/建表.sql` | 通知请求、模板、任务、投递、消息中心和偏好表 |
| `spectra_oa` | `docs/sql/spectra_oa/建表.sql` | OA 表和基础字典 |
| `spectra_workflow` | `docs/sql/spectra_workflow/建表.sql` | 自定义工作流表单表；Flowable 引擎表由 dev profile 自动维护 |
| 全库数据基线 | `docs/sql/db.dump` | 自定义格式快照/夹具；不作为新环境的结构迁移事实源 |

新环境的结构和普通种子唯一由 `spectra-admin/spectra-config/src/main/resources/db/migration/V1__init_db.sql` 管理。当前 V1 是基于最终目标结构重新生成的单一初始化基线，包含目标 schema、字段顺序、技术主键、约束、索引、完整注释、运行时角色边界、字典/文件类型/菜单、Permission Catalog、安全策略和 OA 固定种子；不再保留后续开发迁移。迁移默认不启用 `baselineOnMigrate`，非空旧库不能通过自动 baseline 冒充目标库。

基础小体量种子属于 Flyway V1 的一部分，不再与 Spring Boot `data.sql` 并行维护。`sys_region` 的约 66.5 万行是独立的参考数据包，不再塞入 V1；数据源为 `spectra-core/src/test/resources/regions` 下的五个 JSON，由 `scripts/import-regions.ps1` 在确认目标为隔离开发库后显式导入。这样 V1 保持可审查，区域数据仍可复现且不会在应用启动时隐式写入。`docs/sql/db.dump` 只作为隔离开发快照或迁移夹具使用。用户、部门、凭据、MFA 和 RoleAssignment 不从普通种子自动恢复，首个账号由系统初始化 API 创建。

`docs/sql` 下的各 schema `建表.sql` 是结构审查/导出参考，不是运行时迁移入口；`docs/sql/db.dump` 仅作为隔离开发快照或迁移夹具使用。

首次初始化顺序见 [[10-环境搭建#4. 准备 PostgreSQL 与 Redis]]。

## UUID v7

PostgreSQL 18 原生函数名是 `uuidv7()`。项目 SQL 若调用 UUID v7，应优先使用数据库实际提供的函数并在目标 PostgreSQL 版本验证，不要混用自定义的 `uuid_v7()` 名称。

应用侧通过 MyBatis-Plus 新增继承 `BaseEntity` 的实体时，保持 `id` 为空，由全局 `MetaObjectHandler` 使用 `UuidCreator.getTimeOrderedEpoch()` 自动生成 UUID v7；Service 不得手工调用 `setId` 生成新增主键。数据库默认 UUID 仅用于原生 SQL、迁移回填等非 MyBatis-Plus 写入场景。

## 备份

推荐使用 PostgreSQL custom format：

```powershell
pg_dump -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    -Fc -Z 9 --no-owner --no-privileges `
    -f .\spectra-backup.dump
```

只备份某个 schema：

```powershell
pg_dump -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    -n spectra_core -Fc -Z 9 --no-owner --no-privileges `
    -f .\spectra-core.dump
```

备份文件可能包含个人数据、账号散列、业务数据或敏感配置，不应默认提交。仓库现有 `docs/sql/db.dump` 是明确纳入版本管理的全库项目快照，更新时使用上面的全库命令，不得添加 `-n` 限定 schema，并需要单独审查。

## 恢复

恢复到已经创建的目标数据库：

```powershell
pg_restore -h $dbHost -p $dbPort -U $dbUser -d $dbName `
    --no-owner --no-privileges .\spectra-backup.dump
```

恢复前确认目标数据库是否为空。`pg_restore --clean`、覆盖现有对象或删除 schema 都是破坏性操作，不放入默认复制即用命令。

## Docker 容器

Compose 服务名为 `spectra-postgres` 时，可以把仓库 SQL 目录复制到容器临时目录：

```powershell
docker cp .\docs\sql spectra-postgres:/tmp/spectra-sql
docker exec -it spectra-postgres psql -U $dbUser -d $dbName -f /tmp/spectra-sql/spectra_core/建表.sql
```

容器名、数据库用户和数据库名必须与实际 Compose 配置一致；上例不是宿主机固定路径。
