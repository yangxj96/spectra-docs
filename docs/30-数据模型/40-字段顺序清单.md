# 字段顺序清单

本清单固化数据库表的物理字段顺序。所有表统一采用：

```text
id -> 业务字段 -> created_by -> created_at -> updated_by -> updated_at -> deleted -> version
```

`spectra_security.sec_security_audit_event` 保留分区事实表的业务唯一键 `(event_id, occurred_at)`，但仍遵守 `id -> 业务字段 -> 审计字段` 的物理顺序；`deleted` 固定为 `NULL`。

## 公共审计字段

| 顺序 | 字段 | 类型 | 规则 |
|---:|---|---|---|
| 1 | `id` | `UUID` | 技术主键，MyBatis-Plus 新增时由全局处理器生成 UUID v7 |
| 末 6 | `created_by` | `UUID` | 创建人，可为空 |
| 末 5 | `created_at` | `TIMESTAMP(6) WITH TIME ZONE` | 创建时间，不为空 |
| 末 4 | `updated_by` | `UUID` | 最后更新人，可为空 |
| 末 3 | `updated_at` | `TIMESTAMP(6) WITH TIME ZONE` | 最后更新时间，不为空 |
| 末 2 | `deleted` | `TIMESTAMP(6) WITH TIME ZONE` | 逻辑删除时间；审计事实表固定为空 |
| 末 1 | `version` | `BIGINT` | 乐观锁版本，默认 `0` |

## Core 初始化状态表

`spectra_core.sys_system_state` 是系统初始化与系统设置引导状态表：

```text
id -> state_key -> state -> initialization_id -> initialized_at -> initialized_by ->
created_by -> created_at -> updated_by -> updated_at -> deleted -> version
```

`state_key=SYSTEM` 的状态值为 `UNINITIALIZED`、`INITIALIZING` 或 `INITIALIZED`；`state_key=SYSTEM_GUIDE` 的状态值为 `PENDING` 或 `COMPLETED`。两行均为固定种子，不是用户、角色或权限数据；分别只允许由初始化服务或系统引导服务推进状态。

## 种子边界

| 范围 | 固定种子 | 首次初始化/运行时数据 |
|---|---|---|
| `spectra_core` | 字典组、字典项、文件类型、菜单、组织版本；行政区划参考数据由独立 JSON 数据包导入 | 用户、部门、组织成员关系、业务数据、日志 |
| `spectra_security` | Permission Catalog、内置角色定义、客户端定义、认证方式定义、Session/Password 策略、Root 策略、审计保留策略 | 用户、认证身份、密码凭证、MFA、Recovery Code、RoleAssignment、Boundary、Scope、审计事件、Outbox |

行政区划数据约 66 万行，属于 Core 的独立参考数据包，不再纳入 Flyway V1。其 JSON 源文件位于 `spectra-admin/spectra-modules/spectra-core/src/test/resources/regions`，通过 `scripts/import-regions.ps1` 按层级批量导入；导入时主键仍由 MyBatis-Plus 生成 UUID v7，创建人、更新人、创建时间和更新时间显式使用固定种子元数据，以便与 V1 中的参考数据保持一致。

## 种子审计元数据

所有固定种子的 `created_by`、`updated_by` 使用零 UUID：

```text
00000000-0000-0000-0000-000000000000
```

所有固定种子的 `created_at`、`updated_at` 使用 `1996-10-15 00:00:00+08`。Core 的组织版本和系统初始化状态，以及 Security 的密码策略、Root 策略和审计保留策略是固定单例，技术主键 `id` 同样使用零 UUID；多行字典、文件类型、菜单、权限、角色和客户端种子继续使用各自稳定的业务映射 ID。行政区划虽然不属于 V1 文件内的固定种子，但独立 JSON 导入夹具同样显式使用零 UUID 审计人和固定审计时间；其区域主键仍按导入批次生成，不承诺稳定的技术 ID。
