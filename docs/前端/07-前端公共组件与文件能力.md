# 前端公共组件与文件能力

> 对应源码：`spectra-ui/src/components/`、`src/directive/`、`src/services/`、`src/composables/`、`src/workers/` 和 `src/utils/`。

## 公共组件目录

| 组件 | 用途 | 使用注意 |
|---|---|---|
| `DictSelect` | 字典下拉选择 | 通过 Dict Store 加载和缓存字典组 |
| `DictTag` | 将字典值展示为标签 | 不要在组件内重复实现字典请求 |
| `OAApproverSelect` | OA 申请选择审批人 | 与请假、报销、采购等流程申请页配合使用 |
| `NotificationBell` | 头部铃铛和未读数 | 复用 Notification Store，打开抽屉或消息中心 |
| `NotificationDrawer` | 消息抽屉、用途筛选和快速操作 | 当前用户消息，不接受任意 userId |
| `JsonEditor` | JSON 编辑和展示 | 由类型声明补充第三方编辑器类型 |
| `IconPicker` | 图标选择 | 供菜单等配置页面复用 |
| `RegionSelectLazy` | 行政区划懒加载选择 | 通过区域 API 按层级加载 |
| `StepNavigation` | 多步骤页面导航 | 使用 `types.ts` 中的步骤类型 |
| `ComponentsIcons` | 内置图标渲染 | 图标名保持现有约定 |

公共组件只封装稳定的展示或交互能力；页面特有业务规则放在页面或页面专属组件中，避免公共组件反向依赖某个具体业务页面。

## 权限指令

`src/directive/permission.ts` 提供 `v-permission`：

```vue
<el-button v-permission="'user:create'">新增用户</el-button>
<el-button v-permission="['user:update', 'user:delete']">批量操作</el-button>
<el-button v-permission.or="['menu:update', 'menu:disable']">菜单操作</el-button>
```

- 字符串：检查单个权限。
- 数组：默认要求全部权限。
- `.or`：数组中任意一个权限满足即可。
- 具体匹配委托给 User Store，支持精确、分段通配和全局通配。

指令只改变前端元素展示，不能替代后端接口授权。导出、删除、密钥管理、通知运维等敏感操作必须同时依赖后端权限。

## 文件上传分层

文件能力分为“业务控制面”和“二进制传输面”：

```text
页面
  └─ useFileUpload(options)
       └─ FileUploadClient
            ├─ Worker 计算 SHA-256
            ├─ FileUploadStore 使用 IndexedDB 保存恢复元数据
            ├─ FileApi 创建会话、获取分片目标、确认分片、完成和查询状态
            └─ uploadBinary / requestBinary 执行 Local 或预签名 PUT
```

### FileUploadClient 生命周期

上传快照中的核心状态包括：`IDLE`、`ANALYZING`、`UPLOADING`、`VERIFYING`、`READY`、`PAUSED`、`FAILED`、`CANCELED` 和 `EXPIRED`，同时报告分析、上传和服务端复核进度。

一次上传通常经历：

1. 校验文件、大小、文件类型和客户端状态。
2. 使用 Worker 增量计算 SHA-256，避免阻塞主线程。
3. 以文件大小和 SHA-256 构造恢复 Key，查询 IndexedDB 中的上传会话。
4. 没有可恢复会话时调用 `FileApi.create` 创建会话。
5. 按服务端返回的分片大小获取每片的 Local 或 S3 目标。
6. 并发上传分片，记录进度；失败时按配置重试。
7. 每片上传成功后调用 confirm，服务端确认结果才计入完成集合。
8. 调用 complete，并轮询状态直到 `READY`、`FAILED`、`CANCELED` 或 `EXPIRED`。
9. `READY` 且取得 `file_asset_id` 后删除 IndexedDB 恢复记录，业务只保存资产 ID。

### 暂停、继续和取消

- `pause()` 停止后续分片调度并保留可恢复元数据。
- `resumeUpload()` 从服务端确认过的分片集合继续，不假定本地上传成功即服务端已确认。
- `cancel()` 取消客户端活动并调用后端取消接口，具体状态以服务端返回为准。
- 页面销毁时通过 `useFileUpload` 取消订阅；不要让页面直接管理 Worker 或 XHR 生命周期。

### 传输边界

| 传输方式 | 认证 | 入口 | 适用场景 |
|---|---|---|---|
| `LOCAL_PROXY` | Api-Version、CSRF、Bearer、Cookie | `uploadBinary()` → `requestBinary()` | 后端代理接收二进制 |
| `PRESIGNED` | 使用服务端签发的目标 URL 和请求头 | `uploadBinary()` → `requestBinary(external)` | S3 预签名直传 |

预签名请求不能擅自添加 Bearer 或 CSRF 头；Local 与预签名请求的差异由传输适配器处理，页面不判断认证细节。

## IndexedDB 恢复存储

`FileUploadStore` 使用数据库 `spectra-file-upload` 和对象仓库 `upload_sessions`，只保存以下可重新校验的元数据：

`key`、`upload_id`、`original_name`、`size`、`content_sha256`、`file_type_code`、`updated_at`。

它不会保存 File 对象、本地分片内容或把本地进度当作事实源。读取列表时会过滤并删除不合法记录；浏览器不支持 IndexedDB 时返回明确错误。

## 通知组件

`NotificationBell` 和 `NotificationDrawer` 不自己维护另一份消息事实：

- 铃铛显示 Notification Store 的 `unreadCount`。
- 抽屉调用 Store 的列表、已读和删除 action。
- 完整消息中心页面位于 `src/views/Notification/`，支持更丰富的时间、关键词和用途筛选。
- 跳转目标由后端通知链接和前端安全前缀规则共同约束，不能直接拼接任意外部地址。

## 工具和组合式能力

| 能力 | 文件 | 说明 |
|---|---|---|
| 表格分页 | `hooks/use-table.ts` | 复用页码、页大小、加载和查询状态 |
| 文件上传 | `composables/use-file-upload.ts` | 将 FileUploadClient 转换为 Vue 响应式快照 |
| 用户导入 | `utils/user-import.ts` | 表头、错误分类和导入数据辅助逻辑 |
| 加解密 | `utils/crypto/` | RSA、AES-GCM、签名、验签和密钥转换 |
| 路由菜单 | `utils/route-utils.ts`、`menu-utils.ts` | 加载、过滤和查找授权菜单 |
| 消息提示 | `utils/message-utils.ts` | 统一 Message、Notification 和确认框 |
| 表单校验 | `utils/verify-rules.ts`、`form-security.ts` | 复用规则和敏感表单保护 |

新增公共能力前先搜索现有组件、Hook、Service 和 Utils，避免对同一后端能力创建第二套请求或状态抽象。
