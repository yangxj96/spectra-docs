# 前端启动与路由

> 对应源码：`spectra-ui/src/main.ts`、`src/App.vue`、`src/plugin/router/`、`src/layouts/` 和 `src/utils/route-utils.ts`。

## 启动顺序

入口文件是 `src/main.ts`。启动顺序是有意安排的：Bootstrap 必须先于 Router，避免路由守卫启动后把初始化请求误判为页面切换请求并取消。

```text
main.ts
  │
  ├─ CommonUtils.hasReload()       检查刷新标记
  ├─ createApp(App)                创建 Vue 应用
  ├─ app.use(formCreate)           注册表单设计器
  ├─ app.use(ElementPlus)          注册 UI 组件和中文 locale
  ├─ app.use(Particles, ...)       注册登录页粒子背景
  ├─ registerDirectives(app)      注册 v-permission
  ├─ app.use(createStore())        创建 Pinia 和持久化插件
  ├─ await initBootstrap()         读取公开启动配置
  ├─ app.use(router)               注册路由及守卫
  └─ app.mount("#app")             挂载到 index.html
```

`App.vue` 只负责根容器、`el-config-provider`、Element Plus 中文语言包和全局消息配置；业务页面由 `router-view` 渲染。消息最多同时显示 3 条，挂载到 `.box-content`，具体提示方法统一由 `MessageUtils` 管理。

## 路由表组合

`src/plugin/router/routes.ts` 不直接堆放所有页面，而是组合五个路由模块：

| 路由模块 | 根路径 | 主要页面 |
|---|---|---|
| `common.ts` | `/`、`/login`、`/initialization` | 登录、初始化、首页、个人中心、消息中心、401、404、重定向 |
| `system.ts` | `/system` | 用户、角色、授权方案、部门、字典、菜单、工作流、行政区划 |
| `devops.ts` | `/devops` | 监控、通知运维、调度、文件、安全和系统维护 |
| `oa.ts` | `/oa` | 资产、办公用品、请假、报销、采购、合同、文档、会议、日历等 |
| `example.ts` | `/exampl` | 表单、列表、ECharts 示例 |

页面路由是静态注册的，页面是否出现在侧边栏由后端菜单 API 决定。这样可以让前端代码拥有确定的组件入口，同时让不同用户看到不同的导航树。

## 布局层级

路由组件根据页面是否需要完整管理后台布局分为两类：

- `Blank` 布局承载首页、个人中心和消息中心等不使用管理侧边栏的页面。
- `Default` 布局承载系统、运维、OA 和示例模块，包含 `Navbar`、`Sidebar`、面包屑、内容区和 `Footer`。
- `/login`、`/initialization`、`/system-guide`、`/401`、`/404` 等特殊页面直接使用页面组件。

`Default` 布局中的侧边栏从 `useAppStore().currentMenus` 渲染，`MenuItem` 只在菜单节点存在 `routeName` 时执行 `router.push({ name })`。页面路由和菜单树通过命名路由关联，不依赖 URL 字符串拼接。

## 路由元数据

业务路由通常包含以下 `meta` 字段：

| 字段 | 作用 |
|---|---|
| `title` | 后置守卫设置页面标题，最终形式为“系统名 - 页面标题” |
| `requiresAuth` | 标识需要登录的路由，实际鉴权由全局守卫统一执行 |
| `requiredMenu` | 页面必须拥有的菜单路由名，供访问校验和菜单激活使用 |
| `activeMenu` | 新增、编辑、详情等子页面返回时仍高亮父级菜单 |
| `approvalProcessKey` | OA 审批类型页面过滤对应流程定义 |

新增页面不要绕过现有元数据约定。列表页和其创建/编辑页通常共享同一个 `requiredMenu`，编辑页额外设置 `activeMenu`。

## 全局守卫执行顺序

`src/plugin/router/index.ts` 的 `beforeEach` 在每次跳转时执行以下步骤：

1. 调用 `cancelAllRequests()`，取消上一次页面留下的非持久请求。
2. `/login` 和 `/initialization` 在没有 Access Token 时直接放行。
3. 内存中没有 Access Token 时，使用 HttpOnly Refresh Cookie 尝试恢复会话。
4. 已有 Token 访问 `/login` 时重定向到首页。
5. 查询系统设置引导状态；DEV_OPS 用户若必须完成引导，则跳转 `/system-guide`。
6. 首次进入或刷新页面时并行加载当前用户菜单和安全上下文，必要时先获取客户端私钥。
7. 使用 `requiredMenu` 检查命名路由是否在授权菜单中，不满足时进入 `/401`。
8. 通过后显示页面 Loading，后置守卫负责设置标题并关闭 Loading。

菜单加载由 `loadMenu()` 完成：它调用 `MenuApi.current()` 和 `SecurityContextApi.current()`，过滤需要隐藏的内部投递记录菜单，将权限写入 User Store，将菜单树和可访问路由名写入 App Store。菜单接口失败时不会伪造菜单，而是提示错误并阻止继续加载。

## 页面新增流程

新增一个受菜单控制的管理页面时，建议按以下顺序操作：

1. 在 `src/views/{模块}/{页面名}/index.vue` 创建页面，页面专属组件放到同级 `components/`。
2. 在对应的 `src/plugin/router/modules/*.ts` 添加静态路由和懒加载组件。
3. 设置 `name`、`title`、`requiresAuth`、`requiredMenu`，编辑/详情路由补充 `activeMenu`。
4. 在后端菜单和 Permission Catalog 中创建同名 `routeName` 及访问权限。
5. 如果页面需要 API，在 `src/api/` 增加模块封装，并通过统一请求客户端访问。
6. 补充页面测试、路由访问测试或接口契约测试，并更新 [[06-前端页面与业务模块]]。

## 常见故障定位

| 现象 | 优先检查 |
|---|---|
| 页面能直接访问但侧边栏没有入口 | 后端菜单的 `routeName` 是否与路由 `name` 一致 |
| 刷新后回到登录页 | Refresh Cookie、CSRF Cookie、`validateToken()` 和后端刷新接口 |
| 页面跳转后请求被取消 | 请求是否需要 `persistent: true`，以及是否在路由切换期间发起 |
| 访问页面进入 401 | `meta.requiredMenu` 是否已加载进 `authorizedRouteNames` |
| 页面标题为空 | 路由 `meta.title` 是否为字符串，或标题函数是否抛错 |
