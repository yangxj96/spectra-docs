# 前端开发测试与构建

> 对应项目：`spectra-ui/`。Node 和 pnpm 版本以项目 `mise.toml` 及根目录开发指南为准。

## 依赖和命令

项目使用 Node 24.14.0、pnpm 11.0.9，主要脚本来自 `package.json`：

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装工作区依赖和本地 Flowable 插件依赖 |
| `pnpm start` | 启动 Vite 开发服务器；`prestart` 会执行 format、lint 和 type-check |
| `pnpm run build` | 生产构建 |
| `pnpm run format` | Prettier 自动格式化 |
| `pnpm run format:check` | 检查格式，不写文件 |
| `pnpm run lint` | ESLint 检查 |
| `pnpm run type-check` | `vue-tsc --noEmit` 类型检查 |
| `pnpm run test` | 使用 Vitest 执行测试 |
| `pnpm run test:watch` | Vitest 监听模式 |

首次启动建议：

```bash
cp .env.example .env.development
mise exec -- pnpm install
mise exec -- pnpm start
```

`.env.development` 只保存本机配置，不提交真实部署地址、证书口令或其他凭据。开发服务器默认使用 HTTPS，后端 API 地址通过环境变量注入。

## Vite 配置要点

`vite.config.mts` 负责：

- Vue SFC 和 Vue JSX 插件。
- 开发服务器端口 `5173` 及本地 HTTPS。
- `@` 指向 `src`。
- Flowable 插件包在开发时别名到本地 `logicflow-plugin-flowable/src`，样式别名到其 `dist/index.css`。
- 生产环境压缩、Gzip/Brotli 和移除 Console。
- 将 Flowable 插件、LogicFlow 核心、LogicFlow 扩展、表单设计器和图表库拆成独立 chunk。
- Vitest 使用 `happy-dom`、`tests/setup.ts` 和 `tests/**/*.{test,spec}.*`。

修改插件源码后，先在插件仓库构建或运行监听，再启动 Web；否则 Web 可能继续使用旧的 CSS 或构建产物。

## 测试分层

当前测试集中在 `spectra-ui/tests/`，重点覆盖：

| 测试类别 | 示例 |
|---|---|
| HTTP 契约 | 空响应、错误 Envelope、加密请求和响应、二进制上传 |
| 认证和权限 | Token 刷新、路由访问、权限边界、用户隔离 |
| API 和转换器 | 用户、菜单、调度、密钥、缓存、部门和数据转换 |
| 公共组件 | 字典选择、字典标签、图标、步骤导航、消息工具 |
| 业务页面 | 调度、缓存管理、应用健康、密钥管理、通知页面 |
| 文件能力 | SHA-256 Worker、上传客户端、文件 API 合同 |

新增页面至少覆盖成功、空数据、接口失败和重复提交；修改请求客户端时要补充请求头、取消、401 刷新、错误 Envelope 和加密状态测试。

## 开发联调

前端与流程插件联调的推荐顺序：

```text
logicflow-plugin-flowable/
  └─ pnpm run dev 或 pnpm run build
          │
spectra-ui/
  └─ pnpm start
          │
工作流页面
  ├─ 从后端读取 BPMN XML
  ├─ 在 LogicFlow 画布编辑
  ├─ Flowable.toBpmnXml()
  └─ WorkflowApi.deployProcess()
```

插件的宿主集成、Picker 和部署流程见 [[07-Spectra宿主集成]]；插件本身的构建和扩展见 [[08-构建发布与扩展开发]]。

## 交付前检查

文档或前端代码变更交付前，按影响范围执行：

```bash
pnpm run format:check
pnpm run lint
pnpm run type-check
pnpm run test
pnpm run build
```

如果只修改 Markdown，可执行根仓库的 `scripts/check-docs.sh` 和同步测试；如果修改了 `src/api/`、路由、Store、请求客户端或上传能力，应同时运行前端相关测试。

## 常见问题

| 问题 | 检查方向 |
|---|---|
| 本地插件导入失败 | 插件是否先构建，`vite.config.mts` 的本地别名是否指向正确目录 |
| HTTPS 启动失败 | 本机证书文件和口令是否存在；不要把口令写入仓库 |
| 类型检查出现全局类型缺失 | 是否使用 `types/` 中已有声明，是否错误引入了未安装包 |
| 页面提示接口失败但 Network 是 200 | 检查后端 `IResult.code`、嵌套失败结构和客户端解密结果 |
| 测试中出现浏览器 API 缺失 | 检查 `tests/setup.ts` 和 happy-dom mock，不要在生产代码中加入测试分支 |
