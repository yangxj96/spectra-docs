# 前端请求与安全通信

> 对应源码：`spectra-ui/src/plugin/request/`、`types/http.d.ts`、`src/utils/crypto/` 和 `src/services/file-upload-client.ts`。

## 请求分层

业务 API 不直接调用浏览器传输 API，而是按以下层次进入统一请求管道：

```text
业务页面 / API 模块
      │
      ├─ get / post / put / del / download
      │        └─ request()                  JSON、鉴权、重试、缓存、加解密
      │
      └─ uploadBinary()
               └─ requestBinary()            Local PUT / 预签名 PUT
```

`src/plugin/request/api.ts` 只负责把 REST 方法转换为 `request()` 参数：`post`/`put` 自动 JSON 序列化，`download` 请求 Blob。业务代码不新增 Axios，也不直接使用 `fetch` 或 `XMLHttpRequest`。

## RequestOptions

公共请求选项在 `types/http.d.ts` 中定义：

| 选项 | 说明 |
|---|---|
| `params` | 查询参数，使用 `qs` 的 indices 数组格式和点号对象格式 |
| `pathParams` | 替换 URL 中的 `{id}` 等路径参数，缺失参数立即抛错 |
| `loading` | 是否参与全局 Loading，默认开启 |
| `priority` | 应用层并发级别：`high` 10、`normal` 6、`low` 2 |
| `fetchPriority` | 浏览器网络优先级，不替代应用层队列 |
| `retry` | 网络或处理失败后的重试次数，单次等待 300ms |
| `cache` | 使用内存缓存，默认 TTL 为 5 分钟 |
| `dedupe` | 相同请求共享 Promise，并取消重复的旧请求 |
| `persistent` | 路由切换时不被 `cancelAllRequests()` 取消 |
| `skipAuth` | 不附带 Access Token，仅供 Refresh 等特殊请求使用 |
| `noBody` / `responseType` | 处理空响应或原始 Blob |

示例：

```typescript
const detail = await get<UserVO, "/api/users/{id}">("/api/users/{id}", undefined, {
    pathParams: { id },
    priority: "high"
});

await put("/api/users/{id}", { nickname }, { pathParams: { id } });
const file = await download("/api/file/assets/{id}", { pathParams: { id } });
```

## 请求生命周期

`request()` 的主要处理顺序如下：

1. 替换路径参数并拼接 `VITE_API_URL`。
2. 使用稳定 JSON 序列化生成请求 Key。
3. 检查缓存和进行中的相同请求。
4. 创建 `AbortController`，登记待处理请求和 60 秒超时。
5. 对 JSON 请求体按加密开关执行加密。
6. 等待应用层优先级队列空位。
7. 使用 `credentials: "include"` 发起请求，附加协议头、CSRF 和 Bearer Token。
8. 401 时共享一次 Token 刷新结果，并最多重试原请求一次。
9. 处理 HTTP 错误、Blob、空响应和业务响应包装。
10. 对加密响应验签和解密，检查嵌套业务失败，再检查顶层 `code === 200`。
11. 写入缓存并在 `finally` 中清理超时、请求、优先级和 Loading 计数。

所有请求附带 `Api-Version: 1.0.0`。非 GET/HEAD/OPTIONS 请求同时附带 `X-XSRF-TOKEN`，值来自 `XSRF-TOKEN` Cookie。

## Token 与 CSRF

`refreshToken()` 使用模块级 `refreshPromise` 保证并发安全：多个请求同时收到 401 时只有第一个真正访问 Refresh 接口，其余调用共享同一个 Promise。Refresh Token 只存在 HttpOnly Cookie，JavaScript 不能读取或写入。

刷新前会检查 `XSRF-TOKEN` Cookie；退出登录后 Cookie 已被清除时直接返回失败，不发送必然被 CSRF 拒绝的 Refresh 请求。刷新失败时所有等待者都得到 `null`，不会悬挂。

刷新成功后：

- 新 Access Token 写入 `useUserStore` 内存状态。
- 原请求使用 `_retry` 标记重试一次。
- 再次 401 不会递归刷新，显示“登录已过期”并跳转登录页。

## 接口加解密

启用通信加密且存在服务端公钥时，非 GET、非 FormData、非二进制请求体使用混合加密：

1. 生成 256 位随机 AES 密钥和 12 字节 HEX IV。
2. 使用 AES-GCM 加密 JSON 请求体，生成 `data`。
3. 使用 RSA-OAEP 加密 AES 密钥，生成 `key`。
4. 生成 URL-safe、无填充 Base64 的 16 字节 `nonce` 和秒级 `timestamp`。
5. 客户端私钥就绪时，对 `data={data}&nonce={nonce}&timestamp={timestamp}` 做 RSA-SHA256 签名。

请求体形态为：

```json
{
  "data": "...",
  "key": "...",
  "iv": "...",
  "nonce": "...",
  "timestamp": 0,
  "signature": "..."
}
```

登录等客户端私钥尚未就绪的请求使用不签名版本，由服务端公钥加密请求体。响应如果符合加密包装结构，客户端先用服务端公钥验签，再用客户端私钥解密 AES 密钥和业务数据；验签失败或密钥未就绪都会阻止继续处理。

## 错误、缓存和取消

- 4xx：读取后端 `msg`，通过 `MessageUtils.error()` 提示并抛出 `HttpRequestError`。
- 5xx：通过通知形式提示服务器错误并抛出 `HttpRequestError`。
- HTTP 200 但业务 `code` 非 200：同样提示并抛出业务错误。
- 业务数据内部包含 `code >= 400` 的嵌套失败结构时，先处理嵌套失败，避免页面误认为成功。
- `cache` 使用模块内存 Map，不是持久化缓存；涉及用户、权限、安全或实时状态的接口不要开启缓存。
- 路由切换会取消普通请求；跨页面仍必须完成的请求显式使用 `persistent: true`。
- 请求被取消应由页面按需静默处理，不能把用户主动取消显示成服务器故障。

## Blob 与二进制上传

`download()` 和 `responseType: "blob"` 返回原始 Blob，不执行 JSON 业务包装和响应解密。对可下载的 Content-Type，`download: true` 会根据 `Content-Disposition` 解析文件名并触发浏览器下载。

分片上传使用单独的 `requestBinary()`：

- Local 代理请求附带 API 版本、CSRF 和 Bearer Token，并使用 Cookie 凭证。
- S3 预签名 PUT 使用 `external: true`，目标 URL 和签名头由服务端下发，不能额外添加认证头。
- 二进制传输底层使用 XHR 仅用于上传进度、超时和 AbortSignal；业务组件必须经过 `uploadBinary()`。
- 文件上传的哈希、分片确认、暂停恢复和 IndexedDB 续传见 [[07-前端公共组件与文件能力]]。

## 请求模块开发规则

新增 API 模块时：

1. 在 `src/api/{领域}/` 创建 kebab-case 文件。
2. 从 `src/plugin/request/api.ts` 引入 REST 辅助函数。
3. 为返回值指定全局声明中的 VO、分页或 Blob 类型。
4. 路径参数使用带 `{param}` 的字面量类型和 `pathParams`，不要手动拼接未编码的 ID。
5. 根据接口语义选择 `loading`、`cache`、`persistent`、`noBody` 和 `responseType`。
6. 为 401、错误响应、空响应、重复请求和安全字段补充测试。
