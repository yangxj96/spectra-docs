# 安全问题报告

请不要在公开 Issue、Pull Request、博客或聊天记录中披露密码、Token、Cookie、密钥、证书私钥、生产数据或可直接利用的漏洞细节。

## 报告渠道

优先使用 GitHub 仓库提供的 Security Advisory 私下报告入口。如果仓库当前未开放该入口，可以联系维护者 `yangxj96@gmail.com`，邮件标题注明 `Spectra Security Report`，不要在邮件主题中写入敏感数据。

## 报告内容

报告应尽量包含：

- 受影响的仓库、子项目、提交或版本。
- 漏洞类型和影响范围。
- 不包含真实凭据的复现步骤或最小示例。
- 影响条件、权限前提和可观察结果。
- 可能的修复方向；不要附带生产数据或真实攻击载荷。

如果必须发送日志或配置，请先删除密码、Token、Cookie、密钥、证书内容、内部地址和个人信息。

## 处理边界

安全问题的处理、修复和公开时间由维护者根据影响范围、可复现性和受影响版本决定。报告者应在问题完成协调前避免公开披露完整利用细节。
