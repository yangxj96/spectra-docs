# 问题反馈与合并请求

## 提交问题前

先搜索已有 Issue 和文档中的 [[参考文档/02-常见问题|常见问题]]，确认问题能够在当前版本复现。依赖版本、部署拓扑、账号权限和浏览器环境会影响结果，需要一并记录。

## Issue 内容

问题反馈至少包含：

- 简短且可定位的标题。
- 使用的根仓库和子模块提交。
- 操作系统、浏览器、Node/Java 版本或部署方式。
- 重现步骤、预期结果和实际结果。
- 页面路径、请求方法、脱敏后的接口路径和 HTTP 状态码。
- 与问题相关的日志摘要；删除密码、Token、Cookie、密钥和个人信息。

功能建议还应说明使用场景、当前限制和期望的行为，不直接指定未经讨论的实现方式。

## 合并请求内容

合并请求应说明：

1. 修改解决了什么问题。
2. 涉及哪些子项目、模块、接口、配置或数据库迁移。
3. 哪些文档已经同步。
4. 执行了哪些检查，结果是什么。
5. 是否存在需要部署者或使用者注意的行为变化。

如果修改网站文档，同步说明源文档、生成页面、侧边栏和构建结果；不要只提交网站生成文件而不提交源文档。

## 审查重点

审查者会重点确认：

- 行为、接口、权限和数据范围是否与当前代码一致。
- 是否保留了旧入口、临时兼容分支或未验证的能力描述。
- 是否更新受影响的配置、数据模型、API 和用户指南。
- 是否泄露本机配置、生产信息或敏感数据。
- 测试、文档检查和网站构建是否有可复现证据。
