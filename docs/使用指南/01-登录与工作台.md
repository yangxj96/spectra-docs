# 登录与工作台

## 首次初始化

新数据库第一次启动后，访问 `/initialization` 进入系统初始化页面。初始化流程用于确认系统初始状态并创建首个运维用户；初始化完成后，使用 `/login` 登录。

初始化入口和登录入口是两个不同的页面：

- `/initialization`：只在系统尚未完成初始化时使用。
- `/login`：系统初始化完成后的日常登录入口。
- `/system-guide`：登录后的系统设置引导入口，是否可访问由认证状态和权限决定。

初始化完成后不要把初始凭证写入文档、脚本或聊天记录。需要重置密码时使用系统提供的密码重置能力，并在首次使用临时密码后按页面提示修改密码。

## 登录

登录页提交登录标识、密码和验证码。验证码由后端生成并校验，登录失败次数和锁定状态由安全 Redis 保存；Redis 不可用时，认证相关操作不会降级为无校验模式。

登录成功后，前端请求当前用户的身份和菜单权限，并进入首页。后端使用 Opaque Token 和 Session 校验请求，刷新 Cookie、CSRF Cookie 和接口加解密策略由后端配置控制。

## 会话与退出

- 页面刷新后，前端通过当前会话恢复用户身份和菜单权限。
- 会话过期、账号被停用、角色被撤销或安全版本发生变化时，受保护请求会失败，前端回到登录流程。
- 用户可以从个人中心查看个人信息并执行退出。
- 管理员从“安全管理”相关页面踢出在线用户后，对应会话不能继续访问受保护接口。

开发环境默认使用 HTTPS 和 `__Host-spectra-refresh` 刷新 Cookie。不要为了绕过浏览器或代理问题，把生产环境改成不安全 Cookie；应先检查证书、Origin、Cookie 属性和反向代理配置。

## 首页和个人中心

登录后的根路径 `/` 对应首页，首页需要 `Dashboard` 菜单权限。个人中心路径为 `/profile`，消息中心路径为 `/notification`。首页数据和消息中心的可见内容由当前用户身份、权限和业务数据范围决定。

## 菜单为什么会不同

系统菜单不是前端固定写死的完整功能列表。页面路由声明 `requiredMenu` 后，前端根据后端返回的菜单权限构建可见导航；后端接口还会再次执行权限检查。因此：

- 看不到某个菜单时，先检查角色是否拥有对应菜单和操作权限。
- 能看到菜单但接口返回无权访问时，检查后端权限、角色边界和数据范围。
- 新增角色或调整菜单后，退出并重新登录，或等待当前会话权限刷新。

## 常用入口

| 页面 | 路径 | 作用 |
|---|---|---|
| 登录 | `/login` | 建立认证会话 |
| 系统初始化 | `/initialization` | 创建初始系统状态和运维用户 |
| 首页 | `/` | 登录后的工作台入口 |
| 个人中心 | `/profile` | 查看和维护个人信息 |
| 消息中心 | `/notification` | 查看当前用户消息 |
| 无权访问 | `/401` | 当前用户没有目标页面权限 |
