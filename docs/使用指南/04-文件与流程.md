# 文件与流程

## 文件上传

文件能力通过上传会话管理文件内容，通过文件资产记录最终对象，通过业务引用把文件关联到 OA 合同、文档、申请和报销等业务。

上传时的基本过程如下：

1. 在业务页面选择文件，前端先计算文件大小和 SHA-256。
2. 服务端校验文件类型策略、扩展名、Content-Type、大小和声明摘要。
3. 已存在相同摘要和大小的 READY 文件时，服务端返回秒传结果。
4. 未命中时创建上传会话，按分片获取传输目标并逐片上传、确认。
5. 所有分片确认后完成会话，服务端重新校验最终对象大小和摘要。
6. 生成 READY 文件资产后，业务页面登记文件引用。

默认分片大小为 8 MiB，允许范围为 5 MiB 至 64 MiB，最多 10,000 个分片；上传会话最长保留 24 小时，连续 2 小时没有成功上传或确认活动时会被视为空闲。实际限制以 [[后端/40-配置说明/00-后端配置说明|后端配置说明]] 和文件类型策略为准。

### 上传失败时的处理

- 检查文件扩展名、声明类型和管理员维护的文件类型策略。
- 检查上传会话是否过期、是否被取消或是否进入失败状态。
- S3 存储检查预签名目标是否过期；重新获取目标后继续上传。
- 本地存储检查后端 staging 目录是否可写。
- 上传完成后仍失败时，以服务端最终校验结果为准，不以客户端摘要作为最终成功依据。

## 文件资产和业务引用

文件资产页面用于管理员查询文件元数据和状态；文件引用页面用于查看文件被哪些业务记录引用。文件名只是显示信息，业务下载和预览必须经过业务引用或管理员权限校验。

没有业务引用的 READY 文件可以按管理员权限删除；已经被业务引用的文件需要先处理业务引用关系。文件物理路径、对象存储 key 和预签名 URL 不应写入业务表或公开文档。

## 流程设计和发布

流程设计器可以创建 BPMN 2.0 流程图，编辑流程、节点和连线属性，并导出 BPMN XML。后端工作流模块负责表单定义、流程定义部署、流程实例和任务处理。

典型流程如下：

1. 在流程设计器中拖入事件、任务、网关和序列流。
2. 选择节点或连线，在属性面板填写名称、办理人、候选组、表单 Key 或其他 Flowable 属性。
3. 校验连线关系和必要属性，导出 BPMN XML。
4. 在后端流程管理中部署流程定义。
5. 从 OA 申请或流程实例入口启动流程。
6. 在审批中心处理待办任务，在已办中查看已经完成的任务。

流程设计器的 `form`、`user`、`group`、`javaClass` 和 `process` 选择器由宿主项目实现。插件只发出选择事件，不负责业务弹窗和业务接口。详细节点、Schema 和导入导出规则见 [[流程设计器/00-流程设计器|流程设计器文档]]。

## 审批任务

工作流页面提供待办和已办任务。审批、驳回、转办和委派等操作必须满足任务办理人所有权和当前权限；任务 ID 本身不能作为越权依据。

请假、报销和采购的业务状态由工作流回调和 OA 服务共同维护。审批通过不一定代表后续业务已经完成，例如报销付款、采购执行和收货仍有独立状态。
