# 问题排查

先确认问题属于页面、后端、数据库、Redis、对象存储还是权限配置。不要通过关闭 HTTPS、绕过权限检查或删除生产数据来验证问题。

## 页面打不开

1. 确认 Web 开发服务或网站服务正在运行。
2. 确认访问协议与服务一致：本机默认使用 `https://localhost:5173`。
3. 检查浏览器控制台和网络面板中的第一个失败请求。
4. 如果页面返回 404，检查当前路由和构建产物；如果返回 401/403，转到权限检查。

## 页面能打开但接口失败

检查 `spectra-ui/.env.development` 中的 `VITE_API_URL` 是否指向实际后端地址，并确认协议、域名、端口和 `/api` 上下文路径一致。后端默认健康检查地址为：

```text
https://127.0.0.1:4004/api/actuator/health
```

如果浏览器报告证书或跨域错误，检查后端 TLS、CORS Origin allowlist、反向代理头和浏览器证书信任状态。

## 登录、刷新或验证码失败

按以下顺序检查：

1. Redis 是否能使用密码认证返回 `PONG`。
2. 后端是否能连接安全 Redis。
3. 浏览器是否保存了刷新 Cookie 和 CSRF Cookie。
4. 请求是否使用正确的 Origin、CSRF Header 和 API 版本 `1.0.0`。
5. 账号是否处于 ACTIVE 状态，是否因为失败次数或安全策略被锁定。

安全 Redis 不可用时，认证、Session、验证码、防重放和登录失败锁定保持 fail-closed；此时不应通过修改前端请求绕过安全检查。

## 菜单为空或无权访问

确认账号状态、RoleAssignment、角色状态、菜单权限、Permission、authority level 和数据范围。调整授权后重新登录，再分别验证菜单显示和接口访问。后端会独立执行授权检查，前端隐藏按钮不代表后端已经授权。

## 文件上传失败

检查文件类型策略、扩展名、Content-Type、文件大小、上传会话状态和存储 provider：

- S3 模式检查 endpoint、bucket、region、密钥、CORS 和预签名目标有效期。
- Local 模式检查 staging 目录和最终文件目录权限及磁盘空间。
- 分片上传检查是否有未确认分片，必要时重新获取目标并继续上传。
- 最终完成失败时查看服务端对象大小和 SHA-256 校验结果。

## OA 或审批状态没有变化

确认 OA 和 Workflow 模块是否在 `spectra-launch` 中装配，检查申请是否已提交、流程是否已经部署、当前用户是否为任务办理人。审批完成后的业务回写由工作流回调执行，查看任务状态、业务状态和通知投递记录可以区分流程问题与通知问题。

## 收集信息

向开发者或运维者反馈问题时，提供以下非敏感信息：

- 发生时间和使用的页面路径。
- 浏览器、操作系统和项目版本信息。
- 脱敏后的请求方法、路径、HTTP 状态码和错误消息。
- 后端健康检查结果和相关时间范围的日志摘要。
- 是否只有一个账号、一个文件或一个业务单据出现问题。

不要上传密码、Token、Cookie、密钥、完整请求头、生产文件内容或未经脱敏的个人信息。
